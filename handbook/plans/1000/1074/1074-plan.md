## The design

Text only. The duty lives in three places on main, and each loses it:

1. The `MEASURED_SECONDS` bullet of `handbook/specs/site-architecture.md` keeps its bold heading word for word, so the three pointers that quote it (the new-suite roster entry in the same spec, the comment at the constant in `test/e2e/lane-timings.test.ts`, and no other) stay valid. Its body is replaced: no pull request re-times a suite; the table is kept by hand and edited by whoever notices a lane grown lopsided; it feeds only the lane-balance check; how a value is read from a lane log (the first sentence of today's bullet, kept); and a pull request that edits a value names the jobs it read in its body, never at the constant. The slow-tier comparison, the yardstick, the three scaling cases, runs started by hand and the list of errors all go.
2. The new-suite roster entry in the same spec stops saying "an estimate first, corrected from its pull request's own lane log", which is the duty applied to a new suite, and says the seconds are kept by hand as the bullet says.
3. The sentence of `handbook/specs/settle-doctrine.md` that has a pull request pulling a slow step re-measure its suite loses its re-measure half and keeps its other half, Issue #1063's: that pull request moves suites only where `test/e2e/lane-timings.test.ts` reds. With no re-measure a pull alone does not red that test, so the sentence keeps meaning what it meant: a pull request that pulls a step does not re-share the lanes.
4. Gate 4 of `.claude/skills/vellum-footguns/SKILL.md` loses item 3 ("Re-measure any budget the roster carries"), the duty at the moment a new suite is typed, and its opening sentence loses the matching example ("a budget nobody re-measured"). `MEASURED_SECONDS` stays in item 1's list of rosters, since a new suite still needs an entry (the type `Record<E2eSuiteName, number>` refuses a missing one).

Nothing under `src/`, `test/`, `test-support/`, `e2e/` or `scripts/` changes, and no test is added: a text edit has no test.

**Rejected:**

- *Rename the bullet's heading* (to say "kept by hand"): it would force an edit to the comment at the constant in `test/e2e/lane-timings.test.ts`, a code file, for no gain, since the bullet's body now says the values are kept by hand.
- *Add "the numbers are hand-kept" to the comment at the constant*: the comment already points at the one normative home by that home's unchanged heading, and stating the rule again at the constant is the second copy `handbook/specs/conventions.md` ("Exactly one home is normative") refuses; the comment doctrine (`CLAUDE.md`, Process) argues the same way. The comment stays exactly as it is.
- *A rule for a new suite's first figure* (an estimate, or one reading of its own lane job): this is the softened rule Alex was offered beside removal in comment 6407764430 ("a rough estimate with no runs started by hand, for a pull request that adds or removes a whole suite or a long step") and did not choose. The type check forces the entry; the spec sets no rule for its number beyond where seconds are read from.
- *Rewrite Gate 4 item 3 to exempt `MEASURED_SECONDS`*: `git grep -n -i -E 'budget|_BYTES|MAX_KB|SIZE_CAP' -- test/ scripts/` finds no other budget a roster carries, and the item's own scar (`.claude/skills/vellum-footguns/references/scars.md`, Issue #546: "`MEASURED_SECONDS` 6.9 from an eleven-check suite carried into a twenty-three-check one") is this duty, so an exemption would leave an item with nothing to cover.
- *Delete the whole settle-doctrine sentence*: its second half ("moves suites only where `test/e2e/lane-timings.test.ts` then reds") is Issue #1063's constraint on a pull request that pulls a step, shipped in PR #1067 and not ruled on here. "One honest fix" says moving suites is not a *fix* of a step; it does not say a pull request that *pulls* a step may not move them, so deleting the half would loosen a rule nobody asked to loosen.
- *Rephrase the sentence as "the pull request leaves the table and the lanes as they stand"*: a new wording of Issue #1063's rule where cutting the re-measure clause alone keeps its meaning.
- *Delete `scripts/proof-runner/remeasure.ts` and its helpers*: no such file exists. `ls scripts/proof-runner/` lists `job.ts ledger.ts list.ts main.ts outcome.ts reporter.ts send.ts`; `git log --all --oneline --diff-filter=A -- '*remeasure*'` prints nothing on any ref. The scripts the duty used (`lane-seconds.ts`, `remeasure.ts`, `step-seconds.ts`) live only as text in Appendix A of `handbook/plans/785/785-r1-plan.md` and Appendix C of `handbook/plans/785/785-kits-plan.md` (frozen archives, never edited) and as copies in gitignored `out/` folders. Nothing to delete.
