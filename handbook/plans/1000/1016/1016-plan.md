### Pull request 1

**One Explorer arrival.** `toExplorer(ctx, url, label, onReady?)` sends the page to `about:blank` and then to `url` (`bounce`), takes `waitReady`'s answer and throws naming `label` when it is false (`explorerUp`), runs the caller's `onReady` step if it gave one, then `waitSettled(label)`. That order is the one all six copies use; three of them switch the redraft between the ready answer and the settle, which is what `onReady` is for. `explorerUp(ctx, label)` is also exported, for the two hand-offs that navigate without a bounce.

**One ink wait.** `waitInked(ctx, label, atLeast = 1)` reads how many points `#map .voyage-overlay .voyage-track` carries (0 when there is no track), returns that count once it is at least `atLeast`, and throws `waitInked timeout <label>` after 120 reads 50 ms apart, the copies' own budget. The survey asks for 11 (its `n > 10`); the Broadside and the zoom suite ask for the default 1, which is exactly their presence test, since a track whose `points` is empty still counts 1 (`"".trim().split(/\s+/)` is `[""]`).

### Alternatives rejected

- **A shared `reload` and a shared `goto` under the issue's own names.** `reload` is already the writing room's word for a real `Page.reload` (`e2e/suites/writing-room/kit.ts:95`), and `goto` names ten page-specific arrivals that wait on ten different signals; one shared `goto` would either wait on the Explorer for pages that are not the Explorer or take a wait as an argument and be a bounce in a costume. The shared pieces are named for what they do: `bounce` (the hop), `toExplorer` (the one page six copies arrive at). Ruling 4 took these names.
- **Dropping `waitReady`'s answer in the shared arrival, as the copies do.** It writes a new instance of the shape clause 4 calls wrong. Ruling 2 rejected it.
- **Giving `waitReady` itself a throw** (Issue #603's second option). It reds `test/repo/e2e-tiers.test.ts` until `waitReady` joins `CTX_THROWING_WAITS`, and then every bare call outside a step is a lint breach (Issue #603, comment of 2026-10-08). Not needed: the asserting helper reaches every discarded answer at no roster cost.
- **Folding the two `/faq/` hops** (`goto` in `e2e/suites/prospect/kit.ts:51` and `e2e/suites/ribbon/kit.ts:38`) into `bounce`. They are not `about:blank` bounces: each waits for the old plate to leave between its two navigates, Issue #1015 built them that way, and `test/e2e/room-kit-waits.test.ts:46-62` pins it. They stay.
- **A lint rule in this pull request.** No CDP spelling leaves the tree entirely in pull request 1, so a rule would need an allow-list of every other file. The rows land with the pull requests that finish each kind (the split above, ruling 1), so no allow-list is ever written.
- **A guard that no new Explorer arrival or ink loop is written by hand.** No instrument here can see one: a function composed of `bounce`, `waitReady` and `waitSettled`, or a fourth loop counting the track's points, is legal code whatever it is called, and a rule keyed on a function's name is evaded by renaming it. The lint rows of pull requests 2 to 4 refuse the raw browser spellings, which keeps every new arrival on `bounce` at least; a hand-written arrival or ink wait built on top passes them. That blind spot errs toward missing a copy, and review holds it. The PR body says so.
- **A browser check that the arrival lands on a fresh document.** The arrival is already the fixture of every check after it in six suites; a stale document reds those (Z13 reads the deep link's camera, RD3 compares bytes). The unit tests below hold the order of the calls; the suites hold what the page does.

    url: string,
    label: string,
    onReady?: () => Promise<unknown>,

      const n = await ctx.evaluate(INK_POINTS);
      if (n >= atLeast) return n;
      await ctx.sleep(50);
    }
    throw new Error("waitInked timeout " + label);
  }
