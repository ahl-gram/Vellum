## The design

**The page stops carrying the three sliders' limits, and each slider's own module writes them from the constants** (ruling 1). The three inputs lose `min` and `max` in `src/pages/explorer/index.astro`. At module scope, through the module's own conversion, `sea-level.ts` writes `landSlider.min = String(landToSlider(LAND_MIN))` and `landSlider.max = String(landToSlider(LAND_MAX))` directly under `landToSlider`; `coast-warp.ts` writes the coast pair directly under `coastToSlider`; and `src/site/explorer/shape-controls.ts` writes `islands.min = String(ISLANDS_SEEDS_CHOICE)` and `islands.max = String(MAX_ISLANDS)` directly under its lookups (ruling 2). One home per number: when a constant moves, the slider moves with it.

- **Where the writes stand is load bearing.** They must run before the boot reads the address into the sliders (`landFromHash` in `src/site/explorer/hash-sync.ts`, reached through `readAddress`). Measured at 9faf3431: with the writes moved after the boot, a visit to `#seed=42&style=antique&land=650` clamps the slider to the browser's default top, draws land fraction 0.1, and rewrites the address to `land=100` (`out/1035-dry-run/1035-probe.log`, BOOT "arm2 writes after boot (misordered)"); at module scope it reads 650 and 0.65 ("arm2 writes at module scope"). The module-scope writes run first because `hash-sync.ts` imports both modules and the boot (`const hashed = await readAddress(hashControls);` and `draw()`) is the last block of `src/site/explorer/app.ts`. The check that holds this is PRW7 in `e2e/suites/print-room/link.ts`, which boots at `land=150` and asserts `before.land === "0.15"`: measured red under the misordered writes (`out/1035-dry-run/1035-suite-late-print-room.log`: `"land":"0.1"`, hash `land=100`) and green at module scope (`1035-suite-arm2-print-room.log`).
- **The writes stand after the conversion functions**, which are `const` arrow functions and so cannot be called above their own line.
- **Before the script runs nothing a reader sees changes.** With the bundle never loading, and with scripts off altogether, the page with the limits dropped is identical to the pixel to today's at 1280 by 800, whole window and the Land rows crop, each shot twice as its own control (`magick compare -metric AE` reads 0 for all twelve pairs, `out/1035-dry-run/1035-compare.log`, shots by `1035-pre-probe.ts`). The slider's hidden value before the script differs (50 against 400 on the sea level, the midpoint of 0 to 100 against that of 100 to 700), and a drag made before the script is discarded when the page boots either way (`1035-probe.log`, PREDRAG: both read the parked 340).

**The check.** One new browser check, step `R19` in the `render` suite, in a new kit file `e2e/suites/render/ranges.ts`. After the boot draw (the page `render` already holds after R0), one `evaluate` reads, for each of `#land`, `#coast` and `#islands`, the `min` and `max` attributes AND the reach: a detached `cloneNode(false)` of the input is set to `"1e9"` and `"-1e9"` and its value read back, which is where the browser stops the thumb. Each slider is its own check line (R19a land, R19b coast, R19c islands), passing only when both attributes and both ends of the reach equal the constants: `Math.round(LAND_MIN * 1000)` and `Math.round(LAND_MAX * 1000)`, `Math.round(COAST_MIN * 100)` and `Math.round(COAST_MAX * 100)`, `ISLANDS_SEEDS_CHOICE` and `MAX_ISLANDS`, imported by the suite from their source modules.

- The attribute half is what sees a missing write where the browser's default range (0 to 100) happens to equal the constant: coast's two ends and islands' top (Gate 1 item 3). Measured: with the coast `max` write deleted, the reach still reads 0 to 100 and only `max: null` reds R19b (`out/1035-dry-run/1035-readings-probe.log`, "the coastMax write deleted").
- The reach half is what sees a limit the slider cannot actually reach, such as a constant that falls off the step grid (`step="2"` on land, `step="5"` on coast).
- The clone leaves the live slider, its value and every later check untouched; the step neither navigates nor waits.

**Rejected designs:**

- **Keep the limits in the page, and only add the check** (the menu's option B, not ruled). The number would live twice, the check making a drift loud rather than impossible.
- **Keep the limits in the page AND write them from the script** (the menu's option C, the issue's own "keep as fallback" wording, not ruled). The issue says the check would tie the two copies; it cannot. R19 reads after the script, so it sees only the script's numbers, and with the script's writes staged its readings are byte-identical to today's build without them (`1035-readings-probe.log`, "arm 3" against "arm 1 fixture"): the check could not tell the six script lines from their absence, and the page's copy would drift unseen.
- **A unit test instead of a browser check.** The writes run only in a browser, so no unit test can see them; `sea-level.ts`, `coast-warp.ts` and `shape-controls.ts` look up their sliders when loaded and cannot be imported in Node.
- **Writing the limits in `src/site/explorer/elements.ts`**, the Explorer's other lookup of the two sliders: it would restate each scale beside the one `landToSlider` and `coastToSlider` already own.
- **A pin on the page's whole set of range inputs** (so a new slider must be classified): looseness and ragged would need an exemption list with nothing to tie them to; a new slider with a constant behind it is its own issue's to tie.

  ```ts
  // The Explorer's range inputs carry exactly the limits the address and their scripts clamp with, and reach both (Issue #1035).
  import { ISLANDS_SEEDS_CHOICE } from "../../../src/site/explorer/land-rows.ts";
  import { COAST_MAX, COAST_MIN, LAND_MAX, LAND_MIN } from "../../../src/site/shared/address-grammar.ts";
  import { MAX_ISLANDS } from "../../../src/terrain/lobes.ts";
  import type { Payload, SuiteContext } from "../../types.ts";

  const RANGES = [
    {
      id: "land",
      code: "R19a",
      says: "the sea-level slider's limits are LAND_MIN and LAND_MAX in thousandths",
      min: Math.round(LAND_MIN * 1000),
      max: Math.round(LAND_MAX * 1000),
    },
    {
      id: "coast",
      code: "R19b",
      says: "the coast slider's limits are COAST_MIN and COAST_MAX in hundredths",
      min: Math.round(COAST_MIN * 100),
      max: Math.round(COAST_MAX * 100),
    },
    {
      id: "islands",
      code: "R19c",
      says: "the islands slider's limits are the seed's choice and MAX_ISLANDS",
      min: ISLANDS_SEEDS_CHOICE,
      max: MAX_ISLANDS,
    },
  ] as const;

  type Reach = { min: string | null; max: string | null; lo: string; hi: string } | null;
  const REACH: Payload<Record<string, Reach>> = `(() => { const out = {};
    for (const id of ${JSON.stringify(RANGES.map((r) => r.id))}) { const el = document.getElementById(id);
      if (el === null) { out[id] = null; continue; }
      const c = el.cloneNode(false); c.value = "1e9"; const hi = c.value; c.value = "-1e9";
      out[id] = { min: el.getAttribute("min"), max: el.getAttribute("max"), lo: c.value, hi }; }
    return out; })()`;

  export async function r19RangeLimits({ evaluate, check }: SuiteContext): Promise<void> {
    const got = await evaluate(REACH);
    for (const { id, code, says, min, max } of RANGES) {
      const r = got[id];
      check(
        `${code} ${says}, and the slider reaches both`,
        !!r && r.min === String(min) && r.lo === String(min) && r.max === String(max) && r.hi === String(max),
        JSON.stringify({ want: { min, max }, got: r }),
      );
    }
  }
  ```
