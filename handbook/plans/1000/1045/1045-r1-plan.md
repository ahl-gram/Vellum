## The design

**One change: once the probe is done with the harness page, it hands the page back as `start()` left it.** `readBrowserFacts` in `e2e/support/fingerprint-probe.ts` takes the page `start()` opened as a second argument. It runs the bounded probe exactly as the PR head does (renamed `boundedProbe`, its body unchanged), then sends `Page.navigate` to `about:blank` and then `Page.navigate` to that page, awaiting each answer and nothing more, and returns the facts. The wrapper `fingerprinted` in `e2e/support/fingerprint.ts` hands it `options.PAGE`. So the first suite starts, as on main, right after a `Page.navigate` to `/explorer/` has answered with that load in flight, and every check that leans on that (PB1, PRL, R0's 15 s `waitReady` window, R0b's bare visit) reads what it reads on main.

**The hand-back is bounded too, so the line always prints.** A browser that has died never answers a send: the harness's socket has no close listener and Node's `WebSocket.send` on a closed socket returns without throwing (the plan skeptic's measurement), so an unbounded hand-back would hang before the wrapper prints, in exactly the hung-lane case where the line is the only diagnostic (`.github/workflows/ci.yml`, the comment at `timeout-minutes`: "A hung lane is the one failure the outcome rule cannot catch"). The hand-back is raced against the same `FINGERPRINT_BOUND_MS`, and at that bound it aborts, so a `about:blank` navigate that answers late sends nothing more: the second navigate, sent after the run had moved into its first suite, would reset that suite's own page (prospect's `/explorer/#seed=42...` to a bare `/explorer/`), the very state this revision exists to protect. A hand-back that is refused or gives up keeps the readings the probe took and replaces the line's `unread` reason with `the page was not handed back: <error>` or `the page was not handed back within 5000 ms`; `readBrowserFacts` never rejects and settles within two bounds. The run then goes on to its first suite, which on a dead browser hangs as main's would until the job's limit, the line already printed.

**Every path tries the hand-back**: the probe that answers, the one that throws, the one missing its title, and the one the probe's bound gives up on, since `boundedProbe` never rejects (`probePage` catches everything and `gaveUp` only resolves) and the hand-back follows it unconditionally. The probe's own removal (`REMOVE_PAYLOAD` in `probePage`'s `finally`) still runs first on every path but the bound's.

**Why through `about:blank`**: `handbook/specs/settle-doctrine.md` clause 9. A navigate straight back to `/explorer/` works today only because the Explorer has rewritten its address by the time the probe ends (3 of 3 drew 42 here, the page inherited `interactive` with a history of 3), and the address is unwritten when the probe finishes before the boot draw, on a slower runner say, which makes it a same-URL navigate that answers on the stale document.

**What the first suite inherits, read at the moment it would start** (`p1045r1-mechanism.ts <arm> state`, logs above):

|---|---|---|
| `location.href` | `http://127.0.0.1:8846/explorer/` | the same |
| `document.readyState` | `loading` | `loading` |
| `history.length` | 2 | 4 |
| `localStorage`, `sessionStorage` keys | none | none |

**What it costs per lane** (the brief's (c)). The design adds the probe and the hand-back to that, and its first suite then waits for a fresh load as main's does, where the PR head's lane A had overlapped R0 with the probe's load (3.95 s). Predicted: under 2.5 s more than main in each lane, under 0.7 % of a 360 to 550 s lane; UNVERIFIABLE until this revision's CI runs, and read then (Evidence).

**Residual window, named.** When the probe's bound fires mid-probe, the hand-back starts at once and the abandoned probe's remaining sends can land after it on the restored page: the removal (`REMOVE_PAYLOAD`, which finds no box there and returns), and, when the bound fires inside the face read, the rest of `faceOf` (`DOM.querySelector` on a node of the old document, which rejects; `CSS.enable` and `CSS.disable`, a domain no suite uses: `git grep -n '"CSS\.' -- e2e/suites` is empty). After the hand-back's own bound, an `about:blank` navigate already sent may still answer later and land on the first suite's page; nothing is sent after it (P10). A second navigate not awaited would not be seen by the unit tests (the plan skeptic's finding 6), which is why the text below awaits each.

### Alternatives rejected

- **Probe in a target, a page or a browser context of its own**: the harness page finishes loading while any probe runs elsewhere (a plain 300 ms sleep reds PB1, the table above), so it would still need the hand-back; and the readings would come from a page the lanes do not use.
- **Navigate straight back to `/explorer/`, without the blank hop**: clause 9, above.
- **Hop `pb1WayIn` and `prlLink` through `about:blank` instead**: fixes two suites, not the class. The PR head moves `VELLUM_E2E_SUITES=zoom-gestures` from main's `0/1` (stopped early, `window.__vellumZoomTo is not a function`) to `15/17` (ZG1, ZG1b red), so the probe changes what other first suites read too, and R0's window and R0b's bare visit lean on the in-flight load as well. The two navigates are already rows in `handbook/errata/guards.md` (PR #701's for `prlLink`, PR #746's for `pb1WayIn`, the latter corrected below).
- **Probe after the last suite**: the issue's body item 2 prints the line "at its start", and the start wrapper would become a hook in `runE2e`, whose test file stands at 398 of 400 lines (the old plan's call 2).
- **Drop the `readyState` wait**: the probe would read a document whose title and sheets may not be parsed, and any probe still delays the first suite past the in-flight load.
- **Print the line before the hand-back**: the read and the hand-back are one call the wrapper awaits, so printing between them needs a fifth parameter on `fingerprinted`, and Issue #1047's finished plan calls it with four (its T4); bounding the hand-back prints the line on every path without that.
- **A refused hand-back as `HARNESS ERROR`**: needs the same fifth parameter, and a browser that has died never answers, so nothing would throw to become one.
- **Drop `REMOVE_PAYLOAD`, since the hand-back discards the box**: keeps P1, P2, P5 and P6 unedited, and a hand-back that fails leaves no box behind.

   async function handedBack(ctx: ProbeContext, page: string, facts: BrowserFacts): Promise<BrowserFacts> {
     const stop = new AbortController();
     let timer: NodeJS.Timeout | undefined;
     const gaveUp = new Promise<string>((settle) => {
       timer = setTimeout(() => {
         const reason = `the page was not handed back within ${FINGERPRINT_BOUND_MS} ms`;
         stop.abort(new Error(reason));
         settle(reason);
       }, FINGERPRINT_BOUND_MS);
     });
     try {
       const failed = await Promise.race([
         handBack(ctx, page, stop.signal).then(
           () => null,
           (failure: unknown) => `the page was not handed back: ${errorText(failure)}`,
         ),
         gaveUp,
       ]);
       return failed === null ? facts : { ...facts, unread: failed };
     } finally {
       clearTimeout(timer);
     }
   }

   export async function readBrowserFacts(ctx: ProbeContext, page: string): Promise<BrowserFacts> {
     return handedBack(ctx, page, await boundedProbe(ctx));
   }
