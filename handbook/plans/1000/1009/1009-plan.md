Every file that builds the default instance drops it for the shared one. ### Part E: the scale reaches the browser

Each edge test runs the CLI with `--png --scale <edge>` and `VELLUM_BROWSER` pointing at a stand-in browser: a one-command shell script that writes the arguments it was given into the file its `--screenshot=` argument names. The test asserts that the arguments include `--force-device-scale-factor=<edge>`. This drives `main` (the top-level API) at two non-default values (the default is 2), so it reds when the CLI drops, clamps or replaces the scale anywhere between the flag and the spawn, and it still reds when an edge is refused (the draw rejects). Measured at f475d0f0 with the stand-in: the readings are `--force-device-scale-factor=0.5` and `=4`; under M5a and M5b both read `=2`.

Precedent for a stand-in browser: `standIn` in `test/e2e/launch-harness.test.ts`, which writes a `#!/bin/sh` script to a temp directory, points the code at it through the environment and restores the environment after. The stand-in is the browser, a dependency, not the system under test.

Rejected: a real PNG with its width read from the header (needs a real browser, which the deliberate CI skip in `test/cli/raster.test.ts` would make vacuous on CI; a 4x render of a 1500 px chart is a 6000 px screenshot in a unit test); a stand-in that writes a PNG of a computed width (the test would assert the stand-in's own arithmetic); asserting `chartOptions(...).scale` at the edges (the "an empty --scale means the default scale, 2" test already reads a given scale through `chartOptions`, and it cannot see the CLI handing the browser a different one).
