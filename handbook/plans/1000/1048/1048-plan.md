## The design

The rule gets one normative home, `handbook/specs/check-placement.md`'s section "The browser lanes and a plate read", as the issue rules. It is written as two new bullets inserted between the section's first bullet ("What the browser computes is read in a browser") and its last ("How a browser check waits ..."), and the heading is not renamed, since archived plans cite it by name (`git grep -c "The browser lanes and a plate read" -- handbook/plans` finds five archived plans).

- The first bullet is the rule: a number the room's layout decides (the press that fills, a fill depth, a clearance, a contrast over a ground, a travel), whether the check asserts it or steers by it, is read off the run's own layout and the check asserts the relation the rule names. Its models are the two witnesses Issue #1034's Revision 4 rewrote: SW2's `thirdPress` and SW4's chart folio clause in `sw1Rooms`, both in `e2e/suites/slide-away/rooms.ts`. It also states menu ruling 3: a witness whose instances the layout decides asks its case of a named instance only where both layouts' readings of that instance carry their margin on a dated line, and otherwise of at least one instance. It points at the planner's Tests line for the readings a plan prints.
- The second bullet is the escape ruling: what counts as ruled (may stay a literal, as a named constant with one dated line naming the ruling or token) and what counts as measured (read from the layout, or where no read gives it, bounded from both layouts on the dated line `CLAUDE.md` gives a bound, the runner's reading taken on GitHub's machines), and what is neither (a check's own inputs, a product constant the check writes again, a tolerance).
- No process step is added anywhere (menu ruling 1): the written rule alone holds it, and the first machine to catch a copied number stays CI. `.claude/agents/vellum-planner.md`, `handbook/specs/development-workflow.md` and `handbook/specs/cloud-routine.md` are not edited, and no issue for a lint is filed.

A second normative copy exists today and is removed: `handbook/specs/settle-doctrine.md`'s environment bullet says "A check reads such a number off the room's own layout in the run, as SW2's `thirdPress` in `e2e/suites/slide-away/rooms.ts` reads the press that fills, or asserts it with its margin measured on both browsers' layouts." ### Alternatives rejected

- **The rule in `handbook/specs/settle-doctrine.md`, where a sentence of it already stands.** Rejected: the issue rules the home, and `handbook/specs/conventions.md` "Where a rule lives" allows one normative home with every other copy pointing at it. That file's environment section is a list of facts about the harness ("Each item is a fact about the environment"), so the pointer belongs there and the rule does not.
- **Leaving the settle-doctrine sentence beside the new bullet.** Rejected: two copies of one rule are two rules the moment either is edited (`handbook/specs/conventions.md`, Where a rule lives).
- **A line in `vellum-footguns` Gate 2.** Rejected: the issue forbids it, and the measurement stands: `node .claude/skills/vellum-footguns/hooks/footgun-gate.selftest.ts` prints "a new e2e suite that clicks and escapes: the pasted note carries ## Gate 4, ## Gate 2, ... in 7950 of 8000 characters", and `test/repo/footgun-gate.test.ts` holds the 8000 ceiling.
- **A catch before CI** (a staged reading in the planner's Tests line, a staged run at workflow step 10, or a lint on written press counts). Rejected by menu ruling 1.
- **Converting the measured checks in this pull request or a second one of this issue.** Rejected by menu ruling 2.
- **Asking a contrast witness of at least one instance always, or of each instance always.** Rejected by menu ruling 3.
- **Listing the checks that break the rule in the spec.** Rejected: a roster in a spec rots unnoticed (`handbook/specs/conventions.md`, "Do not copy volatile state into a spec"), and these are to be converted. The sorted list lives in this plan and in the comment on Issue #785.
- **Naming the issue numbers (Issue #1034, Issue #1048) in the spec text.** Rejected: specs drop provenance and name a live issue number only where it is part of a rule (conventions). The checks are cited by symbol and path instead.
- **Citing the product's `fillPress` (`src/site/shared/slide-away.ts`) as the source of the number**, as the issue's own wording ("`fillPress`") suggests. Rejected: a check that took the press from the product's function would assert the product against itself. The check's own arithmetic, written again on purpose, is `fillOf` and `fillPressOf` in `e2e/suites/slide-away/kit.ts` and `fillOf` in `e2e/suites/stage/slide-kit.ts`, and that is what the bullet cites.
- **Editing the descriptions of `check-placement.md` in `CLAUDE.md`'s table and in `handbook/specs/rulebook.md` (lines 37 and 434).** Rejected: their "read it before" column already sends anyone writing a browser check there, and the description ("which check holds which kind of rule") is not made false by one more rule about the browser instrument.
