## The design

**The rule's purpose is its first clause.** The archive holds every plan a build was made to. A revision is a plan finished again by a fresh `vellum-planner` after the plan came back to it: a builder's hand-back, or a finding about the plan's design at step 14 or 15. It is a new file beside the plan it revises, never written over it, named `<N>-r<k>-plan.md` (`<N>-<label>-r<k>-plan.md` for a later pull request), and it is committed with the first commit its builder makes, copied unchanged as it stood after its rulings were folded in.

**The name is chosen once, by the planner, and carried.** The revising planner writes the revision to the scratchpad under the name it will be archived at. The dispatcher archives it to `out/plans/` and the issue under that name. The implementer copies it into `handbook/plans/<N>/` under that name. Nobody renames a plan on the way.

**`k` counts revisions per pull request and is never used twice** (D2, ruled A): one more than the highest revision of that pull request's plan named on its branch, on main or in the opening line of a `Plan archive, not a ruling:` comment on the issue, the plan the pull request first committed counting as 0. Counting the issue's archive as well as the branch is what keeps a second hand-back from reusing a number whose file the first revision's builder committed but never pushed, or never committed at all; a revision archived and never built leaves its number unused. The planner reads the branch with two plain git commands and the archive lines among the comments it already reads. A revision copied into the archive after its pull request merged keeps the number its own text gives it (`1034-r3`, `1034-r4`). Precedent on main: `778-pr2-r1-plan.md` to `778-pr2-r4-plan.md`, numbered within Issue #778's second pull request, and `751-loupe-r1-plan.md`, numbered within Issue #751's second, beside the first pull request's `751-r1-plan.md` and `751-r2-plan.md`.

**Every revision a build was made to is committed** (D1, ruled A), each with its builder's first commit, which is what ruling A's timing already does: no lane knows at that moment whether a later hand-back will supersede it.

**A revision finished before the branch carries any plan of its pull request** (D3, ruled A) is the plan that pull request's build first commits: the planner gives it the name of the plan it supersedes and writes it over that scratchpad file, which the dispatcher has already archived in two places. The superseded plan was built against by nothing and stays in `out/plans/` and on the issue. Precedent: Issue #1047, whose `handbook/plans/1047/1047-plan.md` is byte for byte the dispatcher's `1047-plan-r1-20261024T235103Z.md` (sha256 `d080b301`, archived on the issue under the name `1047-plan-r1.md`), the first record (comment 6389571622) having been superseded before PR #1055's first commit. Two archive comments then name one file, and the sha256 on their opening lines says which is which.

**Only the plan file is archived** (D5, ruled B). A file a plan names as standing beside it (a patch, a stylesheet) is not committed; it stays where the dispatcher archived it. The five Issue #751 names (`751-r1-zoom-controller-stub.diff` and its two siblings, `751-r2-fmt/rules.css`, `751-r2-fmt/unfurl.css`, 10,171 bytes) stay on Issue #751's comments, and the committed `handbook/plans/751/751-r2-plan.md`'s "`751-r2-fmt/rules.css` beside it is not archived" stands.

**A change at review that no planner revised stays in the PR body.** The builder's own fix after a review round, which the plan did not name, is named in the PR body with the difference, as today.

**The backfill applies the same test to the merged pull requests** (D4, ruled A): the revision each was built to goes in the repo beside its frozen original, copied byte for byte from the dispatcher's `out/plans/` copy and checked by `cmp` and by sha256 against the table below.

### Alternatives rejected

- **Renaming at copy time** (the planner writes `N-plan-r1.md`, the implementer commits `N-r1-plan.md`, as Issues #1043, #1045 and #1047 did): every rename is a judgment the cheaper implementer has to make and a mismatch between the issue's archive comment and the committed file. The name is the planner's, once.
- **The issue body's suggested parenthetical, word for word**, "a plan that changes at review (a skeptic's finding folded before the pull request is reviewed, not a hand-back)": its meaning is kept and its words are not, since "not a hand-back" would define a revision a second time beside the sentences that now define it (call 2).
- **A repo test that every file under `handbook/plans/` matches the naming forms**: Alex chose the PR #721 row in `handbook/errata/guards.md` over such a test on 2026-09-29, and nothing here reopens that.
- **Counting `k` from the branch alone**: a second hand-back that arrives while the first revision's file is committed only in an unpushed commit, or archived and not yet committed, reuses its number, and the resumed implementer then meets a file it may not write over (the plan skeptic's finding 2). The issue's archive lines are read by every planner already.
- **Renumbering backfilled files 1, 2 in order of hand-back** (`1034-r1`, `1034-r2`): Alex ruled D2 A, so every citation of a revision by its own number keeps pointing at the right file.
- **Archiving the files a plan names as standing beside it**: Alex ruled D5 B.
