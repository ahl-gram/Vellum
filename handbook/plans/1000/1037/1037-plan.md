What the rule says, as written into line 36 below:

- For each browser check, the planner prints two readings it takes itself before anything is built: the value the check's own read returns on its fixture, and the value it returns under the mutation the line already owes.
- The fixture reading passes the check's assertion on every instance it asserts on, and the mutation reading fails it on every instance the mutation is meant to red. A check whose readings fall on the same side for such an instance, or whose fixture does not carry what it reads (a name, a ground, a mark), is redesigned in the plan before the plan skeptic reads it.
- Both come from the site `npm run build` makes in the planner's tree, through a probe the planner writes in its tree's `out/<N>-dry-run/`, where the footgun hook gates it as a browser script, driving the built site through `start` in `e2e/harness.ts`. The change, and then the mutation, are staged by what a probe reaches without editing source: a class forced, a style injected, markup the engine renders mounted in the page through the harness's engine route.
- Each reading is quoted from the probe's log, with the probe's path and command; over several instances, the plan quotes the instance whose fixture reading comes nearest to failing and, of those the mutation is meant to red, the one whose mutation reading comes nearest to passing, each named, and cites the log for the rest.
- A reading no probe can stage without editing source is printed as UNVERIFIABLE with that reason, and the plan's **Stop conditions** name the implementer's first run of it (Alex's ruling, comment 6376163468).
