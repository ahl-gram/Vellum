## The design

**One settle, with an opt-in tolerant mode.** `makeSettle` gains one optional input, `tolerant` (default `false`). With it on, a read that throws counts as no read: the poll pauses its 50 ms and reads again, the previous read is forgotten (so a stillness predicate never pairs a read from one document with a read from the next), and the error text is kept. When the budget runs out the settle throws exactly as today, `settle timeout <label>: <last read as JSON>`, and when the last read threw it adds ` (the last read threw: <error text>)`. With it off, nothing changes: a read that throws rejects the settle at once with that read's own error, and the timeout message is byte-identical to today's.

**The interface Issue #785 and Issue #1016 build on** (Issue #785 wants this shape for its conversions; Issue #1016's shared helpers meet it at `e2e/support/`):

```ts
makeSettle({ evaluate, sleep, tolerant?: boolean })
  => <T>(read: Payload<T>, settled: (d: NonNullable<T>, last: T | null) => boolean | null, label: string, tries = 120)
  => Promise<NonNullable<T>>   // polls every 50 ms; throws `settle timeout <label>: <last>` [+ ` (the last read threw: <error>)`]
```

- A wait across a navigation, a boot or a hop passes `tolerant: true`. A read that must never throw keeps the default and fails fast.
- Issue #785's `stable()` factory (its sub 4) is a predicate builder: it drops into the `settled` slot. A factory that hands back `makeSettle`'s own arrow keeps the shape scan's reader; one that returns an arrow of its own must join `knownDeclarations` in `test/repo/e2e-read-types.test.ts`, whose scan otherwise reports any callee named `settle` that resolves to a generic declaration it does not know.
- Issue #1016's shared `goto` or `reload` hops with `makeSettle({ ...ctx, tolerant: true })`. The two kits' `goto` are two more `goto` copies beside the four Issue #1016 lists, and they hop differently: through `/faq/`, where those four (`e2e/suites/survey/kit.ts`, `e2e/suites/broadside/kit.ts`, `e2e/suites/zoom-gestures.ts`, `e2e/support/room.ts`) hop through `about:blank`. Folding them into its shared helper is Issue #1016's.

**Lines of `e2e/support/settle.ts` this touches**: one import added after line 2; the options destructure and its type at lines 4 to 10 (one field each); the poll at lines 18 to 25 (the read wrapped in a `try`, the `threw` record, the timeout message). Lines 1, 11 to 17 and 26 to 27 are unchanged.

**The kits.** Each kit builds one tolerant settle and runs both its waits on it: `goto`'s hop (label `prospect-goto-away` or `ribbon-goto-away`, `HOP_TRIES` = 100 tries, a new constant exported from the Prospect kit with its dated line, the same plate read) and `opened`'s draw (label `<room> page never drew: <label>`, 300 tries at 50 ms, which is today's 200 tries at 75 ms, 15 s). The hop now THROWS when the page never leaves the plate, instead of navigating to the room's address on a document that may still be the room's (a same-path, same-document navigation that never re-boots, clause 9). Both waits keep the tolerance their `catch {}` gave them.

**Rejected alternatives** (do not rediscover these mid-build):

- **A second factory or a `waitFor` with its own arrow.** `test/repo/e2e-read-types.test.ts` knows the settle as the arrow `makeSettle` returns and reports any callee named `settle` that resolves to a different generic declaration; a second arrow is a second declaration both that scan and `vellum/e2e-throw-inside-step` would have to learn.
- **An exported adapter `tolerant(evaluate)`** (the call-site `.catch(() => null)` idiom made shared). It keeps `makeSettle` unchanged, but the swallowed error never reaches the timeout, so a read that throws on every try times out reporting `null`, which is the failure clause 4 says a throw must name.
- **Tolerant by default.** It would loosen every existing settle call: a read with a bug in its payload, which fails fast today with its own error, would burn its whole budget first.
- **Rethrowing only "navigation" errors and tolerating the rest, or the reverse.** The CI record above is an `eval exception: TypeError` on a document with no root yet, which is a navigation case wearing a payload error's text; no rule on the text separates the two.
- **Changing the hop's predicate to `backHome`'s** (`location.pathname === "/faq/"` and `readyState === "complete"`, in `e2e/suites/prospect/room.ts`). The next `Page.navigate` needs only a current document that is not the room's, which the plate read already establishes (the plate is authored markup in `src/pages/prospect/index.astro` and `src/pages/ribbon/index.astro`, and the probe read `false` on the drawn room and `true` on `/faq/`). Not asked for; see Calls made.
- **A lint rule refusing a hand-written swallowing poll loop**, here or later. Ruled out (comment 6392355188): the 73 loud loops stay, so it would carry 73 accepted skips.
- **A clause 4 sentence that binds every existing wait.** The 73 loud loops stay by ruling, so a sentence ruling them all would contradict the code for good. The sentence binds a wait being written.

### In `test/repo/e2e-read-types.test.ts`

`reading` becomes:

```ts
const reading = (reads: unknown[], options: { tolerant?: boolean } = {}) => {
  const asked: string[] = [];
  const slept: number[] = [];
  const evaluate = (expression: string): Promise<unknown> => {
    asked.push(expression);
    const next = reads.shift();
    return next instanceof Error ? Promise.reject(next) : Promise.resolve(next);
  };
  const sleep = (ms: number): Promise<void> => {
    slept.push(ms);
    return Promise.resolve();
  };
  return { asked, slept, settle: makeSettle({ evaluate, sleep, ...options }) };
};
```

`options` is spread, never passed as `tolerant: false`, so a settle built without it takes `makeSettle`'s own default: that is what S2 pins (a `reading` that always passed the key would leave the default untested, which the planning mutation run showed). **What each carries from pull request 1's interface.**
- **A silent loop inside a step** becomes `makeSettle({ evaluate, sleep, tolerant: true })` called as `settle(read, settled, label, tries)`:
  - `read` is the loop's read and `settled` its break condition. A stillness break uses `(d, last)`.
  - `label` names the check or the helper.
  - `tries` keeps the loop's budget in 50 ms reads, as `opened` does here.
  - A helper that today returns `null` or `false` on giving up returns the settle's value and throws instead.
- **A silent loop outside every step** takes one of two forms, decided per site in that pull request's plan:
  - its check moves into a `step`, and the loop becomes the tolerant settle there;
  - or the loop is left exactly as it is and only its check gains a guard on the answer. The loop is not rewritten, so clause 4's sentence for a wait being written does not reach it.
- **A loop handed to a caller or only branched on** is converted only where its caller drops the answer. One whose caller already asserts on it is loud and stays. That pull request's plan reads every caller first, so the 30 below is an upper bound.
