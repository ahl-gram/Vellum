## The design

Four small modules under `src/site/shared/`, each DOM-free at import (nothing at module scope reads `document`, `window`, storage or `URL`), because `test/repo/constant-contracts.test.ts` imports `src/site/seed-of-the-day/app-hunt.ts` and `test/site/landfall-ceremony.test.ts` imports `src/site/home/ceremony.ts` in Node. The four files, their names and the finder's name `$` are as ruled (question 1).

1. **`src/site/shared/by-id.ts`**, the one id lookup. It keeps the name `$`, so all 181 call sites stay as written, and `vellum/stage-no-status` (which matches a call named `$` or `getElementById`, `ID_LOOKUPS` in `scripts/lint/site-shape.ts`) keeps biting. It throws `no element #<id> on this page` when the id is absent. This is the issue's one behavior change: a missing element now stops the page's script at the lookup, naming the id, instead of failing later or quietly.
2. **`src/site/shared/storage.ts`**: `readStored`, `writeStored`, `removeStored`, each a try/catch around the injected `getStorage()` and the one storage call, `getStorage()` itself inside the guard (a store whose accessor throws reads as absent, as `desk-notice.test.ts` already pins). Each caller keeps its own key, its own failure value (by comparing the `null` it gets) and its own remove branch.
3. **`src/site/shared/reduced-motion.ts`**: `prefersReduce`, reading `window.matchMedia("(prefers-reduced-motion: reduce)").matches` at each call. The query stays a literal at the call (`vellum/no-narrow-width` refuses a query handed in as a parameter, `test/repo/narrow-width.test.ts`), and it reads `window` because `test/site/living-chart-pace.test.ts` stubs `window.matchMedia` (measured: the stub reaches the engine today, `out/1012-dry-run/pace-reduced-probe.log`). `src/site/shared/zoom-controller.ts` keeps its own guard for Node (`typeof globalThis.matchMedia === "function"`) and calls `prefersReduce` behind it.
4. **`src/site/shared/object-url.ts`**: `downloadBlob(blob, filename)`, today's routine verbatim with the revoke straight after the click, and `nextObjectUrl(previous, blob)`, which revokes the previous url when there is one and mints the next, remembering nothing.

The living chart (`ages.ts`, `voyage.ts`) imports `reduced-motion.ts`; it never imports `by-id.ts`, and **the lint learns to refuse that import**: `vellum/engine-no-id-lookup` (and through it `vellum/frame-no-id-lookup`, whose `create` is the engine rule's) also reports a module source that resolves to `src/site/shared/by-id.ts`. Without that, the shared lookup is a new path by which the engine or the reading frame could look an id up unseen (measured: today's lint reports nothing for the planned import lines, `out/1012-dry-run/lookup-rule.log`).

## Alternatives rejected

- **Reusing `svgUrl` for the Ribbon and the Prospect.** It returns the old url when the same svg is drawn twice, where today both rooms mint a fresh one, which is a behavior change, and `handbook/specs/explorer-doctrine.md` ("The loupe's urls have exactly one owner") makes `svgUrl` the loupe's alone. It stays in `src/site/explorer/loupe.ts`, unchanged.
- **Deferring the revoke in `downloadBlob`** (a timer, as FileSaver.js does with 40 s). Not needed on any engine measured or documented (Call C4), and it would be a behavior change the issue does not make.
- **One generic `attempt(fn, fallback)` guard for storage.** It would also wrap the hunt's JSON parse, but names nothing; three storage verbs read better at every caller, and the hunt keeps its own try for the parse, which is not a storage failure.
- **A guarded `prefersReduce` reading `globalThis.matchMedia`.** It would leave the living-chart-pace stub (on `window`) unread, so that test would pass by coincidence.
- **Moving `deviceStorage` into `storage.ts`.** `SHARED_BINDINGS` in `scripts/lint/shared-bindings.ts` pins it as imported from `../shared/table-store.ts` by two rooms, and the hunt importing `table-store.ts` would pull the table grammar into its bundle; the hunt keeps a local `() => localStorage` thunk.
- **Declaring the engine's new blind spot instead of closing it.** The extension is one helper and two listener clauses, measured exact on the planned plant; naming a hole the change itself opens is the weaker of the two.

**`out/1012-dry-run/ids.ts`**, to write into the implementer's tree for Evidence step 3 (it reads the BUILT pages, so it runs after `npm run build`):

```ts
import { existsSync, readFileSync } from "node:fs";
import { dirname, join, resolve } from "node:path";
import { BUNDLE_ENTRIES } from "../../scripts/build-app-bundles.ts";

const ROOT = resolve(import.meta.dirname, "..", "..");
const SPEC = /(?:\bfrom\s*|\bimport\s*\(\s*)["'](\.{1,2}\/[^"']+)["']/g;
const LOOKUP =
  process.argv[2] === "casts"
    ? /document\.getElementById\(\s*["']([^"']+)["']\s*\)\s+as\s+HTML\w*Element(?!\s*\|)/g
    : /(?<![\w$.])\$(?:<[^>()]*>)?\(\s*["']([^"']+)["']\s*\)/g;
const ID_ATTR = /\sid=["']([^"']+)["']/g;

const closure = (entry: string): string[] => {
  const seen = new Set<string>();
  const walk = (file: string): void => {
    if (seen.has(file) || !existsSync(file)) return;
    seen.add(file);
    const src = readFileSync(file, "utf8");
    for (const m of src.matchAll(SPEC)) walk(resolve(dirname(file), m[1]!));
  };
  walk(join(ROOT, entry));
  return [...seen].map((f) => f.slice(ROOT.length + 1)).sort();
};

const pageOf = (twin: string): string => {
  const dir = dirname(twin);
  return join(ROOT, "dist", dir === "." ? "" : dir, "index.html");
};

let missingTotal = 0;
let askedTotal = 0;
for (const { entry, twin } of BUNDLE_ENTRIES) {
  const files = closure(entry);
  const raw = readFileSync(pageOf(twin), "utf8");
  const html = raw.replace(/<noscript\b[\s\S]*?<\/noscript>/gi, "").replace(/<template\b[\s\S]*?<\/template>/gi, "");
  const ids = new Set([...html.matchAll(ID_ATTR)].map((m) => m[1]!));
  console.log(`ENTRY ${entry} -> ${pageOf(twin).slice(ROOT.length + 1)}: ${files.length} modules, ${ids.size} ids in the built page`);
  for (const f of files) {
    const asked = [...readFileSync(join(ROOT, f), "utf8").matchAll(LOOKUP)].map((m) => m[1]!);
    if (asked.length === 0) continue;
    const missing = [...new Set(asked)].filter((id) => !ids.has(id));
    askedTotal += asked.length;
    missingTotal += missing.length;
    console.log(`  ${f}: ${asked.length} lookups of ${new Set(asked).size} ids; missing from the built page: ${missing.length === 0 ? "none" : missing.join(", ")}`);
  }
}
console.log(`TOTAL ${askedTotal} lookups read; ${missingTotal} ids missing from their page`);
```
