## Rules of the round (binding; each is an earlier round's ruling or call)

1. **The unit of proof is the claim**: one assertion with its message. Its mutation is the smallest source change that makes THAT claim false, applied alone, and it keeps the page alive: never a deleted import or a broken build; a behavioural edit (a call dropped or stubbed, a value changed, a selector renamed); where a script looks an element up, rename it on BOTH sides (two edits) so the page lives and the stop is the named check's own read.
2. **A claim leaves the unit suite only when a named holder reds on its mutation**:
   - **BITES**: a named browser check prints `FAIL`.
   - **NEEDS READ**: the suite stops on an exception thrown by the named check's OWN read of the broken code (Alex's ruling 6090198881). Mark such a row and name the check whose read throws.
   - **HELD-DATA**: a surviving built-page data test reds on it (the built-page reads in `test/site/astro-scaffold.test.ts`; 2f call 5 and 2f-home call 18 are the precedent). The row then names that unit test as the holder and carries no e2e block.
3. **A claim no browser check here can see** keeps a smaller unit test for part 2i, renamed where its name over-claims, in one of these classes, which you name: (a) an import pin (ruling 3 of 6098118329); (b) a retire pin outside ruling 6's fifteen named rows (2e call 5: an absence of a retired id, class, token or copy); (c) "declared once", a repeating block that changes nothing; (d) the order of two synchronous calls or writes nothing interleaves; (e) code shape (a census of call sites, an import's name, a type, a selector's form that changes nothing served, such as an unscoped arm when every wearer stands in the scope); (f) a pair Chromium reads as one property (a vendor prefix). **Dead CSS is NOT kept**: a declaration that changes no computed value because another rule decides it (or a rule for a class no served element wears) loses its pin and gets a `handbook/errata/site.md` row (2g-plates call 24). Say which.
4. **A new check**: its own `step(...)`; its id continues its suite's prefix (use a PROVISIONAL id in your table, `<AREA>:<suite>:<n>`, since three agents work at once; the planner assigns the final ids); it undoes everything it changes in a `finally` (emulated media, device metrics, scripts, hover, focus, scroll, zoom, an open slip, a stored table, an injected script); it fails rather than throws where its premise is a press (wait about a second for the effect, then read it as it stands); an absent element reads as a sentinel, never a throw; every function stays under 50 code lines and every file under 400 code lines (split by part of the page); no early-return gate in a suite's `run`. Colours compare through `e2e/support/pixel.ts` (`PAGE_RGBA`, `tokenRgba` from `SITE_PALETTE`, `nearRgba`); a value whose claim is "via the token" is compared against the token resolved on a probe element in the same page, never a hard copy. Gestures are real (CDP `Input.dispatchMouseEvent`, `Input.dispatchKeyEvent`, `sendKey`), never `.click()` for a gesture claim. A device-metrics clear waits through `clearMetrics`. A check whose premise is motion clears the emulated features first. A regex inside an `evaluate` template literal writes its backslashes doubled. The cursor is parked off a plate before a plate's box is read (`.plate:hover` tips it).
5. **New e2e files follow the naming rule** (Alex, 6098118329 ruling 2): a folder named for the suite holding `kit.ts` (the suite's kit, moved out of the suite file when new files need it), `room.ts` (the page as authored, and what loading it does), `dress.ts` (its computed dress at rest), `gestures.ts` (what a press, hover, key, resize or print does). A suite whose folder already exists takes new files beside the old by those names. A check that fits an existing file staying under 400 code lines may join it. Name the file for every check.
6. **Mutations are exact**: each edit is `{file, find, replace}` with `find` occurring EXACTLY ONCE in that file at `2b148100`. Count OCCURRENCES, not lines, with node, never grep -c: write the find to a temp file under the scratchpad (prefix `779-2h-`) and run `node -e 'const fs=require("fs");const t=fs.readFileSync(process.argv[1],"utf8");const f=fs.readFileSync(process.argv[2],"utf8");console.log(t.split(f).length-1)' <file> <findfile>` (strip the trailing newline your temp file gets). Prefer single-line finds.
