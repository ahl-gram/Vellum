## The design

A committed switch, `VELLUM_E2E_RUNNER_LAYOUT=1`, makes any e2e run stage the CI runner's measured layout differences on this machine, so a layout-dependent check can be run against the runner's layout before pushing.

1. **One module holds the model**: `e2e/support/runner-layout.ts` carries the measured differences as data (`RUNNER_NUMERO_FAMILY`, `RUNNER_SELECTS`), the sheet built from that data (`runnerLayoutCss`, `RUNNER_LAYOUT_CSS`), the new-document script that adopts a sheet (`runnerLayoutScript`), the switch's reader (`runnerLayoutRequested`), the one call that registers the staged script (`applyRunnerLayout`), and the fingerprint's mark (`RUNNER_LAYOUT_MARK`).
2. **The runner reads the switch, the harness applies it.** `plan` in `e2e/support/runner.ts`, which already turns the environment into the harness's options (ports, site, suites), adds `runnerLayout: runnerLayoutRequested(env)`. A bad value throws there, so the run ends `FAIL: ...` with exit 1 before any browser starts, as a bad port does. `StartOptions` gains an optional `runnerLayout`, and `openSession` in `e2e/harness.ts` registers the script, when it is true, immediately before its first `Page.navigate`, so the boot document and every document after it in the page target (frames included) adopt the sheet before their own scripts run. The registration is never removed: the run is staged from first page to last. Lanes inherit it, since `laneChildEnv` in `e2e/support/lanes.ts` passes the parent's environment to each child.
3. **What is staged is exactly what was measured**, three differences:
   - the "№" (U+2116), absent from the house display face's Latin subset, drawn from Times New Roman through an `@font-face` that extends the family `IM Fell English SC` over `unicode-range: U+2116` alone (the runner draws it from Liberation Serif, a face metric-compatible with Times New Roman: the fingerprint's "Chart № 42" reads 98.02 px on the runner and 98.03 px staged here);
   - `.folio-controls select.control` at `height: 29.21875px`;
   - `.legend-head select` at `height: 23.375px`.
4. **A staged run says so, twice.** `applyRunnerLayout` resolves to a notice line naming the switch and the runner image and browser the values were measured on, printed by the harness once the sheet is registered, inside `start`, so before the fingerprint line and the first suite. And Issue #1045's fingerprint line, printed by its `fingerprinted` wrapper from the same `StartOptions` once `start` has resolved, gains a last measured part, `runner layout staged (VELLUM_E2E_RUNNER_LAYOUT=1)`, so a fingerprint read later (a lane's `FAILED` line carries it) says its title width and select height were read off the staged layout. The notice is the evidence the sheet was registered; the mark follows the switch.
5. **The measured values are pinned by a unit test written out literally** (T3), so a dropped rule or a changed height reds there.
6. **PR40 keeps the model attached to the house's markup and cascade.** It registers a sentinel sheet, built by the same `runnerLayoutCss` and `runnerLayoutScript` from the same data with every select at 50 px, then visits every chart room in `ROOMS` (`e2e/suites/slide-away/kit.ts`). It asserts that each staged select rule matches a select in some chart room, that every select it matches in every room lays out at the sentinel, and that every room's chart folio title draws first from the family the staged face extends, with that face adopted. 50 px is neither machine's own height for either select (34.21875 and 27.375 here, 29.21875 and 23.375 on the runner), so a rule that misses, or that a room's own rule outranks, reds on both machines.
7. **The doctrine bullet names the switch** in place of its recipe sentence, keeping its opening words, which Issue #1043's index cites; it says what a staged run does not model and how drift is caught, the fingerprint included.

### Alternatives rejected

- **The issue's form of the numero rule** (a `#folio-title` rule that restates the title's whole font stack behind a `"Probe Numero"` face, `out/1034-dry-run/staging.ts`): it reproduces the runner's numbers identically (`readings.log`: title right 290.40625, Press row 145.90625, reserve 144.734375 and 182.296875, fills 1.7709 and 2.8810 press 4 on both forms; `suite-red.log`: the same two reds), but the restated stack is a second copy of `.folio-title`'s `font-family` in `src/styles/shared/atelier.css` that drifts silently when the house changes it, and it stages only `#folio-title` while the runner draws every "№" set in that face from its own fallback. The family-level face restates nothing and models the mechanism (the glyph is absent from the subset everywhere).
- **Heights of 29.219 px**: the browser lays heights out in 1/64 px, so 29.219 lands at 29.21875 (`readings.log`); the data says the value the browser lays out.
- **Reading the switch inside `e2e/harness.ts`**: the harness reads no environment today, and a bad value thrown there would end the run as `HARNESS ERROR` with exit 2, which the settle doctrine keeps for infrastructure.
- **Printing the fingerprint's mark from `e2e/run.ts`**: `e2e/run.ts` sees only the line its `out` callback is handed, so it would have to read the environment a second time, beside `plan`'s reading; the `fingerprinted` wrapper in `e2e/support/fingerprint.ts` is already handed the resolved `StartOptions` (call 12).
- **The issue's browser check** ("with the flag set the Print Room title is narrower by the measured amount and the select shorter, and unset it is not"): on the runner the selects already stand at their runner heights and the staged face probably resolves no local font, so it reads no difference there and reds on CI (`readings.log`'s `ci-like-no-local-face` arm stands in for the runner). Alex ruled PR40 (D3).
- **PR40 pinning the real staged heights** (the first draft): on the runner those equal the selects' own heights, so a rule that missed or lost would still pass there (the plan skeptic's finding 5); the sentinel reds on both machines, and T3 pins the real values.
- **Modelling the select difference as a delta** (natural height less 5 px): CSS cannot read an element's natural height, and a script that measures after layout would adopt the sheet after the room's first fit, the late form Issue #1034's plan skeptic rejected. The absolute value's blind spot is named in the doctrine instead.
- **The unit tests in `test/e2e/runner.test.ts`**: that file stands at 398 of `max-lines`' 400 counted lines (Issue #1045's plan skeptic's eslint run); the new tests go in their own file and reach the runner through `plan`, exported for them.
- **A pointer line in Issue #1043's index subsection** ("Where the Mac and the CI runner disagree"): the index points at the home of each imperative, and its Layout entry already points at the settle-doctrine bullet this plan edits and at the fingerprint line this plan marks; a second line naming the switch there would be a second copy (call 9).
- **Staging the runner's own face, `local("Liberation Serif")`, beside or in place of Times New Roman**: this Mac has no Liberation face (the recon bullet above), so the source would resolve nothing more here, and the two faces are metric-compatible, the fingerprint's title reading 98.03 px staged against the runner's 98.02; a second source would change T3's literal for no reading (call 15).
- **A proof-runner row reversing Revision 4's witnesses on CI**: the pull request's own lane D prints SW2's detail at the runner's fourth press on every run, which is the same CI control at no extra run.
