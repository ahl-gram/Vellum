### Alternatives rejected, with the reason

- **`npm audit fix` as the install command.** It moves eslint to 10.14.0 and typescript-eslint to 8.72.1 as well (the dry run), which clears nothing (both still ask for minimatch 10) and puts a lint change nobody measured into the same lockfile. The two named installs move only what the advisories need.
- **The smallest versions that clear each advisory (astro 7.3.3 and so on).** Unmeasured, and npm's own fix picks 7.4.5 and 8.3.5; a minimal bump also leaves the next upgrade larger.
- **Installing without `--before`.** The registry moves daily (astro 7.4.5 was published at 14:26Z on the day this was planned); every reading here holds only for the tree it was taken on, so the builder reproduces that tree exactly and the lockfile sha proves it.
- **A pattern accepting both marker forms** (`^\/\/(?:#region)? `). It would let the guard read an old press's markers after a rollback without anyone noticing the press had changed; the witness reds loudly when the form moves, which is what it is for.
- **Keeping the Issue #768 comment with its version bumped to 7.4.5.** A test pins it for half a second a run (C6); the comment doctrine keeps a comment only where none can.
- **npm's `eslint@4.0.0` and `typescript-eslint@8.14.0`.** Measured above: the first cannot run the lint, and neither clears minimatch.
- **Bumping eslint and typescript-eslint to their newest minors with the pin.** Not needed for any advisory, and each minor can add findings the lint fails on; a separate upgrade.
- **A test that the override exists or retires itself.** Nothing it would catch is silent: a toolchain that later needs minimatch 12 fails the lint loudly under the pin, and the rule line names the exit.
