## The design

### The rule

`vellum/src-no-tooling-import`, one rule in `scripts/lint/import-bounds.ts` beside its siblings, modelled on `homeClientNoEngine` there and built on that file's own `sourcesJudged` and `literalText`.

- **What it refuses, in every TypeScript file under `src/`:** a string that names a path landing in `e2e/`, `scripts/`, `test/` or `test-support/` at the repo root, when the string is a module source (an `import`, `import type`, `export ... from`, `export * from`, a dynamic `import()` including a template literal whose leading piece names such a path, `new URL(<it>, import.meta.url)`, a `require` or `createRequire` call: whatever `isModuleSource` in `scripts/lint/source-shape.ts` reads), or when it is a relative string held anywhere else in a value position (a specifier stored in a variable first), or when it is the source of an inline type import (`typeof import("...")`, `import("...").T`).
- **How a string lands in a folder:** a string opening with `.` is resolved against the linted file's own folder and read as a repo path (`repoPath(resolve(dirname(file), text))`); a string opening with `/` is read from the repo root (`text.slice(1)`), as the site's bundler reads a root-absolute source, and only as a module source, never as a held string, since a held `/...` string in site code is a URL path; any other string (a bare package name, prose) lands nowhere. A path lands in a folder when it IS the folder or starts with the folder's name and a `/`, so `src/site/explorer/test/part.ts` and `scripts-archive/x.ts` do not land in `test/` or `scripts/`.
- **What it does not see (declared at its test, each erring toward passing):** a specifier assembled at run time from pieces none of which is itself a relative path into the four (a path join, a concatenation); a module reached through another module; a triple-slash `/// <reference path>` directive (none in `src/` today: `grep -rn "/// *<reference" src` prints nothing); and the 26 `.astro` pages and the sheets under `src/`, which the TypeScript lint never reads (all 26 pages import from `src/` alone today, recon's grep). The import alias `import x = require("...")` is refused by `npm run check` first (TS1294 under `erasableSyntaxOnly`, measured: `out/1132-dry-run/1132-require.log`).

The rule joins the existing last block of `eslint.config.ts`, today named `Issue #763: no script switches layout at a fixed window width at or below the 1024 floor`, whose `files` are exactly `["src/**/*.ts"]` with `plugins: { vellum }`: it is the block that already reaches the same files with the same plugin (`handbook/specs/check-placement.md`, The lint). ### Alternatives rejected

- **`sourceBan` with a text predicate** (`text.includes("scripts/")`, the issue's sketch). Rejected: `sourceBan`'s predicate gets the string alone, not the linted file, so it cannot resolve a relative path; a text match refuses a `src/` folder named `test` and is blind to which folder `../` lands in (mutation M8 below measures the difference).
- **Four rules, one per folder.** Rejected: one predicate over one list (`TOOLING_ROOTS`) says the rule once; ruling 3 says "in the same rule".
- **A new config block** for the rule. Rejected: `handbook/specs/check-placement.md` wires a rule into the block that already reaches the same files with the same plugins, and the Issue #763 block is exactly that.
- **Scope inside the rule** (`create` returning `{}` unless the file is under `src/`) and wiring on every root. Rejected: the house scopes rules by config block and pins the scope with `calculateConfigForFile`, as `test/repo/narrow-width.test.ts` does.
- **A bullet in "Durable engineering constraints from shipped work".** Rejected: that section calls itself "a convenience index, not their home", and ruling 1 makes the rulebook this rule's home.
- **Covering the triple-slash directive** by reading comments. Rejected as more code than the case is worth: nothing in the tree writes one, it is not an import, and it is declared as a blind spot.
