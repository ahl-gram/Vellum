## What is wrong, as measured at `0300bdb1`

- `skipFor(skips, step)` (`e2e/support/skips.ts` lines 19 to 21) is `skips.find((s) => s.step === step)`: an entry matches a step by its name alone.
- `makeStep` (`e2e/support/step.ts`, line 5) calls `skipFor(skips, name)` at line 19 and records a skip as the bare name, `skippedChecks.push(name)` at line 21. It is never told its suite.
- Two more readers match by name alone, which the issue does not name:
  - `unmetSkips` (`e2e/support/skips.ts` line 32) checks the suite only to ask whether it ran; whether the step was met is `!met.includes(s.step)`, and `met` is the flat list of bare names.
  - the runner's outcome line (`e2e/support/runner.ts` lines 174 to 177) is fed `skips.filter((s) => skippedChecks.includes(s.step))`.
- So once two entries name the same step in two suites, one suite's skip counts as the other's: the outcome line names an entry whose suite never skipped anything, and an entry whose step was renamed away is spared the leftover red. Fixing `skipFor` alone leaves both.
- The context is built ONCE per run (`runner.ts` line 163, `io.start(...)`, through `fingerprinted` in `e2e/support/fingerprint.ts`), and `runSelected` (`e2e/support/suites.ts` line 154) hands that one object to every suite at line 171 (`await run(ctx)`). A `suite` field cannot be "set where the runner builds it": the only place that knows each suite's name is the loop in `runSelected`.
- The bug is latent, not live: across the 33 suites there are 429 step names and none is held by two suites (`node /private/tmp/claude-501/-Users-ahl-CodeProjects-Vellum/ca724480-6383-4266-b511-508f7438e704/scratchpad/p1135-steps.ts <tree>`, which reads the `step("...")` literals in each suite's file and folder; `vellum-spec-recon` counted the same with a grep). Every one of the 7 entries in `E2E_SKIPS` names a step held only by its own suite.

## The design (ruled by Alex, comment 6544205395)

1. **The runner hands each suite its own name.** `runSelected` calls each suite with a shallow copy of the shared context plus that suite's name: `await run({ ...ctx, suite: name })`. The copy shares every member by reference, so the sinks the harness, `check` and `makeStep` push to (`results`, `consoleErrors`, `http4xx`, `skippedGroups`, `skippedChecks`) are still the runner's own arrays, as the comment at `e2e/harness.ts` line 350 says. The runner's own context is never written to.
2. **The types say who has a suite.** What `start()` returns is renamed `HarnessContext` (no suite: it exists before any suite is chosen). `SuiteContext`, the type every suite file already takes, becomes `HarnessContext` plus `readonly suite: E2eSuiteName`, through one generic `SuiteTagged<C>` in `e2e/support/suites.ts`. No suite file changes: all 36 `makeStep(ctx)` and `makeStep(k)` calls in 31 files type-check unchanged, since `ctx` is a `SuiteContext` and every kit is built as `{ ...ctx, ... }` (`e2e/suites/home/kit.ts` line 14 for the `k` that `e2e/suites/home/gestures.ts` line 58 passes).
3. **`makeStep` takes a required `suite`** and passes it to `skipFor(skips, suite, step)`, which matches both.
4. **The skip record carries its suite.** `skippedChecks` becomes `E2eSuiteStep[]` (`{ suite, step }`), and both other readers match suite and step: `unmetSkips` for the leftover red, and a new `metSkips(skips, met)` that replaces the runner's inline filter for the outcome line.

### Alternatives rejected, with the reason

- **`makeStep` taking the suite as an argument at each call site, `makeStep(ctx, "hunt")`** (the issue's other route): rejected by Alex's ruling (comment 6544205395). It would touch 36 call sites in 31 files under `e2e/suites/`, and nothing would check that a written name matches its file, so one copied wrong name would silently bring this bug back; only a new lint rule could guard it.
- **Set a `suite` field where the runner builds the context** (the issue's wording): impossible as written, one context serves every suite.
- **Write `ctx.suite = name` on the shared context before each suite**: shared mutable state, against the house immutability rule; a suite holding the object would see the next suite's name.
- **Wrap each runner in `e2e/support/suite-map.ts`** (`render: (ctx) => runRender({ ...ctx, suite: "render" })`): 33 hand-written names, the same mistype risk as writing the name at each call site, and `runSelected` already holds the name.
- **Slice `skippedChecks` per suite in `runSelected`, as it does `skippedGroups` into the timings**: more machinery than recording the suite beside the step.
- **Keep `skippedChecks` as strings holding a `suite/step` key**: a string standing in for a type.
- **An optional `suite` on `makeStep`**: a caller that forgets it would silently never skip anything; required, the type checker refuses it.
- **A run-time throw in `makeStep` when `suite` is missing**: the type is the guard; the only callers that can reach it without a suite are test fakes built with `as unknown as SuiteContext`, and none of them reaches a suite that has an entry (measured below).
- **Naming the suite in `skipLabel`'s text**: changes the outcome line the lane driver parses and tests in `test/e2e/skips.test.ts` and `test/e2e/runner.test.ts` pin, for no gain; each entry's issue number already tells two same-named steps apart.
