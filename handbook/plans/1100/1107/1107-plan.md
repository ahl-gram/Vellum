## What the issue asks, in one paragraph

## The design

**What a character is.** The wrap and the opening capital stop working on code points and work on grapheme clusters, a character as a reader sees one, from the platform's own Unicode rules: `new Intl.Segmenter("en", { granularity: "grapheme" })`. A flag (two regional indicators), an emoji with its skin tone, an emoji with its variation selector, a letter with its combining marks, a keycap, a tag flag, a Hangul jamo cluster and an Indic conjunct are each one character.

**One bound on a character, `CHARACTER_UNITS = 10`.** The widest emoji sequence Unicode names, a kiss between two people with skin tones, counts 10 width units under `widthUnits`. Measured 2026-10-30 over all 2915 sequences in Unicode 18.0's `emoji-sequences.txt` and `emoji-zwj-sequences.txt` (ranges of single code points excluded, since one code point counts at most 2): every one is a single cluster in Node's segmenter, and the widest is 10. A cluster wider than that is not a character any font draws as one glyph, so it is broken into its parts:
1. after each U+200D, each part keeping its own skin tone and selector, the joiner staying at the end of the earlier part;
2. a part still wider than `CHARACTER_UNITS`, which only a degenerate run reaches (a base with dozens of skin tones), between code points.

The same rule serves both readers, the wrap and the capital, so one function holds it.

**What the wrap does with characters.** Nothing else changes: `pieces` breaks only a word wider than a line, filling greedily character by character, and `foundingLines` fills lines word by word, exactly as today. `widthUnits` and `FOUNDING_LINE_UNITS` are untouched, as the issue asks.

**What the capital takes.** `openingCapital` reads the first line's characters: the first is the opening quotation mark, the second the capital, uppercased, and the rest is the line's remaining text, exactly the shape it has today. A combining mark that opens the sentence attaches to the quotation mark under Unicode's own rule (it follows a character), so the quotation mark carries it and the first letter is still the capital. A flag or an emoji that opens the sentence is the capital, like any first character (Issue #392's plan, call 14).

**Where the segmenter is built.** Inside `characters`, on each call, never at module load. `cartouche.ts` imports this module for every chart, and `engravedLines` returns `[]` before any wrap when a chart has no founding text, so a numeric chart never constructs a segmenter: a browser lacking `Intl.Segmenter` could fail a founded sheet, never a numeric one. The locale is fixed at `"en"` because `undefined` reads the host's default locale; grapheme segmentation has no locale tailoring.

### The planned module

The full file after the change, 128 lines. It was run in the planner's tree (Evidence, the dry run). Write it exactly:

```ts
import { el, type SvgNode } from "../svg.ts";
import type { MapStyle } from "../style.ts";
import type { World } from "../../world/types.ts";

export const FOUNDING_LINE_UNITS = 48;
// 2026-10-30: the widest of the 2915 sequences in Unicode 18.0's emoji-sequences.txt and emoji-zwj-sequences.txt, a kiss between two people with skin tones, counts 10 width units.
const CHARACTER_UNITS = 10;
const FONT = 11.5;
const PITCH = 16;
const GAP = 22;
const CAPITAL_SCALE = 1.7;
const CAPITAL_RISE = 6;
const OPEN_QUOTE = "\u{201C}";
const CLOSE_QUOTE = "\u{201D}";

const WIDE =
  /[\p{Script=Han}\p{Script=Hiragana}\p{Script=Katakana}\p{Script=Hangul}\p{Extended_Pictographic}\u{3000}-\u{303F}\u{FF01}-\u{FF60}\u{FFE0}-\u{FFE6}]/u;
const JOINER = /[\p{M}\p{Variation_Selector}\u{200D}]/u;
const AFTER_ZWJ = /(?<=\u{200D})/u;

const unitOf = (cp: string): number => (JOINER.test(cp) ? 0 : WIDE.test(cp) ? 2 : 1);

export function widthUnits(text: string): number {
  let n = 0;
  for (const cp of text) n += unitOf(cp);
  return n;
}

function fitted(cluster: string): string[] {
  if (widthUnits(cluster) <= CHARACTER_UNITS) return [cluster];
  return cluster.split(AFTER_ZWJ).flatMap((part) => (widthUnits(part) <= CHARACTER_UNITS ? [part] : Array.from(part)));
}

function characters(text: string): string[] {
  const clusters = new Intl.Segmenter("en", { granularity: "grapheme" }).segment(text);
  return Array.from(clusters, ({ segment }) => segment).flatMap((cluster) => fitted(cluster));
}

function pieces(word: string, max: number): string[] {
  const out: string[] = [];
  let cur = "";
  let units = 0;
  for (const unit of characters(word)) {
    const u = widthUnits(unit);
    if (cur !== "" && units + u > max) {
      out.push(cur);
      cur = "";
      units = 0;
    }
    cur += unit;
    units += u;
  }
  if (cur !== "") out.push(cur);
  return out;
}

export function foundingLines(text: string, max: number = FOUNDING_LINE_UNITS): string[] {
  const lines: string[] = [];
  let cur = "";
  let units = 0;
  for (const piece of text.split(" ").flatMap((word) => (word === "" ? [] : pieces(word, max)))) {
    const u = widthUnits(piece);
    if (cur === "") {
      cur = piece;
      units = u;
    } else if (units + 1 + u > max) {
      lines.push(cur);
      cur = piece;
      units = u;
    } else {
      cur = `${cur} ${piece}`;
      units += 1 + u;
    }
  }
  if (cur !== "") lines.push(cur);
  return lines;
}

export function engravedLines(world: World): ReadonlyArray<string> {
  const text = world.recipe.foundingText;
  if (text === undefined || text.trim() === "" || world.region !== undefined) return [];
  return foundingLines(`${OPEN_QUOTE}${text}${CLOSE_QUOTE}`);
}

export function foundingRise(lineCount: number): number {
  if (lineCount === 0) return 0;
  return GAP + CAPITAL_RISE + (lineCount - 1) * PITCH;
}

function openingCapital(style: MapStyle, line: string, k: number): ReadonlyArray<SvgNode | string> {
  const [quote = "", capital = "", ...rest] = characters(line);
  const size = (FONT * CAPITAL_SCALE * k).toFixed(1);
  return [
    el("tspan", { "font-family": style.fontFamilyTitle, "font-size": size }, [`${quote}${capital.toUpperCase()}`]),
    rest.join(""),
  ];
}

export function foundingNodes(
  style: MapStyle,
  lines: ReadonlyArray<string>,
  cx: number,
  subtitleBase: number,
  k: number,
): SvgNode[] {
  if (lines.length === 0) return [];
  const first = subtitleBase + (GAP + CAPITAL_RISE) * k;
  return [
    el(
      "g",
      { id: "cartouche-founding" },
      lines.map((line, i) =>
        el(
          "text",
          {
            x: cx,
            y: first + i * PITCH * k,
            "text-anchor": "middle",
            "font-family": style.fontFamily,
            "font-size": (FONT * k).toFixed(1),
            fill: style.ink,
          },
          i === 0 ? openingCapital(style, line, k) : [line],
        ),
      ),
    ),
  ];
}
```

### Alternatives rejected

- **A hand-rolled cluster rule from property escapes**, which PR #1106's plan preferred. Its stated reason, that `Intl.Segmenter`'s answer comes from the platform's Unicode data, does not separate the two: the property escapes the module already uses (`\p{Extended_Pictographic}`, `\p{M}`) read the same engine's Unicode data. What does separate them: a JavaScript regular expression has no `Grapheme_Cluster_Break` property, so a hand-rolled rule can only approximate Unicode's (no SpacingMark, Prepend, Hangul L/V/T or conjunct class), and `\p{Grapheme_Extend}` is not the rule's Extend (measured: false for the skin tone U+1F3FD), so it needs `\p{Emoji_Modifier}`, regional-indicator pairing and pictograph-after-joiner state on top, each a branch to test and prove, and still carries named blind spots. The segmenter is complete for the platform's Unicode version in one call.
- **Splitting only a cluster wider than a line**, the issue's literal threshold. It leaves a quotation mark alone on its own line when a joined chain exactly a line wide opens or closes the sentence (Test T5 shows `["“", chain, "”"]` on main), and the capital would then need a second, smaller bound to keep a long chain from being set at 1.7 times across the frame. One bound at the widest named emoji keeps every named emoji whole and serves both readers. It splits nothing a font draws as one glyph.
- **Splitting a wide cluster straight to code points:** a skin tone lands at the start of a line (T4 under mutation M4).
- **Dropping the joiner at a break:** the lines would no longer put back together to the sentence, which Issue #392's T1c pins; a joiner at the end of a line draws nothing.
- **Counting width per cluster** (a flag or an emoji sequence as 2): the issue says keep the counting, and the overcount errs toward a narrower line, never a wider one.
- **Building the segmenter once at module load:** a browser without `Intl.Segmenter` would throw on importing the renderer and lose every chart, numeric ones included.
- **The host's locale (`undefined`):** a host read the renderer has no need of.
- **Taking the capital from the text after the quotation mark, by prefix:** when a stray mark opens the sentence it makes the mark the capital and leaves the first letter at body size, while Unicode attaches the mark to the quotation mark anyway.
- **Not enlarging an emoji capital:** a look change nobody asked for; Issue #392's call 14 sets any first character at the capital's size.
- **A browser check:** the unit suite sees the whole wrap (`handbook/specs/check-placement.md`), the browser was measured to agree, and the CI runner has none of the chart's faces.
- **Refusing or stripping emoji at founding:** that is `displayForm`, the 120-code-point cap and founding version 1, which Issue #393 locks; nothing under `src/world/founding/` changes here.

### Known limits, not built against

- **A degenerate part.** A part still wider than `CHARACTER_UNITS` after the joiner split (a base followed by a run of skin tones, no joiner) breaks between code points when it falls at a hard break or in the capital, so a skin tone can open a line there. Only degenerate input reaches it, every line stays within the width, and it is the issue's own "between code points only as a last resort".
- **The bound is Unicode 18.0's.** `CHARACTER_UNITS` is the widest sequence Unicode had named when it was set. If a later version names a wider one (a family with skin tones would count about 12), the rule splits that emoji after its joiners, in the capital and at a hard break inside a word wider than a line. It errs toward parting a new emoji, never toward a line past the frame. The re-measure is the sweep this plan ran: download the newer `emoji-sequences.txt` and `emoji-zwj-sequences.txt` from `https://unicode.org/Public/emoji/latest/`, and take the largest `widthUnits` over their sequences (ranges excluded); a larger number moves the constant and its dated line together, and T6's two fixtures with it.
