## The design

### T8: no ci.yml job reads its trigger

**The defect class** is a ci.yml job that behaves differently on a pull request than on a push to `main`, by any means other than the docs-only verdict. A YAML step learns its trigger in one of two ways:
- through an expression, in any key: `${{ github.event_name }}`, `${{ github.head_ref }}`, `${{ github.event.pull_request.labels }}`, `${{ github.ref }}` and the like, in `continue-on-error`, `env`, `with`, `timeout-minutes` or `run`;
- through one of GitHub's event variables, read in a shell.

The `if:` lines are already held: T6 holds every lane step's, and T7 holds the unit job's.

**T8 sweeps every job under `jobs:`.** It reads job heads by the same two-space-key rule as `ciJob` in `test-support/ci-job.ts`, so a job added later is swept without an edit. It asserts three things:

- **Expressions.** The set of expressions the jobs hold is exactly `["github.token", "matrix.lane", "matrix.shard", "strategy.job-total"]`. This is an allow-list keyed on the defect (Gate 7 item 2): any other expression reds, whatever context it reads. The exact match is also the sweep's anchor, since a reader that finds nothing reds (Gate 1 item 4).
- **Event variables.** No line in any job names `GITHUB_EVENT_NAME`, `GITHUB_EVENT_PATH`, `GITHUB_HEAD_REF`, `GITHUB_BASE_REF`, `GITHUB_REF_NAME`, `GITHUB_REF_TYPE` or `GITHUB_REF`. The scope step reads the event inside `scripts/docs-only.ts`, never in ci.yml.
- **Labels.** No line in any job names a label or `full-e2e`.

**Its blind spot, with its direction.** A `run:` body that learns its trigger without an expression or one of those variables slips past, such as one that calls `gh` or `git`. That is a miss, which review holds. An expression the list does not name reds, which is the safe side.

### The line-break refusal

**The defect.** `main` prints one line per changed path (`doc  <path>` or `code <path>`) and a reason line that can name a path. A path may hold a line break, and git's `-z` list hands it over raw. The runner reads each line of a step's stdout for workflow commands, which begin `::`, so a path can start a line the runner may act on. Whether the runner would honour a given command over the `GITHUB_OUTPUT` file is UNVERIFIABLE here, so the path is kept off stdout altogether.

**`isUnsafePath`** is true when a path holds any of these characters:
- a code point below U+0020, which covers line feed, carriage return and tab;
- U+007F;
- U+0085;
- U+2028;
- U+2029.

That is every character a line reader might take for a line end, and every other control character.

**`verdict` calls it on the read diff** after the merge-commit check and before classifying. When any changed path is unsafe, `verdict` returns `docsOnly: false` with an empty `changed`, so `main` prints no path and the reason line names none. So a refused diff runs every lane, the fail-safe direction, and nothing a path holds reaches stdout. Paths that pass the check print as today, since none of them can begin a line.

### Rejected

- **Restoring the deleted test's two `doesNotMatch` assertions** over the lane job. They catch only `github.event_name` and `full-e2e`, so `${{ github.head_ref != '' }}` passes them.
- **Refusing `github.event` and `labels` in the lane job only.** It misses `github.head_ref`, `github.ref` and `github.base_ref`. It also leaves the unit job unswept, where the same expression lets a shard pass on a pull request and fail on main.
- **T8 in `test/repo/e2e-tiers.test.ts`.** That file is at 387 lines, and T8 reads the same ci.yml as T6 and T7.
- **Escaping each printed path** (`JSON.stringify`) and keeping the verdict (call C16). The verdict's safety would then rest on the escape covering every character the runner reads as a line end. It would also keep a docs-only verdict on a diff no real change makes. A refusal is one check before anything prints, and its only cost is a full run.

### `scripts/docs-only.ts`

- **The new export**, after `isDoc`: `export const isUnsafePath = (path: string): boolean`. It is true when any character of `path` has a code point `c` with `c < 0x20 || c === 0x7f || c === 0x85 || c === 0x2028 || c === 0x2029`. Write it as `[...path].some((ch) => { const c = ch.codePointAt(0) ?? 0; return ...; })`, never as a regular expression: `no-control-regex`, in the lint's `js.configs.recommended`, refuses control characters in one.
