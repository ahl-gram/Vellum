## The design

One script decides, per lane job, whether the pull request's diff is docs only; the workflow carries a single condition that reads its answer.

1. **`scripts/docs-only.ts`** holds the doc list and the verdict. A doc is a path that `isDoc` names: one of `DOC_FILES` exactly, or any path under one of `DOC_DIRS` (each ending in `/`). The verdict is docs-only only when the event is `pull_request`, the changed files were read, there is at least one, and every one is a doc. Everything else, a push, a run started by hand, an empty diff, a HEAD that is not a two-parent merge commit, a git command that throws, is a full run. The script never exits non-zero for a doubt: it writes `docs_only=false` and the lane runs in full.
2. **The changed files are read off the merge commit's first parent.** A `pull_request` run checks out `refs/pull/<N>/merge`, whose first parent is the base branch's tip and second the pull request's head (measured below), so `git diff --name-only --no-renames -z HEAD^1 HEAD` is exactly what the pull request would change on its base. `--no-renames` lists a move at both ends (measured below: without it, `git mv src/a.ts handbook/a.md` lists only `handbook/a.md` and would read as docs-only). `-z` gives unquoted paths, so a path with a character git would quote still matches the list.
3. **Each of the four `build-and-e2e` jobs classifies its own diff, as a step, and keeps running and reporting.** Steps, in order: checkout with `fetch-depth: 2` (depth 1 leaves the merge commit with no parents, measured below); `actions/setup-node` with Node 26 and no cache; the scope step (`id: scope`) running `node scripts/docs-only.ts`; then the cached `actions/setup-node`, `npm ci`, the build, the runner shape and hash, and the e2e lane, each behind `if: steps.scope.outputs.docs_only != 'true'`. Written `!= 'true'`, an output that was never written runs the step. The job ids, the job names and the eight required checks do not change, so branch protection needs no edit.
4. **The unit jobs (`check-and-test`) are untouched** and run on every diff, since the unit suite reads the docs (`PROSE_ROOTS` in `test/repo/prose-paths.test.ts`, `test/repo/memory-pointers.test.ts`, `test/repo/footgun-gate.test.ts` and more, recon row 2).
5. **A push to `main` and a run started by hand run every lane**: the script returns a full run for any event but `pull_request`, and the workflow's only condition is the script's output.

### Rejected, so the builder does not rediscover them

- **A first job that classifies, with the lanes `needs:` it** (the issue's sketch). A classifier that fails makes the lanes "skipped by dependency", which GitHub counts as passing: four required lanes green with no browser run. It also puts a whole extra job, 18 to 39 s of set-up measured on every lane job in seven runs, in front of every code pull request's longest job, and a ninth CI job breaks the proof runner's room (`CONCURRENT_JOBS` in `test/repo/proof-runner-workflow.test.ts`: 8 CI jobs, `max-parallel: 11`, 1 deploy build, 20 in all).
- **A workflow-level `paths-ignore`**: the eight required checks stay Pending and block the merge (GitHub's page, above).
- **A job-level `if:` on the lane matrix**: needs the classifying job above, and a matrix job skipped whole may report under its unexpanded name, which nobody here has measured.
- **One `actions/setup-node` with `cache: npm` before the scope step.** On a cache miss its post step saves `~/.npm`, and `saveCacheV2` in actions/toolkit `packages/cache/src/cache.ts` throws "Path Validation Error: Path(s) specified in the action for caching do(es) not exist" when the folder is absent, which `run` in actions/setup-node v4 `src/cache-save.ts` turns into a failed step: a docs-only lane, which ran no `npm ci`, could go red. Whether `~/.npm` exists on a fresh runner is UNVERIFIABLE here, so the cached call runs only behind the condition; a skipped step has no post step, and an uncached call's post step finds no package manager in its state and does nothing (same file).
- **No cache at all**: a cold `npm ci` on every code pull request's lanes.
- **The GitHub API's list of a pull request's files**: a token scope, a network call and a 3000-file cap, where git on the checked-out merge commit is local.
- **A third-party changed-files action** (`dorny/paths-filter` and the like): supply-chain surface, and its logic is out of reach of the unit suite.
- **Any `.md` as a doc**: `design/kit/outlines/README.md` is read by `scripts/outlines/kit.ts` (recon row 3 corrects the issue's path) and `design/kit/fonts/` feeds the build.

### `scripts/docs-only.ts`

Imports `execFileSync` from `node:child_process` and `appendFileSync` from `node:fs`, nothing else.

- `export const DOC_DIRS: readonly string[] = ["handbook/", ".claude/agents/", ".claude/skills/vellum-footguns/references/"];`
- `export const DOC_FILES: readonly string[] = ["AGENTS.md", "CLAUDE.md", "README.md", ".github/PULL_REQUEST_TEMPLATE.md", ".claude/skills/vellum-footguns/SKILL.md", ".claude/skills/vellum-footguns/hooks/README.md"];`
- `export const OUTPUT_KEY = "docs_only";`
- `export type Verdict = { readonly docsOnly: boolean; readonly changed: readonly string[]; readonly reason: string };`
- `export const isDoc = (path: string): boolean`: `DOC_FILES.includes(path) || DOC_DIRS.some((dir) => path.startsWith(dir))`. Directly above it, the one comment line, verbatim: `// Blind spot, with its direction: nothing reads whether the build or a browser check opens a listed file, so a list that grows past what they read lets a docs-only pull request merge with its lanes unbuilt, and main's own run, which runs every lane, is where that shows (handbook/specs/site-architecture.md).`
- `export const docsOnly = (event: string, changed: readonly string[] | null): boolean`: `event === "pull_request" && changed !== null && changed.length > 0 && changed.every(isDoc)`.
- `export const changedPaths = (dir: string): string[] | null`: runs `git rev-list --parents -n 1 HEAD` in `dir`; when the printed line does not hold exactly three shas (the commit and two parents), returns `null`; else runs `git diff --name-only --no-renames -z HEAD^1 HEAD` in `dir` and returns its output split on `"\0"` with empty strings dropped. Each git call is `execFileSync("git", args, { cwd: dir, encoding: "utf8", timeout: 30_000, stdio: ["ignore", "pipe", "pipe"] })`, no shell.
- `export const verdict = (event: string, dir: string): Verdict`, in this order:
  - `event !== "pull_request"`: `{ docsOnly: false, changed: [], reason: \`a ${event || "run with no event name"} runs every lane\` }`, with no git call;
  - `changedPaths(dir)` inside `try`; on a throw: `{ docsOnly: false, changed: [], reason: \`the changed files could not be read (${String(error).split("\n")[0]}), so every lane runs\` }` (no cast: `vellum/no-error-cast`);
  - `null`: `{ docsOnly: false, changed: [], reason: "HEAD is not a merge commit with two parents, so the changed files are unread and every lane runs" }`;
  - otherwise `docsOnly: docsOnly(event, changed)`, `changed`, and `reason`: for true, `` `every one of the ${changed.length} changed files is a doc, so this lane skips its build and browser steps` ``; for an empty list, `"the diff is empty, so every lane runs"`; else `` `${off.length} of the ${changed.length} changed files are not docs (the first is ${off[0]}), so every lane runs` `` where `off` is `changed.filter((p) => !isDoc(p))`.
- Not exported, `main`: `const v = verdict(process.env["GITHUB_EVENT_NAME"] ?? "", process.cwd())`; prints one line per changed path, `` `doc  ${path}` `` or `` `code ${path}` ``; prints `` `docs-only: ${v.docsOnly}: ${v.reason}` ``; when `process.env["GITHUB_OUTPUT"]` is set, `appendFileSync(out, \`${OUTPUT_KEY}=${v.docsOnly}\n\`)`. Always exits 0. The file ends `if (import.meta.main) main();` (the form `scripts/proof-runner/list.ts` uses).

`GITHUB_EVENT_NAME` and `GITHUB_OUTPUT` are GitHub's default variables in every step, so the workflow passes no `env:` to the scope step.
