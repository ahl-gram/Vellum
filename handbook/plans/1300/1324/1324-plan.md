## What this builds

1. **`npm run comment-sweep -- verify <base> <head>`**, the proof the spec asks for: it reads two commits from git, from their merge base to the head, and compares every file the head changes, TypeScript and JavaScript through `ts.createSourceFile`, sheets through the CSS tokenizer the lint already uses, pages through Astro's own parser (ruling 3), each with its comments removed. It prints the file and the first difference's line on each side for every file that differs, names every file added, deleted, renamed or of a kind it does not read, passes house prose, and exits 0 only when every changed file is token-identical or prose. No Jev call, no probability: its unit tests hold it.
2. **The project skill `comment-sweep`** (`.claude/skills/comment-sweep/SKILL.md`): the weekly sitting's nine steps in order, each naming its command and the spec line that is its rule. It holds no rule.
3. **The doctrine that goes with them**: the spec's sweep bullets name the command and the skill, the routing rule says a sitting's skill holds no rule, `check-placement.md` says why no CI check holds a sweep, and `vellum-pr-skeptic` runs the verifier on a sweep's pull request (ruling 1).

## The design

### What is read, and from where

`verify` resolves `<head>` to a sha with `revParse`, takes `from = mergeBase(repo, <base>, sha)`, and reads both trees from git with `gitTree` (all in `scripts/comment-judge/tree.ts`). The changed paths are `changedFiles(repo, from, sha)` (added, modified and renamed, renames found) followed by `deletedFiles(repo, from, sha)` (Issue #1320). Reading from the merge base is what makes the spec's collision rule mechanical: before `main` is merged into the sweep the base is where the branch began, and after it the base is `main`'s tip, so either way only the sweep's own edits are compared (measured, `temp-repo.log`, below).

Each path gets exactly one finding, first match wins:

1. **prose**: `isDoc` in `scripts/docs-only.ts` accepts the path (and, for a rename, the old path too). Listed, never failing: a sweep's pull request may carry an errata row (`handbook/specs/development-workflow.md` step 15).
2. **added**, **renamed**, **deleted**: a sweep adds, renames and deletes nothing. Each fails.
3. **not read**: `readerOf(path)` is `null`. Fails.
4. **identical** or **differs**: the reader's token streams of the two texts compared, the first difference reported.

### The three readers

**Scripts** (`.ts .mts .cts .tsx .js .mjs .cjs`, `.d.ts` included): `ts.createSourceFile(path, text, ts.ScriptTarget.Latest, true, kind)`, `kind` TSX for `.tsx`, JS for the three JavaScript endings, TS otherwise, walked through `getChildren`. Every node pushes its kind (`ts.SyntaxKind[node.kind]`), and every leaf pushes its text (`getText`, which carries no trivia). A node in the JSDoc kind range, `FirstJSDocNode` to `LastJSDocNode`, is skipped with everything under it. Comments are trivia, so they never reach the stream.

- **Why kinds as well as leaves**: leaves alone read `return` with its value on the next line as `return x` (automatic semicolon insertion makes the first return nothing). Measured: with kinds not pushed, the fixture "a return joined to its value" reads as no change (`mutation-matrix.log`, `nokinds`).
- **Why not `ts.createScanner`**: on the two regular-expression fixtures below, a scanner reads a backtick or a `/*` inside the literal as the start of a template or a comment and reports drift that is not there (`mutation-matrix.log`, `scanner`).

**Sheets** (`.css`): `tokenize` from `@eslint/css-tree` (already a direct devDependency). A Comment token is dropped. A run of WhiteSpace tokens becomes one `" "` token between the tokens around it, and none at the start; every other token pushes its source text. So reindentation reads as no change, while `.a .b` against `.a.b` (a descendant combinator joined) reads as a change. A `/*` inside `url(...)` is part of the url token, so removing it is a change.

**Pages** (`.astro`) (ruling 3): `parse` from `@astrojs/compiler-rs`, Astro's own parser, which the site already installs at 0.5.2 through `astro`. Its tree is plain JSON (oxc's ESTree with Astro nodes); JavaScript comments are not in it, only in the root's `comments` list. The walk pushes each node's `type`, then each field in order except `type`, `start` and `end`: a primitive pushes `key=<JSON>`, a node pushes `key:` and is walked, an array pushes `key:` (and one token holding the JSON of any primitive items) and its items are walked as a list. Four things are left out or normalised, which is exactly where a page's comments live:

- the root's `comments` list (frontmatter and script comments);
- an `AstroComment` node (`<!-- -->`) and a `JSXExpressionContainer` whose expression is a `JSXEmptyExpression` (`{/* */}`), dropped from any list;
- adjacent `JSXText` items, once those are dropped, merged into one run; a run is pushed as `text <JSON of the run with each whitespace run made one space>`, except that a run of whitespace alone is not pushed at all when it is the first or last item of its list; a `JSXText`'s `raw` field is not read;
- the text of a `<style>` element's children is read with the sheet reader instead, its lines counted from the page.

Each parse diagnostic pushes `diagnostic <severity> <text>` at the end, so a sweep that breaks a page reads as a change.

### The blind spots, each named with its direction

All four err toward passing, and none can hide a change a sweep is likely to make. The spec today accepts the first alone ("Pure reindentation is its one acceptable blind spot"); the second and third widen that line, as ruling 4 rules, and the proof bullet is rewritten to say so:

- **pure reindentation**, the spec's own accepted blind spot;
- **in a page, whitespace**: a whitespace run read as one space, and a whitespace-only run at the edge of an element's content not read. Without the edge rule, removing a `<!-- -->` line directly after the frontmatter reads as a change (measured, the fixture "an html comment directly after the frontmatter", `mutation-matrix.log`, `keepedge`). `git grep -n -E "<pre|is:raw" -- '*.astro'` prints nothing at `fc6d7b03`, so no page today holds text whose whitespace is meaningful;
- **a directive comment** (`@ts-expect-error`, `eslint-disable-line`, `prettier-ignore`) reads as a comment; its removal is reported by the sweep pull request's own type check, lint and format check wherever it was still doing its work. The tree holds 13 `@ts-expect-error` and about 20 `eslint-disable` lines today (`directives.log`);
- **a type change** (a file made a symlink) is in neither `changedFiles` nor `deletedFiles`; nothing in a sweep makes one.

A comment inside a template literal is string data rather than a comment, so removing it reads as a change by construction; on PR #377 that is exactly what the verifier reports (below).

### The report

Printed to stdout, each line exactly:

```
comment-sweep verify, read from <from sha> to <head sha>
PROSE <path>
DIFFERS <path>: base <side>, head <side>
ADDED <path>
RENAMED <old path> to <path>
NOT READ <path>: the verifier reads TypeScript, JavaScript, sheets and pages only
DELETED <path>
comment-sweep verify: <n> changed files; identical <i>, differ <d>, added <a>, deleted <x>, renamed <r>, not read <u>, prose <p>
```

- One line per finding except `identical`, in finding order (the changed paths in git's order, then the deleted paths in git's order). `<n>` is the number of findings.
- `<side>` is `line <line> <JSON.stringify(text)>`, or `the end of the file` where that side's stream ended first.
- The excerpt: the first pair of tokens whose texts differ (lines are never compared, so a comment removed above shifts nothing); `k` the length of their texts' common prefix, 0 where one side has no token; each side's line is its token's line plus the line breaks in its text before `k`, and its text is `token.text.slice(Math.max(0, k - 20), k + 40)`. A long template literal therefore shows where inside it the two differ.
- Exit 0 when every finding is `identical` or `prose`, 1 otherwise, 2 on a usage error (printed to stderr); a thrown error (a ref git cannot resolve) prints its message and exits 1.

```markdown
# The weekly comment sweep

This is the order of the sitting and the command each step runs. It holds no rule: each step names
the line of `handbook/specs/conventions.md`, The comment sweep, that is its rule, and that section
wins wherever the two disagree. Read the section in full before step 1, and the comment doctrine it
applies, the opening paragraph of "Durable engineering constraints from shipped work" in
`handbook/specs/rulebook.md`. `<date>` is the sitting's date, written `YYYY-MM-DD`.

1. **Find the base and the head.** Run `git fetch --tags origin`; the base is
   `git tag -l 'comment-sweep/*' --sort=-refname | head -1`. The head is `git rev-parse origin/main`,
   read once and written down: the sweep reads up to it, and step 9 tags it whatever merges in the
   meantime (the section's first bullet).
2. **Collect the comments the range adds.** `npm run comment-judge -- diff <base> <head> --dry-run`
   gives the size of the run; the same without `--dry-run`, and with
   `--out out/comment-sweep-<date>`, lists every TypeScript comment the range adds beside Jev's
   answer whether a test pins it. A Jev answer is a hypothesis to check, never a verdict, a
   `SKIPPED` line is a comment nobody judged, and the key is never printed
   (`handbook/specs/check-placement.md`, the bullet opening "No check holds a judgment that rests
   on a probability"). The command reads TypeScript only, so collect the sheets' and the pages'
   added comments by hand, from `git diff <base> <head> -- '*.css' '*.astro'`.
3. **Judge each comment against the doctrine**, the trailing comments last and most conservatively
   (the section's second bullet). A line holding `rewritten for a red on CI` stays (the section's
   keeper-scan bullet).
4. **Cut on a branch from the head, writing the ledger as you cut.** Name the branch
   `chore/comment-sweep-<date>`. Every deletion made because a test pins the behaviour names that
   test in the ledger at the moment it is cut, once you have read that the test pins what the
   comment said (the section's bullet opening "Every deletion"). Commit the cuts. A week with
   nothing to cut goes straight to step 7.
5. **Prove that no code changed.** `npm run comment-sweep -- verify origin/main HEAD` must exit 0
   (the section's proof bullet). A `DIFFERS`, `ADDED`, `DELETED`, `RENAMED` or `NOT READ` line is
   fixed on the branch, never argued.
6. **Scan the cuts for keepers**, as the section's keeper-scan bullet says, and read by hand
   everything it hands you. Put each keeper fact back at its line or into the test that pins it,
   commit, and run step 5 again.
7. **Run the copy hunt over the same merges**, as `handbook/specs/development-workflow.md` says
   (Sweeps the per-sub recon does not reach), and file what that paragraph says to file.
8. **Open the pull request, if anything was cut**, titled `Comment sweep <date>: ` and what it
   cut, its body in the shape `.github/PULL_REQUEST_TEMPLATE.md` gives, carrying the ledger and what
   steps 5 and 6 printed. It has no issue, so its closing-reference line reads `No issue:` and the
   reason, as the template's own note says, its body carries the calls made
   (`handbook/specs/development-workflow.md` step 12), and the cold review follows as for any pull
   request (step 14). When a feature pull request collides with it, the feature merges first; then
   `git merge origin/main` on the sweep, and step 5 again before it merges (the section's last
   bullet).
9. **Tag the head**, a quiet week's included: `git tag comment-sweep/<date> <head>`, then
   `git push origin comment-sweep/<date>` (the section's first bullet).
```

- **The keeper-scan and copy-hunt steps name no command**: each points at its one home (the keeper-scan bullet, which Issue #1320 rewrites to name `npm run keeper-scan`, and `development-workflow.md`'s paragraph, which names `npm run copy-hunt`), so neither command moving ever moves a line here, which is the issue's proposal 3 ("with no change to the skill's shape"). The other commands are written out because a checklist is read at the keyboard, and each step names the line that owns it.
- **No line names the private store or any file in it** (`test/repo/memory-pointers.test.ts` reads every tracked file under `.claude/skills/`): it says "the weekly sitting", never what else that sitting reviews.
- Every backticked path in it resolves at `fc6d7b03` (`test/repo/prose-paths.test.ts` reads `.claude/skills/`): `handbook/specs/conventions.md`, `handbook/specs/rulebook.md`, `handbook/specs/check-placement.md`, `handbook/specs/development-workflow.md`, `.github/PULL_REQUEST_TEMPLATE.md`.
- The title form `Comment sweep <date>: ` is what the cold review keys on (ruling 1).

## Alternatives rejected

- **Reading the working tree** (the issue's `verify <base>`): the other three commands a sweep runs (`comment-judge diff`, the keeper scan's `diff`, `copy-hunt diff`) read two commits; a commit-to-commit reader is the only one the cold review and the collision rule can use; and the working-tree form needs a second file reader beside `gitTree` and a status reader beside `changedFiles`. The skill commits before step 5.
- **A leaf walk without node kinds** (the spec's words taken literally): blind to automatic semicolon insertion, measured above.
- **`e2e/port-proof.ts`'s `compareSources`**: it compares the JavaScript Node runs, after `stripTypeScriptTypes`, so a dropped type annotation is no change to it, and it reads no sheet or page.
- **`ts.createPrinter({ removeComments: true })` and a text compare** (the normaliser PR #548's skeptic built): it reads no sheet or page, and a compare of two printed texts names no line of either source file.
- **Dropping every CSS whitespace token**: it reads `.a .b` and `.a.b` as the same selector (measured, `cssnospace`).
- **A GitHub check that verifies a sweep's pull request**: declined by ruling 1. It would have been a second exception to Alex's rule that a pull request runs exactly what `main` runs (Issue #1306 comment 6784417882), keyed off the pull request's title, which `test/repo/docs-only.test.ts` refuses.
- **A hand-written page reader, or not reading pages**: declined by ruling 3.
- **Reading a short list of tool-instruction comments as code**: declined by ruling 4, which accepts them as a blind spot the pull request's own type check, lint and format check cover.
- **A second lister of deleted paths here**: Issue #1320's `deletedFiles` is the same `git diff --name-only --diff-filter=D`; one copy (Alex, Issue #1319 comment 6792494044, one home for what the commands share), and the copy hunt the cold review runs would report a second.
- **An `isJsDoc` helper**: `e2e/port-proof.ts` holds one with exactly that body, which the copy hunt lists under "Exact copies, found by code"; the range check is written inline in the walk instead.
- **Making a quiet week open a pull request, or tagging only after the sweep merges**: both contradict the section's first bullet (Alex, 2026-11-10).
- **Naming the skill in `CLAUDE.md`'s handoff line**: that line points at the spec, and the spec names the skill; one hop, no second copy.

- **`scripts/comment-sweep/tokens.ts`**, exactly:

  ```ts
  import { tokenize, tokenTypes } from "@eslint/css-tree";
  import ts from "typescript";

  export type Token = { readonly text: string; readonly line: number };

  export const lineFinder = (text: string): ((offset: number) => number) => {
    const source = ts.createSourceMapSource("", text);
    return (offset) => source.getLineAndCharacterOfPosition(offset).line + 1;
  };

  export const scriptKindOf = (path: string): ts.ScriptKind =>
    path.endsWith(".tsx") ? ts.ScriptKind.TSX : /\.[mc]?js$/.test(path) ? ts.ScriptKind.JS : ts.ScriptKind.TS;

  export const scriptTokens = (path: string, text: string): Token[] => {
    const file = ts.createSourceFile(path, text, ts.ScriptTarget.Latest, true, scriptKindOf(path));
    const out: Token[] = [];
    const walk = (node: ts.Node): void => {
      if (node.kind >= ts.SyntaxKind.FirstJSDocNode && node.kind <= ts.SyntaxKind.LastJSDocNode) return;
      const line = file.getLineAndCharacterOfPosition(node.getStart(file)).line + 1;
      out.push({ text: String(ts.SyntaxKind[node.kind]), line });
      const children = node.getChildren(file);
      if (children.length === 0) out.push({ text: node.getText(file), line });
      for (const child of children) walk(child);
    };
    walk(file);
    return out;
  };

  export const sheetTokens = (css: string, lineOf: (offset: number) => number): Token[] => {
    const out: Token[] = [];
    let spaced = false;
    tokenize(css, (type, start, end) => {
      if (type === tokenTypes["Comment"]) return;
      if (type === tokenTypes["WhiteSpace"]) {
        spaced = true;
        return;
      }
      if (spaced && out.length > 0) out.push({ text: " ", line: lineOf(start) });
      spaced = false;
      out.push({ text: css.slice(start, end), line: lineOf(start) });
    });
    return out;
  };
  ```

- **`scripts/comment-sweep/page-tokens.ts`** (ruling 3), exactly:

  ```ts
  import { parse } from "@astrojs/compiler-rs";
  import { lineFinder, sheetTokens, type Token } from "./tokens.ts";

  type Node = Readonly<Record<string, unknown>>;
  type Run = { readonly text: string; readonly start: number } | { readonly node: Node };

  const isNode = (value: unknown): value is Node => typeof value === "object" && value !== null && !Array.isArray(value);
  const startOf = (node: Node): number => (typeof node["start"] === "number" ? node["start"] : 0);
  const isDropped = (node: Node): boolean =>
    node["type"] === "AstroComment" ||
    (node["type"] === "JSXExpressionContainer" &&
      isNode(node["expression"]) &&
      node["expression"]["type"] === "JSXEmptyExpression");
  const isStyle = (node: Node): boolean =>
    node["type"] === "JSXElement" &&
    isNode(node["openingElement"]) &&
    isNode(node["openingElement"]["name"]) &&
    node["openingElement"]["name"]["name"] === "style";

  const runsOf = (items: readonly unknown[]): Run[] => {
    const runs: Run[] = [];
    for (const item of items) {
      if (!isNode(item) || isDropped(item)) continue;
      const last = runs.at(-1);
      if (item["type"] !== "JSXText") runs.push({ node: item });
      else if (last !== undefined && "text" in last)
        runs[runs.length - 1] = { text: last.text + String(item["value"]), start: last.start };
      else runs.push({ text: String(item["value"]), start: startOf(item) });
    }
    return runs;
  };

  export const pageTokens = (text: string): Token[] => {
    const { ast, diagnostics } = parse(text);
    const lineOf = lineFinder(text);
    const out: Token[] = [];
    const list = (items: readonly unknown[], sheet: boolean): void => {
      const runs = runsOf(items);
      runs.forEach((run, i) => {
        if ("node" in run) visit(run.node);
        else if (sheet) out.push(...sheetTokens(run.text, (offset) => lineOf(run.start + offset)));
        else if (run.text.trim() !== "" || (i !== 0 && i !== runs.length - 1))
          out.push({ text: `text ${JSON.stringify(run.text.replace(/\s+/g, " "))}`, line: lineOf(run.start) });
      });
    };
    const visit = (node: Node): void => {
      const line = lineOf(startOf(node));
      out.push({ text: String(node["type"]), line });
      for (const [key, value] of Object.entries(node)) {
        if (key === "type" || key === "start" || key === "end") continue;
        if ((key === "comments" && node["type"] === "AstroRoot") || (key === "raw" && node["type"] === "JSXText"))
          continue;
        if (Array.isArray(value)) {
          out.push({ text: `${key}:`, line });
          const primitives = value.filter((item) => !isNode(item));
          if (primitives.length > 0) out.push({ text: JSON.stringify(primitives), line });
          list(value, key === "children" && isStyle(node));
        } else if (isNode(value)) {
          out.push({ text: `${key}:`, line });
          visit(value);
        } else out.push({ text: `${key}=${JSON.stringify(value)}`, line });
      }
    };
    visit(ast);
    for (const d of diagnostics) out.push({ text: `diagnostic ${d.severity} ${d.text}`, line: d.labels[0]?.line ?? 1 });
    return out;
  };
  ```

- **`scripts/comment-sweep/verify.ts`**, exactly (a path's text is read only once its reader is known not to be `null`):

  ```ts
  import type { Changed, Tree } from "../comment-judge/tree.ts";
  import { isDoc } from "../docs-only.ts";
  import { pageTokens } from "./page-tokens.ts";
  import { lineFinder, scriptTokens, sheetTokens, type Token } from "./tokens.ts";

  export type Excerpt = { readonly line: number; readonly text: string };
  export type Difference = { readonly base: Excerpt | null; readonly head: Excerpt | null };
  export type Finding =
    | { readonly kind: "identical" | "added" | "deleted" | "not read" | "prose"; readonly path: string }
    | { readonly kind: "renamed"; readonly path: string; readonly before: string }
    | { readonly kind: "differs"; readonly path: string; readonly difference: Difference };

  export const readerOf = (path: string): ((text: string) => Token[]) | null => {
    if (/\.(?:[mc]?ts|tsx|[mc]?js)$/.test(path)) return (text) => scriptTokens(path, text);
    if (path.endsWith(".css")) return (text) => sheetTokens(text, lineFinder(text));
    if (path.endsWith(".astro")) return pageTokens;
    return null;
  };

  const excerptOf = (token: Token | undefined, at: number): Excerpt | null =>
    token === undefined
      ? null
      : {
          line: token.line + (token.text.slice(0, at).match(/\n/g)?.length ?? 0),
          text: token.text.slice(Math.max(0, at - 20), at + 40),
        };

  export const firstDifference = (base: readonly Token[], head: readonly Token[]): Difference | null => {
    for (let i = 0; i < Math.max(base.length, head.length); i += 1) {
      const a = base[i];
      const b = head[i];
      if (a?.text === b?.text) continue;
      let at = 0;
      if (a !== undefined && b !== undefined) while (at < a.text.length && a.text[at] === b.text[at]) at += 1;
      return { base: excerptOf(a, at), head: excerptOf(b, at) };
    }
    return null;
  };

  const findingOf = (c: Changed, before: Tree, after: Tree): Finding => {
    if (isDoc(c.path) && (c.before === null || isDoc(c.before))) return { kind: "prose", path: c.path };
    if (c.before === null) return { kind: "added", path: c.path };
    if (c.before !== c.path) return { kind: "renamed", path: c.path, before: c.before };
    const read = readerOf(c.path);
    if (read === null) return { kind: "not read", path: c.path };
    const difference = firstDifference(read(before.read(c.before)), read(after.read(c.path)));
    return difference === null ? { kind: "identical", path: c.path } : { kind: "differs", path: c.path, difference };
  };

  export const findingsOf = (
    changed: readonly Changed[],
    deleted: readonly string[],
    before: Tree,
    after: Tree,
  ): Finding[] => [
    ...changed.map((c) => findingOf(c, before, after)),
    ...deleted.map((path): Finding => ({ kind: isDoc(path) ? "prose" : "deleted", path })),
  ];
  ```

  ```ts
  export const NOT_READ = "the verifier reads TypeScript, JavaScript, sheets and pages only";

  const side = (excerpt: Excerpt | null): string =>
    excerpt === null ? "the end of the file" : `line ${excerpt.line} ${JSON.stringify(excerpt.text)}`;

    }
  };

  export const reportLines = (findings: readonly Finding[], from: string, head: string): string[] => {
    const count = (kind: Finding["kind"]): number => findings.filter((f) => f.kind === kind).length;

      `comment-sweep verify, read from ${from} to ${head}`,
      ...findings.flatMap((f) => findingLine(f) ?? []),

    ];
  };

    findings.every((f) => f.kind === "identical" || f.kind === "prose") ? 0 : 1;
  ```
