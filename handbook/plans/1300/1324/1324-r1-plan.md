## The design

### Ruling 1: a list's items in their places

At `45fb550a`, `visit` in `scripts/comment-sweep/page-tokens.ts` pushes one token, `JSON.stringify(primitives)`, holding every non-node item of an array, and `runsOf` skips those items, so where a hole stands among the nodes is lost. Measured at the head (`out/1324-r1-dry-run/stages.log`, stage A): the row "an array hole moved" (`const [, a, b] = x` against `const [a, , b] = x`) reads as no change.

The fix: `runsOf` turns each non-node item into a run of its own, `{ value: item }`, where it stands; `list` takes the owning node's line and pushes `{ text: JSON.stringify(run.value), line }` for such a run; the `primitives` push in `visit` is deleted. A hole has no position of its own in the parser's tree, so its token carries its owner's line.

The script reader needs nothing: TypeScript gives a hole as an `OmittedExpression` node, which the walk already pushes in place (the recon's caveat, folded: "the way the script reader does" means in place, not by the same mechanism).

The second row, "an array hole dropped" (`{[1, , 2]}` against `{[1, 2]}`), PASSES at the head, since the gathered `[null]` token already differs when one side has no hole; it is pinned here because the fix must keep it, and its proof is the mutation that skips a non-node run, which reds both rows (`mutations.log`, `hole-skipped`). This settles the guard prover's third survivor, the primitive-array push.

### Ruling 2: instruction comments read as code

**The roster.** `scripts/comment-sweep/instructions.ts` exports the type `Instruction`, `{ readonly name: string; readonly reads: RegExp }`, the roster `INSTRUCTION_COMMENTS: readonly Instruction[]`, and `isInstruction(comment: string): boolean`, true when any entry's `reads` matches the comment's whole source text, its delimiters included (`//`, `///`, `/* */`, `/** */`, `<!-- -->`, or the shebang line). `grep` over `scripts/`, `src/`, `test-support/`, `e2e/` and `eslint.config.ts` finds no matcher of these comments to import (only `test/repo/ts-comment-form.test.ts`, a test, holds its own), so this is the one home.

**Each entry reads its comment the way the tool that obeys it reads it**, taken from that tool's own source in the installed `node_modules` or measured by running it (`out/1324-r1-dry-run/tool-readings.log`, `ts-pragmas.log`, `bundler-comments.log`):

| entry | the tool | what it reads as the instruction |
|---|---|---|
| `@ts-` | TypeScript | a `//` or `///` comment opening `@ts-` after spaces; a block comment whose LAST line opens, after spaces, slashes and stars, with `@ts-expect-error` or `@ts-ignore` (`commentDirectiveRegExSingleLine`, `commentDirectiveRegExMultiLine` and `singleLinePragmaRegEx` in `typescript/lib/typescript.js`; measured: `/* @ts-expect-error\n */` silences nothing, `/*\n * why\n * @ts-expect-error */` does) |
| `eslint-disable` | ESLint | a block comment opening, after spaces, `eslint-disable`, `eslint-disable-line` or `eslint-disable-next-line` then a space or its close; a line comment opening `eslint-disable-line` or `eslint-disable-next-line` (`directivesPattern` in `eslint/lib/shared/directives.js`, and `getInlineConfigNodes` in `eslint/lib/languages/js/source-code/source-code.js`, which reads only those two in a line comment) |
| `eslint-enable`, `eslint-env`, `eslint`, `exported`, `global`, `globals` | ESLint | a block comment opening, after spaces, the word then a space or its close; never a line comment, and never a `/**` block, whose trimmed value opens with a star (same two files) |
| `prettier-ignore` | Prettier | a `//`, `/* */` or `<!-- -->` comment whose whole text inside its delimiters, trimmed, is `prettier-ignore` (`value.trim() === "prettier-ignore"` in `prettier/plugins/estree.js`, and the same test in its postcss and html plugins) |
| `@__PURE__`, `#__PURE__` | rolldown (the bundler Vite 8 runs) | a `//` or `/*` comment opening the word after spaces; never `/**`, never mid-comment (measured: `/* @__PURE__ */`, `// @__PURE__`, `/*#__PURE__*/` and `// #__PURE__` drop the unused call; `/** @__PURE__ */` and `/* a note @__PURE__ */` do not) |
| `@vite-ignore` | Vite | a block comment whose whole body, between spaces, is `@vite-ignore` (`hasViteIgnoreRE` in `vite/dist/node/chunks/node.js`) |
| `/// <reference` | TypeScript | a `///` comment opening `<reference` after spaces, a space after it and `/>` at its end, in any case (`tripleSlashXMLCommentStartRegEx`, whose name it lowercases) |
| `#!` | the shell and Node | the file's first line, read through `ts.getShebang` |
| `/*!` | rolldown | a comment opening `/*!`, `/**!` or `//!` (measured: each is kept in the bundle; `/* !`, spaced, is not) |
| `@jsx`, `@jsxImportSource`, `@jsxFrag` | TypeScript | a block comment holding the pragma anywhere, in any case, followed by a space or a line break (`commentPragmas` and the multi-line pragma reader in `extractPragmas`; measured: `// @jsx h` carries no pragma, `/** doc @jsx h */` and `/** @JSX h */` do, and `@jsx*/` does not) |
| `@type` | TypeScript, in a JavaScript file | a `/**` comment holding `@type` after a space or a star and before a character that cannot continue a name (measured: `/** The width @type {number} */` and `/**@type {number}*/` type the declaration; `/* @type */`, `/** a@type */` and `/** @typedef */` do not) |

The nineteen entries are the seven Alex ruled in comment 6799894756, with `eslint-*` read as ESLint reads it, as the two entries `eslint-disable` and `eslint-enable` (eight); the ten his ruling 6800799605 adds (eighteen); and the bare `/* eslint rule: off */` configuration comment the planner named, as `eslint` (nineteen; Calls made 5 and 6). No fixture is read by two entries, so removing one entry from the list reds its own fixture row (`mutations.log`, the nineteen `entry-dropped` mutations): `global` needs a space or the close after the word, so it never reads `/* globals */`, and `@jsx` needs a space after it, so it never reads `@jsxFrag`.

**Why one pattern per entry, not one rule for all**: a rule reading only the text's start, after the opener and any slashes, stars and spaces (the first draft of this revision), misses what TypeScript obeys on a block comment's last line and in a JSDoc block's later line, reads `// global state lives here` as code although ESLint reads `global` only in a block comment, so a sweep could never cut that ordinary comment, and reads `/** @__PURE__ */`, which rolldown ignores.

**What is pushed**: the comment's whole source text, unchanged, so rewording its reason is a change (ruling 2, "removes or edits"). It is pushed where it stands, so moving one past code is a change too:

- **Scripts** (`scriptTokens` in `scripts/comment-sweep/tokens.ts`): for every token (`ts.isToken(node)`) the walk reaches, the comments in its leading trivia are read with `ts.getTrailingCommentRanges(text, pos)` and `ts.getLeadingCommentRanges(text, pos)` at the token's full start, the trailing ones skipped at position 0, and each one `isInstruction` accepts is pushed before the token. A leading read past position 0 collects nothing before the first line break and a trailing read stops at it, so the two split the trivia with no comment read twice (`mutations.log`, `script-trailing-at-0`, which double-reads at position 0 and reds a quiet row). `ts.getLeadingCommentRanges` skips a shebang, so `ts.getShebang(text)` is read once, first. Comments are trivia, never inside a regular expression or a template, so the two regular-expression quiet rows stay quiet (both green under every revision run). The JSDoc kind range is still skipped as syntax; a JSDoc block's text is trivia of the token after it, so one the list reads (`@type`, a `@jsx` pragma) is read like any other comment.
- **Sheets** (`sheetTokens`): a Comment token that `isInstruction` accepts is kept as an ordinary token; every other Comment token is still dropped. A `<style>` element's text in a page goes through the same function.
- **Pages** (`pageTokens` in `scripts/comment-sweep/page-tokens.ts`): an `AstroComment` (`<!-- -->`) whose `<!--value-->` text `isInstruction` accepts is no longer dropped, so `visit` pushes it as a node in place. The root's `comments` list (frontmatter, `<script>` and `{/* */}` comments, all at page offsets) is read once: each comment's source text (`text.slice(start, end)`) that `isInstruction` accepts is held, in the list's order, and `visit` pushes every held comment that starts before the node it is about to push, so each lands just before the first node after it; any left over are pushed at the end. The parser lists these comments in source order: measured over all 26 tracked pages (32 comments, 0 out of order) and a fixture mixing frontmatter, markup expressions and two scripts (`out/1324-r1-dry-run/page-comment-order.log`), so no sort is written. An empty-expression container (`{/* */}`) is still dropped; its comment reaches the stream through the root list.

**Measured on the whole tree at `45fb550a`** (`out/1324-r1-dry-run/instr-survey.log`): of the 1,514 tracked files the verifier reads, the revised readers push 17 instruction comments: the four `/*!` legal comments (the first line of each of `src/prospect/letter/face-caps.ts`, `face-italic.ts` and `face-roman.ts`, which `test/prospect/plate-face.test.ts` also holds, and the vendored `design/atelier-map/gsap.min.js`), the three `// eslint-disable-line` (`src/site/explorer/chart-drawer-bind.ts`, `src/site/shared/room.ts`, `test/atlas/document.test.ts`), the nine `// @ts-expect-error` in `test/repo/e2e-read-types.test.ts` and `/* eslint-disable max-lines */` in `test/site/astro-scaffold.test.ts`. Removing each one reads as a change under the revised readers, 17 of 17, and under the head's, 0 of 17. The fourth `/*!` in the tree, in `scripts/plate-face.ts`, is template text, which reads as a change by construction.

### Ruling 2: a type change

`changedFiles` reads `--diff-filter=AMR` and `deletedFiles` reads `--diff-filter=D` in `scripts/comment-judge/tree.ts`, so a `T` is in neither. `changedFiles` is read by `scripts/comment-judge/main.ts`, `scripts/copy-hunt/runs.ts` and `scripts/keeper-scan/main.ts` as well, so it is not widened. `deletedFiles`' body becomes a private `pathsWith(repo, from, head, filter: "D" | "T")`, and `deletedFiles` and a new `typeChangedFiles` each call it, so no second lister is written (one home, Issue #1319 comment 6792494044) and `deletedFiles`' signature and its test stand. `findingsOf` takes the type-changed paths third; each is `prose` where `isDoc` accepts it, as a deleted path is, and `type changed` otherwise. `reportLines` prints `TYPE CHANGED <path>` and counts `type changed <t>` on the summary line directly after `renamed`; `exitOf` fails it like every kind but `identical` and `prose`, unchanged.

**What moves**: the summary line's text, in every reading, gains `, type changed <t>` after `renamed <r>`. No acceptance reading's verdict, count or other line moves (Evidence 3): none of the four swept ranges adds or removes a line holding a comment the list reads, and none holds a type change (`out/1324-r1-dry-run/ranges.log`). The tree holds one tracked symbolic link, `AGENTS.md`, which is prose.

### The blind spots, as revised

Each errs toward passing: pure reindentation; in a page, a whitespace run read as one space and a whitespace-only run at the edge of an element's content not read (ruling 4's second, standing); and a comment that instructs a tool in a form `INSTRUCTION_COMMENTS` does not read, read as a comment. The forms known and not on the list: `@license` and `@preserve` legal comments, which rolldown keeps wherever they stand in a comment (`bundler-comments.log`); `@jsxRuntime`; `prettier-ignore-attribute`, `prettier-ignore-start` and `prettier-ignore-end`; the JSDoc type tags other than `@type` (`@param {T}`, `@returns {T}`, `@typedef`, `@satisfies`, `@template`); `@__NO_SIDE_EFFECTS__`; `//# sourceMappingURL`; `c8 ignore` and `istanbul ignore`; `/* webpackIgnore */`. A text scan of the tree at `45fb550a` finds none of them but one `@license`, inside the `/*!` block of `design/atelier-map/gsap.min.js`, which the `/*!` entry reads (`out/1324-r1-dry-run/unlisted.log`). In a page, an instruction comment moved within one text run, with no node between its two places, reads as no change, since it lands before the same node either way.

An entry that reads more than its tool obeys errs the other way, toward reporting, a removal that changes nothing: `@ts-` reads any `@ts-` word in a line comment, where TypeScript obeys four; and every pattern runs in every reader, so in a sheet `eslint-env`, `exported`, `global` and `globals` are read too, though ESLint's CSS language obeys only `eslint`, `eslint-enable` and the `eslint-disable` forms (`INLINE_CONFIG` in `@eslint/css/dist/languages/css-source-code.js`). No sheet in the tree at `45fb550a` holds such a comment (`instr-survey.log`).

## Alternatives rejected

- **Widening `changedFiles` to `AMRT`**: three other commands read it, and each would then read a link's target as a file's text.
- **A second lister beside `deletedFiles`**: the same `git diff --name-only` with another filter; the copy hunt the cold review runs would name it.
- **Reading every page comment from the root list at the end, not in place**: a comment moved past code would read as no change; in place costs one call in `visit` (`mutations.log`, `page-flush-at-end` reds the moved row).
- **A sort of the page's comments, and a flush before each text run**: neither has a reading that differs (the parser's order is source order, measured; a move within one text run passes no code), so each would be code no test reds.
- **One rule for every entry, a listed word at the start of the comment's text**: it misses what TypeScript obeys on a block comment's last line and in a JSDoc block's later line, and reads as code an ordinary `// global ...` comment ESLint ignores (The design).
- **Matching a listed word anywhere in a comment**: a comment that mentions a directive mid-sentence would read as code.
- **Normalising whitespace inside an instruction comment**: a scanner errs toward reporting, and a sweep reindents no comment.
- **`ts.createScanner` over each token's trivia**: the comment-range functions are TypeScript's API for exactly this read, and the spec forbids building the verifier on the scanner.
- **Keeping `eslint-*` as one prefix entry beside `eslint-env`**: the prefix reads `eslint-env` too, so removing the `eslint-env` entry would red nothing but the coverage test, and it reads any comment opening an `eslint-` word ESLint ignores.

- **`scripts/comment-sweep/tokens.ts`** (edited), exactly:

  ```ts
  import { tokenize, tokenTypes } from "@eslint/css-tree";
  import ts from "typescript";
  import { isInstruction } from "./instructions.ts";

  export type Token = { readonly text: string; readonly line: number };

  export const lineFinder = (text: string): ((offset: number) => number) => {
    const source = ts.createSourceMapSource("", text);
    return (offset) => source.getLineAndCharacterOfPosition(offset).line + 1;
  };

  export const scriptKindOf = (path: string): ts.ScriptKind =>
    path.endsWith(".tsx") ? ts.ScriptKind.TSX : /\.[mc]?js$/.test(path) ? ts.ScriptKind.JS : ts.ScriptKind.TS;

  const commentsBefore = (text: string, pos: number): readonly ts.CommentRange[] => [
    ...(pos === 0 ? [] : (ts.getTrailingCommentRanges(text, pos) ?? [])),
    ...(ts.getLeadingCommentRanges(text, pos) ?? []),
  ];

  export const scriptTokens = (path: string, text: string): Token[] => {
    const file = ts.createSourceFile(path, text, ts.ScriptTarget.Latest, true, scriptKindOf(path));
    const lineAt = (pos: number): number => file.getLineAndCharacterOfPosition(pos).line + 1;
    const shebang = ts.getShebang(text);
    const out: Token[] = shebang !== undefined && isInstruction(shebang) ? [{ text: shebang, line: 1 }] : [];
    const walk = (node: ts.Node): void => {
      if (node.kind >= ts.SyntaxKind.FirstJSDocNode && node.kind <= ts.SyntaxKind.LastJSDocNode) return;
      if (ts.isToken(node))
        for (const range of commentsBefore(text, node.getFullStart())) {
          const comment = text.slice(range.pos, range.end);
          if (isInstruction(comment)) out.push({ text: comment, line: lineAt(range.pos) });
        }
      const line = lineAt(node.getStart(file));
      out.push({ text: String(ts.SyntaxKind[node.kind]), line });
      const children = node.getChildren(file);
      if (children.length === 0) out.push({ text: node.getText(file), line });
      for (const child of children) walk(child);
    };
    walk(file);
    return out;
  };

  export const sheetTokens = (css: string, lineOf: (offset: number) => number): Token[] => {
    const out: Token[] = [];
    let spaced = false;
    tokenize(css, (type, start, end) => {
      if (type === tokenTypes["Comment"] && !isInstruction(css.slice(start, end))) return;
      if (type === tokenTypes["WhiteSpace"]) {
        spaced = true;
        return;
      }
      if (spaced && out.length > 0) out.push({ text: " ", line: lineOf(start) });
      spaced = false;
      out.push({ text: css.slice(start, end), line: lineOf(start) });
    });
    return out;
  };
  ```

  ```ts
  import { parse } from "@astrojs/compiler-rs";
  import { isInstruction } from "./instructions.ts";
  import { lineFinder, sheetTokens, type Token } from "./tokens.ts";

  type Node = Readonly<Record<string, unknown>>;
  type Run = { readonly text: string; readonly start: number } | { readonly node: Node } | { readonly value: unknown };

  const isNode = (value: unknown): value is Node => typeof value === "object" && value !== null && !Array.isArray(value);
  const startOf = (node: Node): number => (typeof node["start"] === "number" ? node["start"] : 0);
  const isDropped = (node: Node): boolean =>
    (node["type"] === "AstroComment" && !isInstruction(`<!--${String(node["value"])}-->`)) ||
    (node["type"] === "JSXExpressionContainer" &&
      isNode(node["expression"]) &&
      node["expression"]["type"] === "JSXEmptyExpression");
  const isStyle = (node: Node): boolean =>
    node["type"] === "JSXElement" &&
    isNode(node["openingElement"]) &&
    isNode(node["openingElement"]["name"]) &&
    node["openingElement"]["name"]["name"] === "style";
  const commentText = (comment: Node, text: string): string =>
    text.slice(startOf(comment), typeof comment["end"] === "number" ? comment["end"] : startOf(comment));

  const runsOf = (items: readonly unknown[]): Run[] => {
    const runs: Run[] = [];
    for (const item of items) {
      if (isNode(item) && isDropped(item)) continue;
      const last = runs.at(-1);
      if (!isNode(item)) runs.push({ value: item });
      else if (item["type"] !== "JSXText") runs.push({ node: item });
      else if (last !== undefined && "text" in last)
        runs[runs.length - 1] = { text: last.text + String(item["value"]), start: last.start };
      else runs.push({ text: String(item["value"]), start: startOf(item) });
    }
    return runs;
  };

  export const pageTokens = (text: string): Token[] => {
    const { ast, diagnostics } = parse(text);
    const root: Node = ast;
    const lineOf = lineFinder(text);
    const out: Token[] = [];
    const instructions = (Array.isArray(root["comments"]) ? root["comments"] : [])
      .filter(isNode)
      .map((comment) => ({ start: startOf(comment), text: commentText(comment, text) }))
      .filter((comment) => isInstruction(comment.text));
    let next = 0;
    const flush = (before: number): void => {
      for (; next < instructions.length && instructions[next]!.start < before; next += 1)
        out.push({ text: instructions[next]!.text, line: lineOf(instructions[next]!.start) });
    };
    const list = (items: readonly unknown[], sheet: boolean, line: number): void => {
      const runs = runsOf(items);
      runs.forEach((run, i) => {
        if ("node" in run) visit(run.node);
        else if ("value" in run) out.push({ text: JSON.stringify(run.value), line });
        else if (sheet) out.push(...sheetTokens(run.text, (offset) => lineOf(run.start + offset)));
        else if (run.text.trim() !== "" || (i !== 0 && i !== runs.length - 1))
          out.push({ text: `text ${JSON.stringify(run.text.replace(/\s+/g, " "))}`, line: lineOf(run.start) });
      });
    };
    const visit = (node: Node): void => {
      flush(startOf(node));
      const line = lineOf(startOf(node));
      out.push({ text: String(node["type"]), line });
      for (const [key, value] of Object.entries(node)) {
        if (key === "type" || key === "start" || key === "end") continue;
        if ((key === "comments" && node["type"] === "AstroRoot") || (key === "raw" && node["type"] === "JSXText"))
          continue;
        if (Array.isArray(value)) {
          out.push({ text: `${key}:`, line });
          list(value, key === "children" && isStyle(node), line);
        } else if (isNode(value)) {
          out.push({ text: `${key}:`, line });
          visit(value);
        } else out.push({ text: `${key}=${JSON.stringify(value)}`, line });
      }
    };
    visit(root);
    flush(Infinity);
    for (const d of diagnostics) out.push({ text: `diagnostic ${d.severity} ${d.text}`, line: d.labels[0]?.line ?? 1 });
    return out;
  };
  ```
