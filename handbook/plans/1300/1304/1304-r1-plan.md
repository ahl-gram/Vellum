## The design changes

### 1. The key never reaches a reason (`scripts/jev/system-one.ts`; ruling 1)

Measured (Measured item 1): Node's `fetch` rejects a header value holding a line feed, a carriage return or a NUL
with the message `Headers.append: "Bearer <the whole key>" is an invalid header value.`, and `ask` at `8b66eef2`
returns that message as the reason, which reaches the printed report and `replies.jsonl`. A character above 0xFF
gives a message naming only its index; a trailing line break is stripped by `fetch` and sent. Three changes, each
closing one path:

- **`senderFor` refuses a key it would not send safely**, before any request: the key, trimmed, must match
  `KEY_SHAPE`, the visible ASCII characters other than `"` and `\`. A key that fails resolves every request with
  `KEY_REFUSED` and calls nothing. A key that passes is sent trimmed.
- **A rejected fetch is reported by fixed words only**: `the request got no answer: <name>` and, when the error's
  cause carries a code, ` (<code>)`. `<name>` is the error's `name` when it is letters only, otherwise `error`;
  `<code>` is the cause's `code` when it is capitals, digits and underscores only. Never the message. Measured:
  a timeout gives `TimeoutError`, a refused connection `TypeError (ECONNREFUSED)`, an unknown host
  `TypeError (ENOTFOUND)`, so the reason says more than today's `fetch failed` and carries no data.
- **An error body is kept with the key cut out**: `HTTP <status>: <the body with every exact occurrence of the key
  replaced by <TYPESAFE_API_KEY>, then its first 200 characters>`. The key is replaced before the cut, so a body
  that ends mid-key cannot keep its first characters. The status check is `response.ok`.

What stays unguarded, as ruled: the key echoed in an altered form (escaped or encoded). `KEY_SHAPE` refusing `"`
and `\`, the two characters a JSON body escapes, makes that less likely.

Rejected: **a reason built from the message with the key replaced** (the message carries nothing a planner needs
that the class and code do not); **refusing the key inside `ask`** (the fixed rejection reason already keeps a
malformed key out of every reason, and `senderFor` is the one place the environment's key enters); **a scrub of
every reason `ask` returns** (measured in the probe as a guard no test can make red: no other reason is built from
data that could hold the key, so it is deleted rather than shipped, `CLAUDE.md` Process).

### 2. The trailing-comment defect is written down, not fixed (ruling 2)

`scripts/comment-judge/candidates.ts` is not edited. At `8b66eef2` a run in a test file outside every test call
takes the names declared by the first top-level statement whose end is after the run's start, so
`const big = 10; // ten is big` followed by `const small = 1;` is asked about the tests that use `small` (measured
at `8b66eef2` before the ruling: the candidates were `uses small`), and a comment whose next statement is another
test call is asked about no test. None of the 49 trial rows is such a comment (every trailing
row is under `src/`), so the trial does not move. The defect becomes the row in Files,
`handbook/errata/guards.md`, for the pull request that places the check.

### 3. The score's first line (`scripts/comment-judge/trial.ts`)

`<n> comments; answered by <models or none>; <b> requests built, <a> answered, <f> not answered; <t> input tokens reported, <s> seconds`,
`b` every request built, `a` the `Answered` replies, `f` the other replies. A dry run of the trial writes
`49 comments; answered by none; 50 requests built, 0 answered, 49 not answered; 0 input tokens reported, 0.0 seconds`.
Every number is true in a dry run and a live one.

### 4. The test-file listing reads from the tree's root (`scripts/comment-judge/tree.ts`)

`git ls-tree` reads its path relative to the directory it runs in, so `gitTree(repo, sha).list("test")` run from a
subdirectory lists nothing and every comment outside a test silently loses its candidates. Measured (item 6): the
trial's dry run from `scripts/` printed `49 comments, 49 requests, 70 questions, 64068 characters`; with
`--full-tree`, the same as from the root. `npm run` always runs at the package root, so Alex's command was never
exposed; the flag makes the listing independent of where the command runs.

### `scripts/jev/system-one.ts` (edited)

New exports, beside the existing ones (whose types and signatures do not change):

```ts
export const KEY_SHAPE = /^[!#-[\]-~]+$/;
export const KEY_MASK = `<${KEY_VAR}>`;
export const KEY_REFUSED = `${KEY_VAR} holds a character a request header cannot carry, so nothing was sent`;
```

Local helpers, placed after `readAnswers`:

```ts
const hide = (text: string, key: string): string => (key === "" ? text : text.split(key).join(KEY_MASK));
const word = (value: unknown, shape: RegExp): string | null =>
  typeof value === "string" && shape.test(value) ? value : null;
const noAnswer = (error: unknown): string => {
  const e = (typeof error === "object" && error !== null ? error : {}) as {
    name?: unknown;
    cause?: { code?: unknown };
  };
  const name = word(e.name, /^[A-Za-z]+$/) ?? "error";
  const code = word(e.cause?.code, /^[A-Z0-9_]+$/);
  return `the request got no answer: ${name}${code === null ? "" : ` (${code})`}`;
};
```

In `ask`: the `try` keeps `ok = response.ok` beside `status` and `text` (`let ok: boolean;` declared with them);
the `catch` returns `fail(noAnswer(error))`; the status line becomes
`if (!ok) return fail(`HTTP ${status}: ${hide(text, key).slice(0, 200)}`);`. Nothing else in `ask` changes.

`senderFor` becomes:

```ts
export const senderFor = (key: string | undefined, fetcher: Fetch): Send => {
  const trimmed = key?.trim() ?? "";
  if (trimmed === "") return () => Promise.resolve(fail(`${KEY_VAR} is not set`));
  if (!KEY_SHAPE.test(trimmed)) return () => Promise.resolve(fail(KEY_REFUSED));
  return (request) => ask(request, trimmed, fetcher);
};
```

These texts are given whole because the self-proof's rows find them; `npm run format` leaves them as written
(measured on the probe copy).
