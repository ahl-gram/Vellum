## What this is

of yes-or-no question about it, and code turns the answers into one outcome per comment: a finding
that names the pinning test, clear, unsettled, or skipped. The pull request builds that pass as a
command, `npm run comment-judge`, builds its trial over 49 comments two past comment sweeps already
ruled on, and runs the trial's dry run (every request built and written to a file, nothing sent).

## The design

**Code finds, Jev judges, code decides**, as the issue proposes, with three of its parts measured and
two changed (Calls made 1 and 6).

1. **The comments.** `npm run comment-judge -- diff <base> <head>` reads every TypeScript file under
   the lint's roots (`lintTsRoots()` in `test-support/lint-roots.ts`: `e2e`, `scripts`, `src`, `test`,
   `test-support`) that the diff from `git merge-base <base> <head>` to `<head>` adds, modifies or
   renames, parses it with ESLint's `Linter` and the `typescript-eslint` parser, and takes its
   comments from `getAllComments()`. Comments join into runs exactly as the citation rule joins them
   (`runs` in `scripts/lint/comment-notes.ts`, moved from `scripts/lint/comment-citation.ts`). A run
   is added when no run in the file's earlier text carries the same text, so a comment moved
   unchanged is not added. Everything is read from git objects at the two commits, never from the
   working tree, so nothing untracked can reach a request.
2. **The code beside each run** (`code` in the state). A trailing run (one that starts after code on
   its line) takes the code on its own line. An own-line run takes the code under it: the lines after
   its last line, with every comment blanked out, leading blank lines skipped, stopping at the next
   blank line, at most 5 lines, each trimmed at its end.
3. **The candidate tests**, a unit test being a top-level `test(...)` call in a `test/**/*.test.ts`
   file:
   - a run inside a test call has that test alone;
   - a run in a test file outside every test call has the file's tests whose body names a name the
     next top-level statement declares;
   - a run in any other file has every test, in a test file that imports the run's file by a relative
     non-type import, whose body names a binding that file imports from it (type-only imports and
     specifiers do not count).
   A test's body is sent with its comments removed, so no comment inside it answers the question.
4. **The questions**, all Nouls, one request per run unless its questions outgrow the request bound:
   `restates` ("Does `comment` only restate what `code` already shows?") and one `pins_<i>` per
   candidate, its test in its own question as structured instructions (`primitives/advanced.md`). The
   wording is frozen in `scripts/comment-judge/questions.ts` and never fitted to the trial.
5. **The decision**, the issue's truth table, in code:

   | answers | outcome |
   |---|---|
   | any `pins_<i>` above 0.7, or `restates` above 0.7 | `finding`, naming each test above 0.7 |
   | every answer below 0.3 | `clear` |
   | anything else | `unsettled` |
   | any request for the run failed | `skipped`, with the failure's reason |

   "Above" and "below" are strict: an answer of exactly 0.7 or 0.3 is unsettled.
6. **The report**: one line per run, then a summary line. A skipped run is printed as `SKIPPED` with
   its reason, and the summary says a skipped comment claims no finding. The exit code is 0 when no
   run was skipped (or the run was a dry run), 1 when any was, 2 on a usage error. A finding never
   changes the exit code: the pass is advisory.
7. **The trial**: `npm run comment-judge -- trial --out <dir>` judges the 49 trial rows (below) the
   same way, each at its own commit, and writes `trial.md` (the score), `requests.jsonl` (every
   request as built), `replies.jsonl` (every reply) and `notes.md` (so `npm run delivery` gives the
   folder its page). `--dry-run` builds and writes everything and sends nothing.
8. **The client** lives apart, in `scripts/jev/system-one.ts`, since Issue #1305 names this
   plumbing as what it reuses: one POST through an injected `fetch`, every requested answer checked,
   a failure returned as a failure, never as an answer. No SDK (Calls made 11).

### Rejected, so nobody rediscovers them mid-build

- **The issue's candidate rule, test names that mention the symbol**: measured 2 of 22 (Measured).
- **Tests whose body names the subject symbol only**: 12 of 22, and it misses every private helper.
- **A cap on candidates per comment**: any number would be fitted to nothing; the trial reports the
  counts and whether a finding named the ledger's test.
- **The SDK**: it adds a dependency every lane's linked install would have to mirror, for retries the
  pass does not want (a failure is a skip) and types four lines declare.
- **Sheets** (`@eslint/css`), out of this pull request (Calls made 6).

- **A Choice among the candidate tests**: several tests can pin one comment, and a Choice splits its

### `scripts/jev/system-one.ts` (new)

```ts
export const ENDPOINT = "https://api.typesafe.ai/v1/systemone";
export const MODEL = "jev-1.14.0";
export const KEY_VAR = "TYPESAFE_API_KEY";
export const TIMEOUT_MS = 10_000;
export type NoulQuestion = {
  readonly type: "noul";
  readonly instructions: string | Readonly<Record<string, unknown>>;
  readonly criteria?: { readonly true: string; readonly false: string };
};
export type SystemOneRequest = {
  readonly model: string;
  readonly state: Readonly<Record<string, string>>;
  readonly questions: Readonly<Record<string, NoulQuestion>>;
};
export type Answered = {
  readonly ok: true;
  readonly model: string;
  readonly nouls: Readonly<Record<string, number>>;
  readonly inputTokens: number;
  readonly ms: number;
};
export type Failed = { readonly ok: false; readonly reason: string };
export type Reply = Answered | Failed;
export type Send = (request: SystemOneRequest) => Promise<Reply>;
export type Fetch = (url: string, init: RequestInit) => Promise<Response>;
export const ask = async (request: SystemOneRequest, key: string, fetcher: Fetch): Promise<Reply>
export const senderFor = (key: string | undefined, fetcher: Fetch): Send
export const dryRunSender: Send
```

- `ask` calls `fetcher(ENDPOINT, { method: "POST", headers: { Authorization: "Bearer " + key,
  "Content-Type": "application/json" }, body: JSON.stringify(request), signal:
  AbortSignal.timeout(TIMEOUT_MS) })`, once, with no retry. It returns `Failed` when: the fetch
  rejects (reason: the error's message); the status is not 2xx (reason:
  `HTTP <status>: <the first 200 characters of the body>`); the body is not JSON (reason:
  `the answer is not JSON`); `model` is not a string (reason: `the answer names no model`); or any
  question id in `request.questions` has no `answers[id]` of `type: "noul"` whose `noul` is a finite
  number from 0 to 1 (reason: `the answer to <id> is missing or not a probability`). Otherwise
  `Answered`, `nouls` holding one entry per requested id, `inputTokens` the reply's
  `usage.input_tokens` when it is a number and otherwise `Math.ceil(JSON.stringify(request).length / 2)`,
  `ms` the rounded `performance.now()` difference around the call.
- `senderFor(key, fetcher)`: when `key` is undefined or empty after trimming, a `Send` that resolves
  `{ ok: false, reason: "TYPESAFE_API_KEY is not set" }` without calling `fetcher`; otherwise
  `(request) => ask(request, key, fetcher)`.
- `dryRunSender` resolves `{ ok: false, reason: "dry run: nothing was sent" }`.
- The key is never written to a file, a log line, a reason or a reply.

### `scripts/comment-judge/questions.ts` (new): every word sent, and the thresholds

```ts
import { MODEL, type NoulQuestion, type SystemOneRequest } from "../jev/system-one.ts";
import type { Candidate, CommentRun } from "./types.ts";

export const YES = 0.7;
export const NO = 0.3;
export const MAX_REQUEST_CHARS = 100_000;
export const RESTATES_ID = "restates";
export const pinsId = (index: number): string => `pins_${index}`;
export const RESTATES: NoulQuestion = {
  type: "noul",
  instructions: "Does `comment` only restate what `code` already shows?",
  criteria: {
    true: "`comment` repeats the names, parameters, types or values that `code` shows, and adds nothing of its own.",
    false:
      "`comment` adds something `code` does not show, such as a reason, a constraint, a unit, a measurement or a fact about another part of the system.",
  },
};
export const PINS_QUESTION = "Does `test` check the behavior that `comment` describes?";
export const PINS_CRITERIA = {
  true: "An assertion in `test.body` fails when the code stops behaving the way `comment` says.",
  false:
    "`test.body` runs the same code but asserts something else, so it still passes when the behavior `comment` describes is broken.",
} as const;
export const pinsQuestion = (candidate: Candidate): NoulQuestion
export const stateOf = (run: CommentRun): { readonly comment: string; readonly file: string; readonly code: string }
export const requestsFor = (run: CommentRun, candidates: readonly Candidate[]): SystemOneRequest[]
```

- `pinsQuestion(c)` is `{ type: "noul", instructions: { test: { name: c.name, file: c.file, body: c.body },
  question: PINS_QUESTION }, criteria: PINS_CRITERIA }`, keys in that order.
- `stateOf(run)` is `{ comment: run.text, file: run.file, code: run.code }`, keys in that order.
- `requestsFor`: the first request is `{ model: MODEL, state, questions: { restates: RESTATES } }`;
  each candidate `i`, in order, joins the last request as `pins_<i>` unless that makes
  `JSON.stringify(request).length` exceed `MAX_REQUEST_CHARS`, in which case it starts a new request
  `{ model: MODEL, state, questions: { pins_<i> } }`; a question too large for the bound on its own is
  still sent, alone. Ids run on across requests, so every id is unique for the run.

### `scripts/comment-judge/decide.ts` (new)

```ts
export const decide = (
  answers: { readonly restates: number; readonly pins: readonly number[] },
  candidates: readonly Candidate[],

```

Throws when `pins.length !== candidates.length`. `pinnedBy` is the candidates whose pin is above
`YES`, in candidate order, each with its `noul`. When `pinnedBy` is not empty or `restates > YES`:

### `scripts/comment-judge/tree.ts` (new)

```ts
export type Tree = { readonly sha: string; readonly read: (path: string) => string; readonly list: (prefix: string) => readonly string[] };
export const memoryTree = (sha: string, files: Readonly<Record<string, string>>): Tree
export const gitTree = (repo: string, sha: string): Tree
export type Changed = { readonly path: string; readonly before: string | null };
export const mergeBase = (repo: string, base: string, head: string): string
export const changedFiles = (repo: string, from: string, head: string): Changed[]
export const ensureCommit = (repo: string, sha: string, ref: string): void
```

- `memoryTree`: `read` throws `<path> is not a file at <sha>` for an absent path; `list(prefix)` is the
  sorted paths that start with `<prefix>/`.
- `gitTree`: `read` is `readAt(repo, sha)` from `scripts/proof-runner/send.ts`, reused, never copied;
  `list(prefix)` is `git ls-tree -r --name-only <sha> -- <prefix>`, sorted.
- `mergeBase`: `git merge-base <base> <head>`, trimmed.

  `{ path: <new>, before: <old> }`.
- `ensureCommit`: when `git cat-file -e <sha>^{commit}` fails, runs `git fetch origin <ref>` and checks
  again, and throws `<sha> is not in this clone: run git fetch origin <ref>` if it still fails.
- Every git call is `spawnSync` with `cwd: repo` and a timeout (`GIT_MS = 30_000`, `FETCH_MS = 120_000`),
  and throws naming the command and its stderr on a non-zero exit.

### `scripts/comment-judge/candidates.ts` (new)

```ts
export const isUnitTestFile = (path: string): boolean
export const candidateFinder = (tree: Tree): ((run: CommentRun) => Candidate[])
```

- `isUnitTestFile`: starts with `test/` and ends with `.test.ts`.
- `candidateFinder` parses each file of `tree` at most once (a `Map` it holds) and applies design
  item 3. A test call is a top-level `ExpressionStatement` whose expression is a `CallExpression` with
  callee `Identifier` `test` and a first argument that is a string `Literal` (its name, the value) or a
  `TemplateLiteral` (its name, the source between the backticks). A body "names" a binding when

  and otherwise the statement's `id.name` when that is a string. Test files are `tree.list("test")`
  filtered by `isUnitTestFile`, in sorted order; tests in source order.

### `scripts/comment-judge/judge.ts` (new)

```ts
export const RUN_INPUT_TOKEN_CAP = 2_000_000;
export type Judged = {
  readonly sha: string;
  readonly run: CommentRun;
  readonly candidates: readonly Candidate[];
  readonly requests: readonly SystemOneRequest[];
  readonly replies: readonly Reply[];
  readonly outcome: Outcome;
};
export const judgeRun = async (sha: string, run: CommentRun, candidates: readonly Candidate[], send: Send): Promise<Judged>
export const judgeAll = async (
  items: readonly { readonly tree: Tree; readonly run: CommentRun }[],
  send: Send,
  cap: number,
): Promise<Judged[]>
```

- `judgeRun` sends `requestsFor(run, candidates)` one at a time and stops at the first `Failed`, whose
  reason becomes `{ kind: "skipped", reason }`; when every reply is `Answered`, it merges their `nouls`
  and returns `decide({ restates: nouls.restates, pins: candidates.map((_, i) => nouls[pinsId(i)]) },
  candidates)`. `requests` holds every request built, `replies` every reply received.
- `judgeAll` goes through `items` in order, one `candidateFinder` per tree `sha`, keeping the sum of
  `Answered.inputTokens`; an item reached when that sum is at or over `cap` is not sent and is
  `{ kind: "skipped", reason: "the input-token cap of <cap> for this run was reached" }` with empty
  `candidates`, `requests` and `replies`. The overshoot is at most one run's requests.
