## The design

**Code finds, Jev judges, code decides**, the shape of the two Jev commands already in the house.

1. **The functions.** Every named function at any depth in every `.ts` file under the lint's roots (`lintTsRoots()` in `test-support/lint-roots.ts`: `e2e`, `scripts`, `src`, `test`, `test-support`, read through git at one commit, never the working tree): a function declaration, a `const` arrow or function expression, a class method and an object-literal member, each with its text, comments removed, as the scan read them. The extraction is the scan's `functionsIn` (`/Users/ahl/CodeProjects/Vellum/out/jev-copies/prep.ts`), ported and measured: at the scan's commit 276cb6ae the port found the same 962 files and 6,073 functions with identical bodies and the same 478 pairs at similarity 0.6 or more (`out/1319-dry-run/port.log`). Two changes from the scan: a function over 6,000 characters is kept (the scan dropped it), held to exact copies only and listed as not asked; and a file that does not parse is listed as not read instead of dropped silently.
2. **Similarity.** A function's names are its distinct identifiers of two or more characters outside the scan's list of common words (`tokensOf`), and two functions' similarity is the share of names they hold in common (`jaccard`). A function with fewer than 6 names is never compared (1,986 of 7,722 at main, mostly one-line closures and test fakes).
3. **Exact copies, by code.** Two functions of 6 or more names whose text is the same once comments are removed and white space is collapsed are an exact copy, reported with no call, whatever their similarity rule says. The scan's rule for pairing missed 12 exact groups at 9644dad9 (main before PR #1328) whose names are common (`out/1319-dry-run/counts.log`), so exact copies are grouped by text over every function, not drawn from the similar pairs.
4. **Similar pairs, asked.** Every other pair of comparable functions (6 or more names, 6,000 characters or fewer, neither nested in the other) at similarity 0.6 or more is asked, in both orders, the scan's frozen question: "Do `fn_a` and `fn_b` implement the same logic, so one could replace the other?". Every pair is compared directly, not through the scan's index of rare names, which was a speed device for its 10,000-pair cap: at main it drops 189 of the 522 pairs at 0.6 or more, and Jev read 17 of those 189 as copies (`out/1319-dry-run/extra-live.txt`), at the same rate as the pairs it keeps (23 of 333). A renamed copy (the same layout under other names) is asked like any other pair, never reported on code alone (ruling D1).
5. **The decision**, in code: the mean of both orders above 0.7 is a copy; below 0.3 not a copy; 0.3 to 0.7 unsettled. A failed call, or the run's token cap, makes the pair skipped, never a verdict.
6. **Which functions are hunted.** `diff <base> <head>`: the functions at head, in each `.ts` file under the roots that the diff from the merge base adds, modifies or renames, whose text the same file at the merge base (its old path for a rename) holds fewer times than head does; every pair that has one of them on a side. `full [<sha>]`: every function, every pair. A pure move keeps its text in its new file and is hunted, so a fold that left one copy behind is found.
7. **Accepted copies.** `scripts/copy-hunt/accepted-copies.ts` lists each pair kept on purpose: both sides by file, name and text hash, a reason, and the link to the ruling that keeps it. A listed pair is neither asked nor reported; an entry a side of which no longer matches a function at head is reported, so the entry goes or is renewed. The list starts empty (Calls made 9).
8. **The report** prints the head sha and the merge base, the counts, one line naming what the hunt cannot see (the blind spots, below), then the exact copies, the copies, the unsettled pairs, the skipped pairs, the functions too long to ask, the files not read and the stale accepted entries. The run exits 1 when any pair was skipped (except a dry run): a skipped pair is never "no copy".
9. **The trial**: 24 pairs the scan's blind read checked by hand (23 of its 24, and the `nat` control), re-asked at their own commits; `npm run copy-hunt -- trial --out <dir>` writes the score. A pull request that moves `MODEL` runs it, as the house's rule for every Jev command says.
10. **Where it runs**: `vellum-pr-skeptic` runs `npm run --silent copy-hunt -- diff <base sha> <head sha>` in its own sandbox every round (Alex's ruling). A copy it reports is a finding like any other, weighed at step 15; an unsettled pair is a hypothesis it reads. The weekly sitting that runs the comment sweep runs the same command over the week's merges (ruling D3). A small cloud fix the cloud routine does not cold-review is not hunted (ruling D4).
11. **What Issue #1332 will share**: the deterministic check for word-for-word copies (ruling D2) imports this command's function reader (`functionsAt`, `functionsIn` in `scripts/copy-hunt/functions.ts`), its exact-copy finder (`exactPairs` in `scripts/copy-hunt/pairs.ts`) and its accepted-copies list (`ACCEPTED_COPIES` in `scripts/copy-hunt/accepted-copies.ts`, read through `acceptedFor` and `acceptedFaults` in `scripts/copy-hunt/accepted.ts`). None of those four modules imports anything under `scripts/jev/`, so that check can run them with no key and no network; only `questions.ts`, `hunt.ts`, `runs.ts`, `report.ts`, `trial.ts` and `main.ts` reach the client. Nothing for Issue #1332 itself is built here.

**The blind spots, and the way each errs.** The hunt cannot see: a function with fewer than 6 names; a pair under similarity 0.6; the body of a `test(...)` call or any unnamed callback; a function beside one nested inside it; any file but a `.ts` under the lint's roots (stylesheets, pages, `design/`). A function over 6,000 characters is held to exact copies. Each of these hides a copy and none invents one: every one removes a function or a pair from what is compared, and a pair never compared is never reported. The one way the hunt can report a copy that is not one is Jev's answer above 0.7 on a pair that is not the same logic, which the skeptic confirms by reading both, and an exact copy can be no such error, since its two texts are the same. The report prints the blind spots as its second line every run, so no reader takes an empty report for a clean tree.

- `HUNT_ROOTS = lintTsRoots()`, computed once at module load.
- `isHuntedPath(path)`: `path.endsWith(".ts") && !path.endsWith(".d.ts") && HUNT_ROOTS.includes(path.split("/")[0]!)`.
- `tokensOf`, word for word the scan's (`/Users/ahl/CodeProjects/Vellum/out/jev-quality/extract.ts`), its list of common words `COMMON` copied exactly:

```ts
const COMMON = new Set(
  "const let var function return if else for of in while do new await async true false null undefined typeof instanceof this break continue throw try catch finally switch case default import export from as type interface readonly void number string boolean test it assert equal deepEqual strictEqual deepStrictEqual ok match throws length map filter some every forEach push slice join Math".split(" "),
);
export const tokensOf = (body: string): string[] =>
  [...new Set((body.match(/[A-Za-z_$][\w$]*/g) ?? []).filter((t) => t.length > 1 && !COMMON.has(t)))].sort();
```

- `hashOf(norm)`: `createHash("sha256").update(norm).digest("hex").slice(0, 16)`.
- `functionsIn(path, text)`: `parseTs(path, text)` first (it throws `<path> does not parse: <message>` on a fatal parse error, and the throw is not caught here); then the scan's walk, word for word except the three marked changes:

```ts
export const functionsIn = (path: string, text: string): Fn[] => {
  const comments = parseTs(path, text).comments;
  const sf = ts.createSourceFile(path, text, ts.ScriptTarget.Latest, true, ts.ScriptKind.TS);
  const out: Fn[] = [];
  const push = (name: string, node: ts.Node): void => {
    const start = node.getStart(sf);
    const body = withoutComments(text, start, node.getEnd(), comments).replace(/\n\s*\n/g, "\n");
    const norm = body.replace(/\s+/g, " ").trim();
    out.push({
      file: path,
      line: sf.getLineAndCharacterOfPosition(start).line + 1,
      end: sf.getLineAndCharacterOfPosition(node.getEnd()).line + 1,
      name,
      body,
      norm,
      tokens: tokensOf(body),
      hash: hashOf(norm),
    });
  };
  const visit = (node: ts.Node, owner: string): void => {
    if (ts.isFunctionDeclaration(node) && node.name && node.body) push(node.name.text, node);
    else if (
      ts.isVariableDeclaration(node) &&
      ts.isIdentifier(node.name) &&
      node.initializer &&
      (ts.isArrowFunction(node.initializer) || ts.isFunctionExpression(node.initializer))
    )
      push(node.name.text, node.parent.parent);
    else if (ts.isMethodDeclaration(node) && node.body) push(`${owner}.${node.name.getText(sf)}`, node);
    else if (ts.isPropertyAssignment(node) && (ts.isArrowFunction(node.initializer) || ts.isFunctionExpression(node.initializer)))
      push(`${owner}.${node.name.getText(sf)}`, node);
    const next = ts.isClassDeclaration(node) && node.name ? node.name.text : owner;
    ts.forEachChild(node, (child) => visit(child, next));
  };
  visit(sf, "");
  return out;
};
```

  The changes from the scan: no `MAX_CHARS` drop in `push`; `node.parent.parent` without the scan's `?? node` (with `setParentNodes` true a declaration's grandparent is always set, and `eslint.config.ts` turns on `@typescript-eslint/no-unnecessary-condition`, which refuses a `??` on a type that cannot be nullish); a parse failure throws instead of returning `[]`. The fields `sha` and `shape` the scan carried are not kept.
- `functionsAt(tree)`: for each `root` of `HUNT_ROOTS` in order, each `file` of `tree.list(root)` that `isHuntedPath` passes, in that order: `functionsIn(file, tree.read(file))` pushed onto `fns`; a throw is caught and pushed onto `unread` as `{ file, reason: error instanceof Error ? error.message : String(error) }`.


- `nested(a, b)`: `a.file === b.file && ((a.line <= b.line && b.end <= a.end) || (b.line <= a.line && a.end <= b.end))`.
- `exactPairs`: group the indices of every `fns[i]` with `tokens.length >= MIN_TOKENS` by `norm`, groups in the order of their first index; within a group, every `x < y` (indices) where `hunted(x) || hunted(y)`, as `{ x, y, similarity: 1 }`. Length is not limited.
- `similarPairs`: every `x < y` over the indices whose function has `tokens.length >= MIN_TOKENS` and `body.length <= MAX_CHARS`, where `hunted(x) || hunted(y)`, `fns[x].norm !== fns[y].norm`, `!nested(fns[x], fns[y])` and `jaccard(...) >= CUT`, in index order of `x` then `y`, as `{ x, y, similarity }`.

- `askPair`: `requests = [requestFor(x, y), requestFor(y, x)]`, both always built.
