## The design

**The reader.** A function held by a `const` or `let` is read with its whole statement (`export const name = ...;`) when the statement declares that one name, as the scan read it and every measured hash records; otherwise, a declaration list of several declarators or a `for` initializer, it is read as its own declarator (`name = ...`). One helper decides:

```ts
const declaredBy = (node: ts.VariableDeclaration): ts.Node =>
  ts.isVariableDeclarationList(node.parent) &&
  node.parent.declarations.length === 1 &&
  ts.isVariableStatement(node.parent.parent)
    ? node.parent.parent
    : node;
```

and the arrow branch's `push(node.name.text, node.parent.parent)` becomes `push(node.name.text, declaredBy(node))`. A statement of several declarators read whole gave each of its functions the same text, hash and line, so the hunt reported two functions of one statement as a word-for-word copy, the one way the reader could invent a copy; reading each declarator ends it, and `BLIND_SPOTS`' "none is made up" holds as written.

**The exit codes.** The test spawns `node scripts/copy-hunt/main.ts` in a temporary repository with `HOME` set to an empty folder and `TYPESAFE_API_KEY` taken out of the child's environment, so `liveSender` finds no key, answers every call with `NO_KEY` before any request is made, and nothing reaches the network. No change to `main.ts`.

**The path rule.** `isTsUnderLintRoots(path)`, a `.ts` file that is not a `.d.ts` and whose first segment is one of `lintTsRoots()`, lives in `test-support/lint-roots.ts` beside `lintTsRoots`, the reader of the roots it asks about and the module both commands already import (R3-C1). `scripts/copy-hunt/functions.ts` keeps `HUNT_ROOTS` for the order it walks the roots in.
