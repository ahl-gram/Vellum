   end_patch: "*** End Patch" LF?

What the reader below is built to, each a row of its tests:
   - a header line (`*** Begin Patch`, `*** End Patch`, `*** Add File:`, `*** Delete File:`, `*** Update File:`) is trimmed before it is matched, so `*** Add File: t.ts   ` writes `t.ts` and a padded `   *** Add File: padh.ts` is a header; a second space after the marker is part of the path (`*** Add File:  lead.ts` writes ` lead.ts`); a path with spaces is read whole; a lowercase header is refused;

## The design

**A reader, a few lines in the adapter, and the core taught three things.**

1. **`decodePatch`** in a new `scripts/agent-infra/hooks/codex-patch.ts` reads the patch text into one `FileChange` a file, in the patch's order, and never runs it. It reads the grammar above with the client's readings above, and returns `{ error }` for anything else, the heredoc wrapper and the `*** Environment ID:` line included (Calls made, items 2 and 3). An added file's text is its `+` lines; an update's text is **one text per hunk**: its context lines, its added lines and the text after its `@@` (Q1, ruled), with its removed lines left out (D10 as Q1); a hunk ends at the next `@@` or at `*** End of File`, which carries no text. A move is an update with a `*** Move to:` line.
2. **`toCodexRequest`** in `scripts/agent-infra/hooks/codex-adapter.ts` reads `apply_patch` as well as `Bash`. A patch that cannot be read becomes one operation of a new kind, `unreadable`, carrying the refusal, which asks for the form the grammar gives (D11 as Q2, ruled); so does a patch whose payload has no absolute `cwd`, since nothing then says where a relative path lands (Calls made, item 8). Otherwise each change's path, and a move's two paths, are resolved against the payload's `cwd` with `resolve`, which keeps an absolute path and folds `..`; a path that leaves the folder stays where it lands (Q7, ruled). The policy root stays the checkout the session started in, as Issue #1396 ruled; only the paths read the call's folder.
3. **The core.** `FileChange` in `scripts/agent-infra/hooks/request.ts` gains `delete` and `move`, and its text becomes `texts`, a list, so each hunk is scanned on its own; `Operation` gains `UnreadableCall`. `evaluate` in `scripts/agent-infra/hooks/engine.ts` turns an unreadable call into its denial. `checkEdit` in `scripts/agent-infra/hooks/edit-checks.ts` scans each text alone and refuses on the first that fails; a delete owes nothing (Q3, ruled); a move is judged where it lands: its texts are scanned under its new path, the route there owes its gate, and it owes Gate 4 there as an added file does, under a lead naming both paths (Q4, ruled). A patch's note carries every gate its files owe, in their order (Q5, ruled); the engine already does this.
4. **Claude's `MultiEdit`** gives `checkEdit` one text per edit instead of its edits joined (Q6, ruled), in a commit of its own (commit 4), which closes the same miss there.
5. **Tests.** A new `test/repo/codex-patch.test.ts` holds each rule to a fixture and the reader to the client's measured readings, row by row. The selftest runs every Edit, Write and MultiEdit row of its table once more as the patch that makes the same edit (`codex: patch:` rows, in `test-support/footgun-gate/codex-rows.ts`), with the same expected decision, which is the parity the issue asks for, and sizes the note of a patch owing every gate an edit can owe.

### Alternatives rejected, so the build does not rediscover one

- **Reading an update's hunks as one text**, as Claude's `MultiEdit` does today. Measured: a template one hunk leaves open hides the next hunk's escape (What was measured).
- **One `FileChange` per hunk.** Each hunk would then owe the next gate on its route, Gate 1 and Gate 7 for one test file in one patch, where one Claude edit owes one; a list of texts on one change keeps one change a file.
- **Reading the patch the way the grammar alone says, without the client's readings.** The grammar's `filename: /(.+)/` keeps trailing spaces the client trims, so `*** Add File: scripts/x.ts ` would be read as a file that is not a script while the client writes `scripts/x.ts`: a miss.
- **Accepting every form the client's standalone tool accepts.** A heredoc is shell syntax a tool call never carries, and an environment line names folders the hook cannot place; refusing both is visible and one edit away.
- **Running the patch, or reading the files it touches, to learn what it does.** The issue forbids running it; reading the files around a hunk is the context-aware scanning the epic leaves to a later, separately ruled follow-up.
- **Refusing at the adapter with a decision of its own.** The engine is the one place a denial is built (`decisionFor` in `scripts/agent-infra/hooks/hook-io.ts`), so an unreadable patch is an operation the engine refuses, and "a denial wins" holds for it.
- **Reading the payload's `cwd` as the policy root.** Issue #1396 ruled the rules come from the checkout the session started in (O3); only a patch's paths read the call's folder.
- **Checking whether an added file already exists**, as Claude's adapter does for a `Write`. The patch's own header says it adds the file; the client overwrites one that exists (measured), and the error is Gate 4 pasted once too often, never one missed (Calls made, item 4).
- **Merging identical warnings across a patch's files.** A patch whose three scripts each call `.click()` gets the click warning three times; the note is whole under `additionalContextLimit: 0`, and nothing is lost.
- **Editing `.codex/hooks.json`.** It is frozen (Issue #1396's O4): this sub changes code only, so the trusted hook runs it with no new trust.

```ts
import type { FileChange } from "./request.ts";

export type DecodedPatch = { readonly files: readonly FileChange[] } | { readonly error: string };

const BEGIN = "*** Begin Patch";
const END = "*** End Patch";
const ADD = "*** Add File: ";
const DELETE = "*** Delete File: ";
const UPDATE = "*** Update File: ";
const MOVE = "*** Move to: ";
const END_OF_FILE = "*** End of File";
const ENVIRONMENT = "*** Environment ID: ";
const UPDATE_LINE = /^(?:@@(?: .*)?|[ +-].*)?$/;

const quoted = (line: string): string => JSON.stringify(line.length > 60 ? `${line.slice(0, 60)}...` : line);

const kept = (line: string): string | null => {
  if (line.startsWith("-") || line === "@@") return null;
  return line.startsWith("@@ ") ? line.slice(3) : line.slice(1);
};

const readAdd = (
  lines: readonly string[],
  from: number,
  end: number,
): readonly [texts: readonly string[], next: number] => {
  let at = from;
  while (at < end && (lines[at] ?? "").startsWith("+")) at += 1;
  return [
    [
      lines
        .slice(from, at)
        .map((line) => line.slice(1))
        .join("\n"),
    ],
    at,
  ];
};

const readUpdate = (
  lines: readonly string[],
  from: number,
  end: number,
): readonly [texts: readonly string[], next: number] | string => {
  const hunks: string[][] = [];
  let open = false;
  let at = from;
  for (; at < end; at += 1) {
    const line = lines[at] ?? "";
    if (line.trimEnd() === END_OF_FILE) {
      open = false;
      continue;
    }
    if (line.startsWith("***")) break;
    if (!UPDATE_LINE.test(line))
      return (
        `line ${at + 1}, ${quoted(line)}, ` +
        "is not a line an update carries: `@@`, or a line starting with a space, `+` or `-`"
      );
    if (line.startsWith("@@") || !open) hunks.push([]);
    open = true;
    const text = kept(line);
    if (text !== null) hunks.at(-1)?.push(text);
  }
  return [hunks.map((hunk) => hunk.join("\n")), at];
};

export const decodePatch = (patch: string): DecodedPatch => {
  const lines = patch.trim().split(/\r?\n/);
  if (lines[0]?.trim() !== BEGIN) return { error: "its first line is not `*** Begin Patch`" };
  const end = lines.length - 1;
  if (end < 1 || lines[end]?.trim() !== END) return { error: "its last line is not `*** End Patch`" };
  const files: FileChange[] = [];
  for (let at = 1; at < end;) {
    const raw = lines[at] ?? "";
    const header = raw.trim();
    at += 1;
    if (header.startsWith(DELETE)) {
      files.push({ kind: "delete", path: header.slice(DELETE.length) });
    } else if (header.startsWith(ADD)) {
      const [texts, next] = readAdd(lines, at, end);
      files.push({ kind: "add", path: header.slice(ADD.length), texts });
      at = next;
    } else if (header.startsWith(UPDATE)) {
      const line = lines[at] ?? "";
      const to = line.startsWith(MOVE) ? line.slice(MOVE.length).trimEnd() : null;
      const read = readUpdate(lines, to === null ? at : at + 1, end);
      if (typeof read === "string") return { error: read };
      const [texts, next] = read;
      const path = header.slice(UPDATE.length);
      files.push(to === null ? { kind: "update", path, texts } : { kind: "move", from: path, path: to, texts });
      at = next;
    } else if (header.startsWith(ENVIRONMENT)) {
      return { error: `line ${at}, ${quoted(raw)}, names another environment, whose folders the hook cannot place` };
    } else {
      return {
        error:
          `line ${at}, ${quoted(raw)}, ` +
          "is not `*** Add File: `, `*** Delete File: ` or `*** Update File: ` and a path",
      };
    }
  }
  return files.length > 0 ? { files } : { error: "it names no file" };
};
```

];

  ["the root", PROBE],
  ["a nested folder", join(PROBE, "probe-1397", "deep")],
];
const kindOf = (out: string): string =>
  out.trim() === "" ? "none" : out.includes('"permissionDecision":"deny"') ? "deny" : "context";
let worst = 0;
let misses = 0;
for (const [place, cwd] of PLACES) {

      const t = process.hrtime.bigint();
