## The design

One new command, `npm run recon-triage`, under `scripts/recon-triage/`, built on the Jev client `scripts/jev/system-one.ts`, and one edit to `vellum-spec-recon`'s definition so that it runs it.

1. **Recon writes the issue's claims as rows** to `out/<N>-recon/claims.jsonl` in the tree it stands in, one JSON object a line: `claim` (one fact), `source` (`body` or `comment <date>`), `paths`, `symbols`, `kind` (`behavior`, `existence`, `count`, `process`, the answer key's four). Recon splits a two-fact sentence into two rows as it writes them; the command splits nothing.
2. **`npm run recon-triage -- rank <claims file>`** reads the rows, reads each behavior claim's cited files at the tree's HEAD, and routes each row by rule, never by Jev:
   - a claim whose kind is not `behavior` goes to recon's command check unasked;
   - a behavior claim that cites no file, or cites a file not at HEAD, is not asked and is listed first (there is no code for Jev to read, and a missing file is itself the likeliest sign of a stale claim);
   - a behavior claim whose every cited file is a stylesheet (`.css`) is not asked: the cascade and a rendered colour are what the browser computes, the trial's largest class of confident misses;
   - every other behavior claim is asked.
3. **Each asked claim is one request**, built exactly as the trial built it: the code excerpt by symbol (twenty lines either side of the first four hits a file, or the file's first 120 lines where no symbol is found; at most 6,000 characters a file and 14,000 a claim), state `{ claim, code }`, and the trial's two frozen questions, `holds` ("Does `code` do what `claim` says?") and `contradicts` ("Does `code` show that `claim` is wrong?"). A probe port of this builder rebuilt all 265 trial requests byte for byte (Tests, the excerpt).
4. **Code ranks**: score = the mean of `holds` and one minus `contradicts`, lowest first, the trial's best ordering (10 of its first 10 stale, 21 of 25, 37 of 50). 0.3 and 0.7 only label a row (likely stale, unsettled, likely current); they gate nothing.
5. **The report prints the rows in the order recon verifies them**: no code to read; triage skipped (each failed call, with its reason); ranked, likely stale first; stylesheet claims; command claims. A failed call is a row under "Triage skipped", never a place in the order, and the run exits 1. No key means every asked claim is skipped with a reason naming both places the key is read from. Where nothing was answered, or the command stops on an error, recon falls back to today's order, the issue's (ruling D1).
6. **The key**: a command that calls Jev reads it from `TYPESAFE_API_KEY`, then from `~/.config/typesafe/key`, through `readKey` and `liveSender` in `scripts/jev/system-one.ts`, which this pull request adds (Issue #1319, which needs the same lookup, has no branch or pull request: `gh pr list --state all --search 1319` printed nothing). `npm run comment-judge` switches to the same lookup, since the amendment covers every command that calls Jev.
7. **The regression set**: the trial's 265 scored behavior claims are tracked as `scripts/recon-triage/trial-set.jsonl`, and `npm run recon-triage -- trial --out <dir>` re-asks them at each claim's own commit and writes the score. A pull request that moves `MODEL` runs it.
8. **Recon verifies every row by command, in the printed order**, and its ledger's shape does not change. No verdict rests on Jev.

**Rejected alternatives** (not choices for the builder):

- **The command splits compound claims.** Jev answers probabilities and writes no text, and a split by punctuation leaves fragments such as "RB7 pins it" whose subject is gone, which no reader could judge. Splitting is recon's, at extraction, as the answer key's own extractor did it.
- **Routing appearance and arithmetic by words in the claim** ("rgb(", "specificity", two numbers). Keyword matching is the brittle heuristic the house replaces, and no trial measured it. The stylesheet rule is measured and ruled (D3): on the trial it set aside 19 of 265 claims, 6 of the 35 confident misses among them, left the first 10, 25 and 50 unchanged, and moved the AUC of the rest from 0.79 to 0.80.
- **Recon labelling appearance and arithmetic claims as kinds of their own.** Not measurable on the trial set, whose rows carry no such label; not ruled (D3 took the stylesheet rule).
- **Recon writing nothing and its dispatcher running the command.** Two rounds per issue; not ruled (D4 took the one file).
- **A third Jev question in the same request** ("Can `claim` be checked from `code` alone?"). Unscored, and Issue #1304's ruling 1 says each question owes its score first.
- **The body's third question** ("Does `comment` change or overrule `claim`?"). No trial scored it; not built.
- **A heredoc or standard input for the rows.** Measured refused by the fence (above).
- **Reading files with `readFileSync` from the working tree.** The trial reads each claim at its own commit, and rank reads HEAD the same way, through `gitTree` in `scripts/comment-judge/tree.ts`, so one reader serves both.
- **A private reader with a larger buffer in `scripts/recon-triage/`.** That copies `readAt`; the fix goes in `readAt` itself.
- **Retrying a 429 or 5xx.** Calls go one at a time (the trial's median call took 109 ms, so a 73-claim epic takes about 8 seconds), and a failed claim is shown skipped rather than retried.
- **Moving `scripts/comment-judge/tree.ts` to `scripts/jev/`.** It is generic, but moving it is a refactor this issue does not need; it is imported where it stands.

**`scripts/recon-triage/excerpt.ts`** (about 60 lines): the trial's excerpt builder, ported from `excerpt` in `/Users/ahl/CodeProjects/Vellum/out/jev-recon-trial/run.ts` (a copy is `/private/tmp/claude-501/-Users-ahl-CodeProjects-Vellum/4a0d7284-bcfc-4125-a14b-971a43f406d3/scratchpad/1310-trial-run.ts`, sha256 1561e483197b88199703bb2ec5a9987eafd94f105ff2684cdc31688d130f48d5), and the probe port `out/1310-dry-run/port.ts` in this planner's tree, which the dispatcher copies to the main checkout's `out/1310-dry-run/`.

```ts
import type { Tree } from "../comment-judge/tree.ts";
export const AROUND = 20;
export const MAX_HITS = 4;
export const HEAD_LINES = 120;
export const PER_PATH = 6000;
export const TOTAL = 14000;
export const SYMBOL = /^[A-Za-z_$][\w$.-]*$/;
export type Excerpt = {
  readonly code: string;
  readonly missingPaths: readonly string[];
  readonly missingSymbols: readonly string[];
};
export const excerptOf = (tree: Tree, paths: readonly string[], symbols: readonly string[]): Excerpt;
```

Behaviour, exactly the trial's:
- `syms` = `symbols` kept where `SYMBOL` matches; the others are ignored everywhere, `missingSymbols` included.
- A symbol matches a line through `new RegExp(`(?<![\\w$])${escaped}(?![\\w$])`)`, `escaped` being the symbol with each of `.*+?^${}()|[]\` escaped (`s.replace(/[.*+?^${}()|[\]\\]/g, "\\$&")`).
- For each path in order: read it with `tree.read(path)`; when that throws, push the path to `missingPaths` and go on. Split the text on `"\n"`. `hits` = the indexes of lines any symbol matches. Kept indexes: for each of the first `MAX_HITS` hits, `max(0, i - AROUND)` up to but not including `min(lines.length, i + AROUND)`; with no hit, `0` up to but not including `min(lines.length, HEAD_LINES)`. Walk the kept indexes in ascending numeric order, writing `// <path>:<index + 1>` before each index that does not follow the previous kept one, then the line. Join with `"\n"` and cut to `PER_PATH` characters.
- `code` = the parts joined with `"\n\n"`, cut to `TOTAL` characters.
- `missingSymbols` = the entries of `syms`, in their order, that match no line of any file read.

**`scripts/recon-triage/questions.ts`** (about 35 lines). The two questions are the trial's, word for word; Q1 pins the request they make.

```ts
import { MODEL, type NoulQuestion, type SystemOneRequest } from "../jev/system-one.ts";
export const HOLDS_ID = "holds";
export const CONTRADICTS_ID = "contradicts";
export const HOLDS: NoulQuestion = {
  type: "noul",
  instructions: "Does `code` do what `claim` says?",
  criteria: {
    true: "`code` behaves the way `claim` describes, for example a function `claim` says takes a URL does take one.",
    false: "`code` does something `claim` does not allow, for example a function `claim` says takes a URL takes no arguments.",
  },
};
export const CONTRADICTS: NoulQuestion = {
  type: "noul",
  instructions: "Does `code` show that `claim` is wrong?",
  criteria: {
    true: "Something in `code` behaves differently from what `claim` says, for example `claim` says a list has five ids and `code` declares three.",
    false: "Nothing in `code` goes against `claim`.",
  },
};
export const YES = 0.7;
export const NO = 0.3;
export const requestFor = (claim: string, code: string): SystemOneRequest =>
  ({ model: MODEL, state: { claim, code }, questions: { [HOLDS_ID]: HOLDS, [CONTRADICTS_ID]: CONTRADICTS } });
export const scoreOf = (holds: number, contradicts: number): number => (holds + 1 - contradicts) / 2;
export type Band = "likely stale" | "unsettled" | "likely current";
export const bandOf = (score: number): Band;   // score < NO: "likely stale"; score > YES: "likely current"; else "unsettled"
```

```ts
export const TRIAL_REFERENCE =
  "The trial at jev-1.14.0 (Issue #1310 comment 6782678031): AUC 0.76 (holds), 0.79 (1 - contradicts), 0.79 (mean of both); stale among the first 10, 25, 50, 100: 10, 21, 37, 66.";
export const parseTrialSet = (text: string): TrialRow[];
export const meanOf = (s: ScoredRow): number => scoreOf(s.holds, s.contradicts);
export const aucOf = (rows: readonly ScoredRow[], feature: (s: ScoredRow) => number): number;
export const rankByMean = (rows: readonly ScoredRow[]): ScoredRow[];
export const staleAmongFirst = (rows: readonly ScoredRow[], n: number): number;
export const scoreLines = (rows: readonly TrialRow[], replies: readonly Reply[]): string[];
```

- `parseTrialSet`: lines as `parseClaims` numbers them, blank lines skipped; messages, checked in this order: `line <n>: not a JSON object`; `line <n>: issue is not a whole number` (`issue` and then `comment_id`, `line <n>: comment_id is not a whole number`, each by `Number.isInteger`); `line <n>: claim is missing or empty`; `line <n>: verdict is not stale or current`; `line <n>: why is not a string`; `line <n>: sha is not a full commit id` (`/^[0-9a-f]{40}$/`); `line <n>: paths is empty or not a list of strings`; `line <n>: symbols is not a list of strings`; `line <n>: not a behavior claim` (`kind !== "behavior"`). It returns the nine fields.
- `aucOf`: over every pair of one `current` row and one `stale` row, count 1 where the current row's feature is greater, 0.5 where equal, 0 where less, divided by the number of pairs; `NaN` when either verdict has no row.
- `rankByMean`: a copy sorted by `meanOf` ascending, stable. `staleAmongFirst(rows, n)`: the stale rows among the first `n` of `rankByMean(rows)`.
- `scoreLines(rows, replies)`: `rows[i]` pairs with `replies[i]`. Answered rows become `ScoredRow`s from `nouls.holds` and `nouls.contradicts`. A number prints with `two`, and `NaN` prints as `n/a`. Lines, in order:

  2. empty
  3. `<answered> of <rows> claims answered (<stale answered> stale), models: <the distinct models of the answered replies, joined ", ", or none>. AUC is the chance a current claim scores above a stale one; 0.5 is chance.`
  4. only when a reply failed: `Not answered: <k> (<the distinct reasons, in first-seen order, joined "; ">).`
  5. empty, `| feature | AUC |`, `|---|---|`, `| holds | <aucOf holds> |`, `| 1 - contradicts | <aucOf 1 - contradicts> |`, `| mean of both | <aucOf meanOf> |`
  6. empty, `Per-issue average AUC of the mean: <mean of aucOf(meanOf) over each issue whose answered rows hold both verdicts, or n/a> over <that issue count> issues holding both verdicts.`
  7. empty, `Stale among the first N ranked by the mean (base rate <(100 * stale answered / answered).toFixed(0)>%): first 10: <a>; first 25: <b>; first 50: <c>; first 100: <d>.`, one entry per `FIRST_N`
  8. empty, `| band of the mean | rows | stale | current |`, `|---|---|---|---|`, then one row each for `likely stale`, `unsettled`, `likely current` (by `bandOf(meanOf)`), `| <band> | <rows> | <stale> | <current> |`
