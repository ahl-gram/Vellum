## The design

### The fade

- The index slip's scrolling box is `#index > .slip-body` (`src/layouts/Slip.astro` renders `<aside class="slip" id="index">` with a `.slip-head`, a `.slip-body` holding the `ol.index`, and no `.slip-foot`). The fade is a CSS `mask-image` on that box, a linear gradient from opaque to transparent, so the words and the hairlines fade into whatever paper is under them.
- Two classes on that box carry the state: `more-below` while more of the list lies below what the box shows, `more-above` once the list has scrolled from its head. The sheet draws the foot fade for the first, the head fade for the second, and both for both.
- The fade's depth is one token, `--index-fade`, a rem length declared in the `:root` block of `src/styles/shared/document-room.css` beside `--slip-w`. The sheet's gradients use it, and the index script reads it the way the house reads `--slip-w` and `--band-h` (the token's number times the root font size), so the mask and the stop short of it (below) are one number.
- The state is computed from the box's own scroll by `edgesOf` and written by `markEdges`, both new in `src/site/shared/index-ink.ts`. A pixel's slack at either end reads as that end (`EDGE_SLACK`, 1 px): `scrollHeight` and `clientHeight` are whole pixels rounded from a fractional layout, so a list scrolled to its end can stand up to a pixel short of it.
- The index script (`src/layouts/IndexSlip.astro`) marks the edges on every `scroll` of the box (the reader's wheel, and the box's own scrolling by the ink pass), and from a `ResizeObserver` on the box and on its `ol.index`, which reports every change of either's size: the slip's height set by `place()` on a resize and once the fonts are ready, the Glossary's find box hiding sections and terms on each keystroke, and a Primer room opening (which shows and hides lessons). The observer also delivers the first marking at boot. Nothing polls and nothing reads a timer.
- With scripts off no class is set, so nothing fades and the list is cut at the box's edge as today.

### Keeping the inked row clear of the fade

- Today `indexInk` (`src/site/shared/index-ink.ts`) scrolls the box so the inked row meets the box's top or foot edge exactly (IK1 and IK2 in `test/site/index-ink.test.ts`). With the fade, that edge is inside the fade, so the inked row would land faded (measured: 32 px of it in a 32 px fade, the `-f32raw` stills).
- The arithmetic moves, unchanged in shape, into a new pure function `inViewBy(row, box, inset)` that returns the scroll the box owes. It shrinks the box by `inset` at its top and at its foot before comparing, so the row lands `inset` px inside either edge. A row taller than the shrunk box is aligned by its top once and left still, IK2's rule carried to the shrunk box (IK6 below holds the shrunk box, since measuring "taller" against the raw box flips such a row between its edges on every pass, the defect IK2 was written for).
- The inset applies at both ends whatever the scroll: at the list's head the browser clamps `scrollTop` at 0, and at its end at its maximum, which are exactly where that end's fade is off, so no fade state is read.
- An inset that is not a positive number (the token unread, so `NaN`, zero, or below zero) is taken as 0, today's behaviour.
- `indexInk` takes a new `inset: () => number` part and calls `inViewBy` for the inked row. The index script passes it the token's depth in pixels.

### A keyboard reaching a link inside the fade

A link focused from the keyboard inside the fade would read at about 1:1 and the browser would not scroll it, since it is inside the box. The index script listens for `focusin` on the box and, only when the focused element matches `:focus-visible`, scrolls the box by `inViewBy` for that element with the same inset. A press's focus is left alone: moving the list under a pressed pointer between its press and its release would take the release off the link and lose the click. Measured by the step 6 plate read on the spike (real Tab through all 33 of the Q & A's index links at 1024 and Shift+Tab back): every link focused in a fade was scrolled wholly clear of it at 20, 32 and 48 px and eased; the focus ring, drawn outside the link, still reaches 3 to 4.5 px into the band and reads 6.47:1 or better there (today the slip's edge clips the ring of a link at its foot to nothing); and a real mouse press held 300 ms on a link in the fade moved neither the list nor the link, left `:focus-visible` false, and followed the link on release.

### Rejected alternatives

- **An overlay painted in the panel's colour** (a `::after` or a sticky strip over the list's foot): it needs a box stuck to the scrollport's foot, which `handbook/specs/cascade-traps.md` says is clamped inside its containing block, and it paints one colour over whatever ground the slip has. The mask needs neither.
- **The fade in `src/styles/shared/atelier.css`** beside the index's dress: that sheet is the kit's and already 861 lines, so adding to it would owe its split; the fade is the index slip's alone, and `src/styles/shared/document-room.css` is linked by exactly the three pages that carry the index slip (`test/site/astro-scaffold.test.ts`, the test opening "the chart rooms whose sheet stands in their stage link /shared/chart-stage.css") and already holds the index slip's width. Keeping it out of the kit also keeps it off the Specimen Book, whose list is not an index slip.
- **A fade state read from the scroll position inside `inViewBy`** (inset only at an end that is fading): the clamp already gives the same landing, so the state would be a second source of truth for nothing.
- **The Primer's open room wired through the index script**, or a module both scripts import: the second emits both scripts as files (above); the first needs the index script to learn the Primer's folds. `bindPrimer` already owns the fold.
- **Hiding the closed rooms' lessons with a class and a sheet rule**: `hidden` needs no rule, matches how `bindPrimer` already folds a room's body, and shows every lesson with scripts off by construction.
- **Only what is open on Q & A and the Glossary**: ruled out by ruling 3.

### `src/site/shared/index-ink.ts` (61 lines today, about 95 after)

`Placed`, `readingAt` and `entryAt` are unchanged. Add, between `entryAt` and `InkParts`:

```ts
interface Scrolled {
  readonly scrollTop: number;
  readonly scrollHeight: number;
  readonly clientHeight: number;
}

interface Span {
  readonly top: number;
  readonly bottom: number;
}

const EDGE_SLACK = 1;

export function edgesOf(box: Scrolled): { readonly above: boolean; readonly below: boolean } {
  return {
    above: box.scrollTop > EDGE_SLACK,
    below: box.scrollHeight - box.clientHeight - box.scrollTop > EDGE_SLACK,
  };
}

export function markEdges(box: HTMLElement): void {
  const { above, below } = edgesOf(box);
  box.classList.toggle("more-above", above);
  box.classList.toggle("more-below", below);
}

export function inViewBy(r: Span, b: Span, inset: number): number {
  const pad = inset > 0 ? inset : 0;
  const top = b.top + pad;
  const bottom = b.bottom - pad;
  const taller = r.bottom - r.top > bottom - top;
  if (r.top < top && r.bottom > bottom) return 0;
  if ((r.top < top && !taller) || (r.bottom > bottom && taller)) return r.top - top;
  if (r.top < top || r.bottom > bottom) return r.bottom - bottom;
  return 0;
}
```

`InkParts` gains `readonly inset: () => number;` after `keepInView`. In `indexInk`'s pass, the block that today reads the two rects and writes `box.scrollTop` (from `if (box !== null && row !== undefined) {` to its closing brace) becomes:

```ts

      box.scrollTop += inViewBy(row.getBoundingClientRect(), box.getBoundingClientRect(), p.inset());
```

`inViewBy` returns the delta rather than writing `scrollTop` itself, because `no-param-reassign` (with property assignments) refuses a write to a parameter's property (measured on the spike: `npm run lint` refused `box.scrollTop +=` on a parameter). `box` in `indexInk` and `body` in the index script are locals.
