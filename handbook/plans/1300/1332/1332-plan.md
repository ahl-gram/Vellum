## The design

**Every family the copy hunt lists is folded into one function, and none is renamed apart.** A copy whose text another function shares goes; the callers take the one that stays, from the module nearest both, or from a new one where none is shared. Renaming one copy so the texts differ would leave the copy and only hide it, so it is never the fold. A one-line wrapper closing over a module constant (F18, F19) is folded by calling the shared function it wraps. Where a near copy of the same logic sits in a fake or a module the fold already edits, it joins the same helper (named per family below), so the hunt has no look-alike left to ask about there.

**The reader learns the four forms in this pull request** (D3): getters and setters with a body, constructors with a body, and arrows or function expressions assigned with `=` to an existing name, as `1332-pr2-plan.md`'s design first gave them. Rule: the folds have to clear every copy the check will refuse, and the check refuses what the widened reader reads; the widened reader finds one pair today's does not (Measured 2), so it lands where its finds are folded, and the second pull request meets a tree already clear.

**The three families that cross between the product and its tests or tools** are read as `handbook/plans/1300/1318/1318-plan.md` read its copies: how the copy is used, then class A (builds a fixture or reads a result), class B (kept equal on purpose) or class C (the oracle an assertion takes its expected value from).
