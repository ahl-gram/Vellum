## The design

The timeout test stops racing real git. It writes a stand-in `git` into a fresh temp directory, a two-line `/bin/sh` script whose second line is `exec sleep 5`, puts that directory first on `process.env.PATH` for the one synchronous call `listWorkingTree(dir, [], 200)`, and restores `PATH` in a `finally`. The real `spawnSync` resolves `git` to the stand-in, the 200 ms limit fires long before the 5 s sleep can end, and the module's existing status check turns the timed-out spawn into the throw the test asserts. `test-support/working-tree.ts` is not touched. The other three tests in the file are not touched.

The assertion also pins the cause: `/git ls-files under .+ failed \(null, Error: spawnSync git ETIMEDOUT\)/`. The old `/git ls-files under .+ failed/` passes when the stand-in is missed, because real git then exits 128 at once in a directory that is no repository (measured below), so the old regex would let a misaimed fixture pass.

`exec` is load-bearing. Without it `sh` forks `sleep` as a grandchild, the limit's kill lands on `sh`, and the `sleep` outlives the test with parent 1 (measured below). With `exec` the shell becomes `sleep`, so the kill lands on the one process. The 5 s sleep is also the child's own time limit: with the module's limit removed (M1) the test ends at 5 s, red, rather than hanging.

**How `spawnSync` finds the stand-in**, measured on Node v26.13.0, darwin (`out/1354-dry-run/1354-lookup.log`): with an `env` option the command is looked up on the child env's `PATH` (case b finds the stand-in; case d, a mutated parent `PATH` with an `env` that lacks the stand-in, runs real git), and without one it is looked up on the parent's current `process.env.PATH` (case c finds the stand-in). The module passes no `env`, so the child's env and the parent's are the same object here and the lookup cannot differ between them on either platform. The linux reading is UNVERIFIABLE from the Mac; the first CI run of this pull request is that reading (Stop conditions).

**Rejected**:
- **An injected spawn.** `listWorkingTree` takes none, so this needs a new parameter, and the test would then hand the module a replacement for `spawnSync`, the very call whose `timeout` is under test. Gate 1 item 10 says pin what reaches the spawn, and the workspace testing rule says never mock the system under test.
- **An `env` (or command) parameter on `listWorkingTree`.** It would change none of the five callers (`scripts/lint/word-for-word.ts:27`, `test-support/site-sheets.ts:8`, `test/repo/type-check.test.ts:26`, `test/site/folder-layout.test.ts:15`, and this file), since none passes a third argument. It is rejected because Alex ruled the fix test only and named the `PATH` route first, and because it widens a helper the lint also imports for the sake of one test ("touch only what you are asked to touch").
- **Keeping the 1 ms limit against real git with a slower fixture** (a bigger tree). It is still a race, only a rarer one.
- **Running the listing in a child Node process with its own env**, to avoid touching `process.env`. It is heavier and asserts on a second process's output, for a window that is already unobservable (next point).

The `process.env` change is shared state, set and restored as `test/e2e/launch-harness.test.ts:34-46` and `test/cli/main.test.ts:208-212` already do around their stand-ins on CI. Its window is one synchronous call: nothing else in the process runs between the set and the `finally`, and `node --test` runs each test file in its own process (`unitArgs` in `scripts/unit-suite.ts` sets no isolation flag).

test("a listing that runs past the time it is given throws, naming git ls-files and the timeout, rather than return a partial tree (Issue #1332, Issue #1354)", () => {
  const dir = realpathSync(mkdtempSync(join(tmpdir(), "working-tree-slow-git-")));
  const saved = process.env["PATH"];
  try {
    writeFileSync(join(dir, "git"), "#!/bin/sh\nexec sleep 5\n", { mode: 0o755 });

    );

    else process.env["PATH"] = saved;
    rmSync(dir, { recursive: true, force: true });
  }
});
