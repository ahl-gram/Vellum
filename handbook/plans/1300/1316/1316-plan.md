## The design

### How each row was decided

Every row was read at its sweep's base (`90ab9066` for PR #377, `5df13800` for PR #548) with `locateRun` in `scripts/comment-judge/trial.ts`, which returns the whole comment run and the code beneath it. Its code was found at `origin/main` by that code line (130 rows matched exactly, 28 by the symbol the code declares, 10 found by hand because the code was moved or rewritten; 16 rows sit in files that moved, 13 under `src/site/living-chart/`, now `src/site/shared/living-chart/`, and 1 in `test/cli/e2e-ports.test.ts`, now `test/e2e/ports.test.ts`). Each was then put in exactly one bucket:

- **N, restore.** A real fact of its kind, lost from the whole repository, and of a kind no assertion can state for a reader at the line: where a number came from, how a tool behaves, the units of a bare number, which way a coordinate or an ordering runs, why a type's width was chosen.
- **Q, pinnable with no test.** A behaviour a unit test could assert and none does.
- **M, context measurement.** A measured number that justifies a design but sets no value at its line: a census, a timing, why a test exists, why a gate was removed. Ruling 1 leaves these out.
- **P, pinned.** An existing test whose ASSERTION fails if the fact stops being true, read in the test's body, never taken from its name alone (`handbook/specs/conventions.md`, the bullet on naming the test).
- **H, held.** Still said at HEAD: in its own file, in a test's comment, in a stylesheet's comment, in a spec or by a lint rule.
- **G, gone.** The code it described was rewritten, or the fact is no longer true.
- **X, no line owed.** A misflag (no fact of the flagged kind), a comment restating the code beside it, the arithmetic of a named constant, or a duplicate of another row's line.

### How a line is written

- One line, on its own, directly above its anchor at the anchor's indentation. Where a one-line doc comment already sits directly on the anchor (`/** Degrees. */` above `MAX_TILT`), the new line goes above that doc, so the doc stays attached to its symbol.
- `//`, except on the fields of `ProspectInput` in `src/prospect/input.ts`, whose surviving docs are one-line `/** ... */`, which those lines match.
- A measurement is written in the past tense with its date and its issue, as a record of what was measured, never as a claim about the code today.
- `Issue #N` or `PR #N`, never a bare number, every number checked with `gh api`: 17, 78, 120, 124, 171, 185, 229, 237, 275, 284, 298, 312, 327, 335 and 366 are issues, 311 is a pull request.
- A clause no longer true is dropped, not carried: row 72's note that a change re-pins RV4 in a script that no longer exists (RV4's label in `e2e/suites/room-voyage-route.ts` reads `MAX_TILT` itself), and row 139's check id S9, which no suite carries.

### Alternatives rejected

- **Restore all 168 as written.** `vellum/ts-comment-issue-form` refuses every bare `#185`, row 72 cites a deleted script, 60 rows are pinned by a test and 25 are already said, so the next weekly sweep would delete those again under the comment rule, and a copy of a held fact is a second home (`handbook/specs/conventions.md`, Where a rule lives).
- **Restore the original multi-line blocks.** The house writes a comment as one long line.
- **An AST token verifier for "no code changed".** Every planned change adds whole lines and edits none, so a line-level read of the diff is the whole proof: `added-only.ts` below, proven at planning against a patched file and a code mutant.
- **`npm run comment-judge` over the diff.** Its answers are probabilities, a reader's hypothesis (`handbook/specs/check-placement.md`, What no check holds), and the triage above already reads every row by hand.
- **Carry the units in the names (`GROUND_SAMPLE_STEP_PX`).** A code change, which this pull request does not make.
