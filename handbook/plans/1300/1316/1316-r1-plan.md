## The design

### How each row was decided

Every row was read at its sweep's base, `90ab9066` for PR #377 and `5df13800` for PR #548. The reader was `locateRun` in `scripts/comment-judge/trial.ts`, which returns the whole comment run and the code beneath it. Each row's code was then found at `origin/main` by that code line:
- 130 rows matched exactly;
- 28 matched by the symbol the code declares;
- 10 were found by hand, because the code was moved or rewritten.

16 rows sit in files that moved:
- 13 under `src/site/living-chart/`, now `src/site/shared/living-chart/`;
- 3 in `test/cli/e2e-ports.test.ts`, now `test/e2e/ports.test.ts`.

Each row went into exactly one bucket:

- **N, restore.** A real fact of its kind, lost from the whole repository, of a kind no assertion can state for a reader at the line: where a number came from, how a tool behaves, the units of a bare number, which way a coordinate or an ordering runs, why a type's width was chosen. A line carries only the part nothing else holds (call 3).
- **Q, pinnable with no test.** A behaviour a unit test could assert and none does. These are the second pull request's tests.
- **M, context measurement.** A measured number that justifies a design but sets no value at its line: a census, a timing, why a test exists, why a gate was removed. Left out by ruling 1.
- **P, pinned.** An existing test whose ASSERTION fails if the fact stops being true. Read in the test's body, never taken from its name alone.
- **H, held.** Still said at HEAD: in its own file, in a test's comment, in a stylesheet's comment, in a spec or by a lint rule.
- **G, gone.** The code it described was rewritten, or the fact is no longer true.
- **X, no line owed.** One of four things:
  - a misflag;
  - a comment restating the code beside it;
  - the arithmetic of a named constant;
  - a duplicate of another row's line.

### How a line is written

- **Placement.** One line, on its own, directly above its anchor, at the anchor's indentation. Where a one-line doc comment already sits directly on the anchor, the new line goes above that doc, so the doc stays attached to its symbol.
- **Marker.** `//` everywhere, except on the fields of `ProspectInput` in `src/prospect/input.ts`. Their surviving docs are one-line `/** ... */`, and those lines match them.
- **Measurements.** Written in the past tense with their date and their issue: a record of what was measured, never a claim about the code today.
- **Numbers.** `Issue #N` or `PR #N`, never bare, each checked with `gh api`. 17, 78, 124, 171, 185, 237, 275, 298, 312, 335 and 366 are issues; 311 is a pull request.
- **Content.** Only what nothing else holds. A clause that is no longer true, or that is said elsewhere, is dropped.

### Alternatives rejected

- **Restore all 168 as written.**
  - `vellum/ts-comment-issue-form` refuses every bare `#185`.
  - 59 rows are pinned by a test and 25 are already said, so the next weekly sweep would delete those again under the comment rule.
  - A copy of a held fact is a second home (`handbook/specs/conventions.md`, Where a rule lives).
- **Keep the first plan's full sentences where part is held elsewhere.** That is the same second home, and the cold skeptic's round named five such lines.
- **Restore the original multi-line blocks.** The house writes a comment as one long line.
- **An AST token verifier for "no code changed".** Every change adds or edits a whole comment line, so a line-level read of the final diff against main is the whole proof (`added-only.ts`).
- **`npm run comment-judge` over the diff.** Its answers are probabilities: a reader's hypothesis, not a check.
