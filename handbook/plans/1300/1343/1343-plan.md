## The design

**One process is one run.** Each Jev command is a script whose `import.meta.main` block runs one subcommand and exits, so a run begins when that block starts and ends when its `main` returns, throws or the process is signalled. Each subcommand calls the sender factory once: the second call sites the recon flagged sit in other subcommand branches (`scripts/copy-hunt/main.ts` lines 21 and 52 are `diff`/`full` and `trial`; `scripts/comment-judge/main.ts` 38 and 58 are `diff` and `trial`; `scripts/recon-triage/main.ts` 32 and 57 are `rank` and `trial`). The meter is shared by every sender one run builds anyway, so a second call would still make one line.

**The entry points**, each a `main.ts` with `export const main` and an `if (import.meta.main)` block:

| npm script | file | subcommands that can send |
|---|---|---|
| `copy-hunt` | `scripts/copy-hunt/main.ts` | `diff`, `full`, `trial` |
| `keeper-scan` | `scripts/keeper-scan/main.ts` | `diff` |
| `recon-triage` | `scripts/recon-triage/main.ts` | `rank`, `trial` |
| `comment-judge` | `scripts/comment-judge/main.ts` | `diff`, `trial` |
| `still-judge` | `scripts/still-judge/main.ts` | `compare`, `trial` |

`npm run comment-sweep` imports `scripts/comment-judge/tree.ts` only and sends nothing; it is not a Jev command.

**A shared runner, `runCommand` in `scripts/jev/cli.ts`, is the run's one home.** Every entry point's `import.meta.main` block becomes one line that calls it. It builds the run's meter, hands `main` a `sendFor` whose live senders report to that meter, registers the SIGINT and SIGTERM handlers, awaits `main`, and writes the run's line in `finally`. Why a shared runner and not each `main`: the start, the end, the signal handling and the write would otherwise be written five times; the signal handler is per process anyway; and a later command gets the log by being written the way the five are.

**The meter sits in `senderFor`'s valid-key branch, around `ask`.** That branch is the only path that reaches the network, so a dry run (`dryRunSender`), a missing key (`NO_KEY` from `liveSender`) and a key a header cannot carry (`KEY_REFUSED` from `senderFor`) never touch it, and "a run that sent nothing logs nothing" follows from where the meter is. It records the request as sent BEFORE awaiting `ask`, so a request in flight when an interrupt lands still counts, and records the reply after. `ask` never rejects (its `try` covers the fetch and the body read, and `readAnswers` returns rather than throws), so every reply is recorded unless the process is interrupted first.

**The meter is a required argument of `senderFor` and `liveSender`, never module state.** Four test files build key-echoing senders with `liveSender({}, "/h", ...)` (`test/repo/jev-system-one.test.ts`, `keeper-scan-report`, `copy-hunt-report`, `recon-triage-report`); a per-process meter would count their 401s, and a flush at exit would write `/h/.config/typesafe/usage.jsonl` inside the test runner. Required, it makes every caller name what tallies its sends (check-placement, "Make a wrong state unrepresentable"): tests pass `unmetered` from `test-support/jev-fakes.ts`, and the one production caller is `runCommand`. The old `sendFor` export of `scripts/jev/cli.ts` is deleted, so no unmetered production sender is left to import; each `main` now takes `sendFor` as its second argument, and the type checker refuses a `main.ts` block that does not supply one.

**A reply says whether its count is TypeSafe's.** `Answered` gains `readonly estimated: boolean`, set by `readAnswers` to `true` exactly where the body carried no `usage.input_tokens` and the count fell back to the request's characters at two a token (`readAnswers` in `scripts/jev/system-one.ts`, line 57; the issue's "line 55" and "`reply`" both mean this line). Every command's `replies.jsonl` gains the field.

**The run's tally** counts every request sent (`requests`), sums the input tokens of the replies that answered (`inputTokens`, an answered reply's estimate included), counts the replies that carried TypeSafe's own count (`counted`), and lists the models the requests named, distinct, in the order first sent. Its line is written when `requests > 0`, even where `inputTokens` is 0, as exactly the six ruled keys in the ruled order:

```
{"at":"2026-11-11T20:00:00.000Z","input_tokens":900,"requests":3,"model":"jev-1.14.0","command":"copy-hunt diff","estimated":false}
```

`estimated` is `counted < requests`: true when any request sent came back without TypeSafe's own count, whether it failed, was still in flight at an interrupt, or was answered with no usage. That is the comment's "true if any reply in the run carried no usage" read literally. A request that failed after it was sent adds no tokens (Rulings: D1, option A).

**The log is appended to, never read whole or rewritten** (the one byte read is its last, below). `appendUsage` creates `~/.config/typesafe/` under the home it is given where it is missing (mode `0o700`, since it is the key's folder), opens `usage.jsonl` for appending, and writes the line in ONE write call, so lines from lanes running at the same moment do not interleave. Where the file is not empty and its last byte is not a line break, the write starts with one, so a line typed by hand without a trailing break is not glued to the client's: the panel drops a line it cannot parse, and a glued pair is two runs silently uncounted, the undercount Alex's comment names.

**The hand-logged lines stay as they are.** `~/.config/typesafe/usage.jsonl` holds seven lines today, each `{"at","input_tokens","command","estimated"}` (read 2026-11-11). `budget.json`'s baseline (43,172,500 tokens as of 2026-11-11) has the source "the hand-kept ledger ...; calls after this are summed from usage.jsonl", so the hand lines are the runs after the baseline and nothing counts twice. The client appends after them; the panel's `JSON.parse(line).input_tokens ?? 0` reads both shapes, so the mixed file sums correctly; the panel's "N logged" counts lines, each of which was already one run. The hand ledger stops when this merges (the issue's "Where it stands").

**A failed write never fails the run.** The runner catches it and reports it once on stderr, with the line it could not write so the count can be added by hand:

```
the run's Jev usage could not be logged to ~/.config/typesafe/usage.jsonl (<errorText of the error>); add its line by hand: <the line as JSON>
```

A once-guard means the line is attempted at most once a run, so the report comes at most once, whether the run ends by `finally` or by a signal, or both.

**An interrupt logs, then exits as the signal's death.** On SIGINT the runner writes the line and exits 130; on SIGTERM, 143 (128 plus the signal number, the shell's convention). Measured 2026-11-11 on Node v26.13.0 by `out/1343-dry-run/1343-sig-probe.ts`, run as `node out/1343-dry-run/1343-sig-probe.ts` at 699dca2b and copied by the dispatcher to the main checkout's `out/1343-dry-run/`: with no handler a SIGINT ends the process with `signal=SIGINT` and runs neither a `finally` nor an `exit` listener, and with a handler that calls `process.exit(130)` it ends with `code=130`. A registered signal listener does not hold the process open (a script that registers both and prints exits in 0.05 s, measured the same day). A run capped by its input-token cap needs no code here: it ends through `main`'s return like any run.

**A thrown error** is printed through `errorText` (`src/site/shared/error-text.ts`) and the run returns 1, exactly as each `main.ts` block does today; the block's catch moves into the runner.

**The `command` key** is the npm script's name, then a space and `argv[0]` where `argv[0]` exists and does not start with `-`: `copy-hunt diff`, `recon-triage rank`, `still-judge trial`. That is the form the hand lines already use ("still-judge trial", "recon-triage rank"). Every `main` sends only after its first positional argument matched a subcommand, and an `argv[0]` not starting with `-` is that first positional argument (`parseArgs` in `scripts/jev/cli.ts`; `takeSeeds` in still-judge strips `--seeds` first), so the second word of any line written is a subcommand from its usage, never a path or text. Where `argv[0]` is a flag the line names the script alone.

**Rejected, with the reason:**

- **Each `main` logging in its own `finally`**: the same block written five times, and none of them sees a signal.
- **A flush from `process.on("exit")`**: measured above, it does not fire on a default SIGINT death, and it can be tested only by spawning.
- **Wrapping the `Send` that `sendFor` returns**: it sees a `Failed` reply and cannot tell a missing key (nothing sent) from an HTTP 429 (sent), short of matching reason strings.
- **Wrapping `Fetch`**: it sees the network but parses TypeSafe's body a second time, a second home for what `readAnswers` reads.
- **A meter held in module state, or read through `AsyncLocalStorage`**: hidden state the report tests' senders would write into, as above.
- **A lint rule refusing `liveSender` outside `scripts/jev/`**: the required meter argument already makes a bypass a deliberate act; the blind spot is named in Calls made.

## Tests, in the order they are written

No browser check is added or made longer, so no ledger line, browser readings or step count is owed, and `vellum-plate-reader` is not owed. No test makes a Jev call: every sender reaches a fake `Fetch` (Issue #1304's ruling).

`AT` below is `new Date("2026-11-11T20:00:00.000Z")`. `EST` is `Math.ceil(JSON.stringify(ONE_QUESTION).length / 2)`, the client's estimate for `ONE_QUESTION`. Every in-process `runCommand` test passes its own home from `withHome`, injects `now: () => AT`, records `warn`, `onSignal` and `exit` into local arrays and a map, and first calls `noExit(t)` from `test-support/process-fakes.ts`, so a mutant that calls `process.exit` itself throws instead of ending the runner.

## Calls made

1. **One process is one run, and the shared `runCommand` in `scripts/jev/cli.ts` is its one home**, called from each entry point's `import.meta.main` block. 6. **`requests` counts every request sent, answered or not, and a line is written whenever it is above 0, even at 0 tokens.** Rule: the comment draws the line at sending ("a run that sent nothing ... logs nothing"); a run whose every request failed was still a run.
