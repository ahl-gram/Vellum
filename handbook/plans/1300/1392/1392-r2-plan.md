## The design

Parts H, S and P of `1392-r1-plan.md` stand as built. This revision adds or changes:

### Part L: the landing against the browser's own jump (C24, D8)

A page opened at an address (`/primer/#prospect`) is scrolled by the browser to the element the address names. In Chrome and Brave that jump reads the document's address just after DOMContentLoaded, which is after the page's own module script has run and landed the walk at the top, so the jump wins (the review's `"y":214` and `"y":335`). The page now takes its address out of the window's location as it lands, with `history.replaceState`, and puts it back with `history.replaceState` a task after DOMContentLoaded, unless something has put another address there since. `replaceState` fires neither `hashchange` nor `popstate` and moves nothing.

- Called from `bindPrimer`'s boot only when the address names something inside a room (an `Aim` other than `none`), so an address outside every room (PB2's `#afterward`) is left to the browser's jump as today.
- A press inside the page already prevents the browser's default (C16), and a back or forward between the page's own entries lands at the top with no frame painted elsewhere (reading C below), so neither needs the hold.
- **D8 (ruled, option 1, comment 7201280596)**: `bindPrimer` sets `window.history.scrollRestoration = "manual"` at boot, so a reload lands the page at its top like every other landing (C14 as ratified), instead of the browser putting back the scroll it left.

Measured (each staged on the build of d506e5a0 by a script the browser adds to every new document, the hold as a `MutationObserver` that runs as the page script sets `data-bound`, no source edited; `y` after the document's load and thirty frames more, `maxY` the furthest scroll any frame or scroll event saw from the document's start):

  ```ts
  // The browser reads a page's address for its own jump to it just after DOMContentLoaded (measured in Chrome 158 and Brave 158, Issue #1392), so the Primer holds its address out of the window's location from its landing until a task after it.
  export interface AddressWindow {
    readonly location: { readonly pathname: string; readonly search: string; readonly hash: string };
    readonly history: { readonly state: unknown; replaceState(data: unknown, unused: string, url: string): void };
    setTimeout(run: () => void, ms: number): unknown;
  }

  export interface AddressDocument {
    addEventListener(type: "DOMContentLoaded", run: () => void, options: AddEventListenerOptions): void;
  }

  export function holdAddress(win: AddressWindow, doc: AddressDocument): void {
    const { pathname, search, hash } = win.location;
    if (hash === "") return;
    win.history.replaceState(win.history.state, "", pathname + search);
    doc.addEventListener(
      "DOMContentLoaded",
      () =>
        win.setTimeout(() => {
          if (win.location.hash === "") win.history.replaceState(win.history.state, "", pathname + search + hash);
        }, 0),
      { once: true },
    );
  }
  ```
