## The design

**The rule.** A unit test can pass with nothing checked when every check in it sits behind a skip. The rule reads each `test(` or `it(` call in a `test/**/*.test.ts` file and refuses it, at its callee, when it holds at least one check and every check is skippable, as the clauses under Files define. A check is reached on every path when it sits under no `if` or `?:` whose other side checks nothing, and after no `return` or `continue` that an `if` takes before anything checks or announces a skip; so a floor after the loop (`assert.ok(checked >= 1)`), `t.skip()` before the exit, and an `if` whose `else` checks each make a test pass, exactly the three forms the ruling names.

**The excuse list.** `SKIPPABLE_TESTS` in the rule's file maps `"<repo path> :: <test title>"` to its reason, is passed to the rule as its option, and every key the rule does not use in its file reds as stale there. The value is the reason, so no entry needs a comment. The option schema refuses an empty reason. A unit test holds every key to a unit test file that exists, since the lint never reads an excuse for a file it never lints.

**Which tests take a witness and which an excuse (the first day).** A test takes a witness where the cases its loop or `if` filters are computed on this run by the code under test (a generated world, a routed voyage, a voyage plan), so one change to that code can leave none and the test pass with nothing checked; each witness's mutation is that one-line change, and it reds the witness and not the test as it stands. A test takes an excuse where its cases come from a literal table no run computes (`LOD_BANDS`, the committed face tables, the file's own page roster), where no case is filtered out at all (each page checked on one side of an `if` or the other; a chart identical to its copy is the pass), or where no one-line change to the code can empty the case (Gate 1 item 1). - *An inline `eslint-disable` per excused test*: every inline skip is an entry Alex rules on in the rulebook's list; the issue asks for an excuse list with a reason per entry.
- *Keying an excuse by line*: lines moved between `9683c29e` and `a6e5fc9b` for six of the 15 (recon); titles are unique per file (`titles.log`).
- *Reading `check<Upper>` and `must<Upper>` helpers, `break`, or `if (c) assert.fail()` too*: measured to change no verdict today (finding 3); the rule keeps the issue's shape and names each as a blind spot with its direction.

- *Wiring the real rule body in the first commit*: the lint would red on CI for every commit until the last witness lands; the stub keeps the lint green and the unit test red on its assertion until the body lands last.
- *Per-seed floors in W3*: seed 7 routes no cross-landmass leg (2, 2, 0), so a per-seed floor reds on a world the test as written allows; swapping the seed is a coverage change this issue does not ask for.

Its `create(context)` implements these clauses, and nothing else; a clause's number is what the prover's rows below name:

- **C1, the test.** A test is a `CallExpression` whose callee is the `Identifier` `test` or `it`. Its body is the LAST argument that is an `ArrowFunctionExpression` or a `FunctionExpression`; a call with no such argument is not read.
- **C2, the walk.** The body (its block, or its expression for an expression-bodied arrow) and every node under it are read through `context.sourceCode.visitorKeys` (the walk `children` in `scripts/lint/e2e-sleep.ts` does), keeping for each node its ancestors up to the body. A `FunctionDeclaration`, `FunctionExpression` or `ArrowFunctionExpression` under the body is not entered.
- **C3, a check.** A `CallExpression` whose callee, read as a dotted name (an `Identifier`, or a non-computed `MemberExpression` chain of identifiers, `a.b.c`; anything else has no name), is `assert`, begins `assert.`, matches `/^(assert|expect)[A-Z]\w*$/`, or begins `<ctx>.assert.`, where `<ctx>` is the body's first parameter's name when that parameter is an `Identifier`.
- **C4, an announced skip.** A `CallExpression` whose dotted callee is exactly `<ctx>.skip`.
- **C5.** A test with no check is not reported.
- **C6, under an if.** A check is under an if when one of its ancestors is a `ConditionalExpression` it sits in the `consequent` or `alternate` of, or an `IfStatement` it sits in the `consequent` or `alternate` of (not the `test`) whose other branch is absent or contains no check.
- **C7, a skip.** An exit is a `ReturnStatement` or a `ContinueStatement`. Its branch is the `consequent` or `alternate` (whichever holds it) of its NEAREST `IfStatement` ancestor; an exit with no `IfStatement` ancestor is not a skip. An exit is a skip when no check and no announced skip starts inside its branch before the exit starts.
- **C8, skippable.** A check is skippable when it is under an if (C6), or a skip (C7) starts before it that is a return, or a skip starts before it that is a continue whose nearest enclosing loop (`ForStatement`, `ForInStatement`, `ForOfStatement`, `WhileStatement`, `DoWhileStatement`) also contains the check.
- **C9, the report.** A test with a check (C5) whose every check is skippable is reported with `messageId: "found"` at its callee, `data: { title }`, unless the option's `excused` holds the key `` `${repoPath(context.filename)} :: ${title}` ``. The title is the first argument's value when it is a string `Literal`, its cooked text when it is a `TemplateLiteral` with no expression, and its source text otherwise.
- **C10, stale.** At `Program:exit`, each key of `excused` that begins `` `${repoPath(context.filename)} :: ` `` and excused no test in this file is reported with `messageId: "stale"`, `data: { entry: key }`, at the program.

"Starts" and "contains" compare node ranges (`range[0]`, `range[1]`). Internal helpers, their names and bodies, are the builder's; for reference, the draft's were `dottedName(node): string | null`, `testBody(call): ArrowFunctionExpression | FunctionExpression | null`, `titleOf(call, text): string`, `collect(body, keys: SourceCode.VisitorKeys)` returning the checks, the announced skips' starts and the exits each with its ancestors, and `everyCheckSkippable(body, keys): boolean`.
