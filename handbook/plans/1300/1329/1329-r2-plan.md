## The design, changed

**The counts.**
- W4 keeps one record `walked = { road: 0, sea: 0 }`. Each loop counts the vertices it asserts on, so the road count is the road loop's and the sea count is the sea interior loop's.
- W5 keeps `chords: Record<RoutedLeg["mode"], number>`. It counts each chord once, by its leg's mode, at the top of the chord loop rather than per sample. Every chord is sampled at least three times (`steps >= 2`), so a chord read is a chord checked.
- Each test then asserts two floors, road and sea, each `>= 1` with its own message: Issue #1315's principle (the named case occurs at least once), the form the ruling names.

**Alternatives rejected.**
- *A floor per sea leg* (every sea leg walks an interior vertex, every sea leg samples a chord): the ruling asks for at least one, and today 1 of the 8 sea legs already takes W5's `continue` (`sea-continue.log`), a case the test allows.
- *Counting samples, not chords, in W5*: the ruling and the finding speak of chords; a sample count would read the same red and green, and a chord count reads in the finding's own unit (77 and 39).
- *M8 as `  return [from, ...water, to];` to `  return [from, to];` (`src/render/voyage-route.ts:196`)*: it shortens the sea chain the router compares against the road (`chainLength(walk) >= SAIL_WHEN_ROAD_EXCEEDS * chainLength(water)`), so it changes which legs sail and need not leave road legs passing; the simplifier's epsilon changes only the points of legs already routed to sea.
- *Keeping the mode set beside the new counts in W4*: the counts imply it.
