## What this is

Code renders a chart sheet, shoots it through `shootAll`, and asks TypeSafe's Jev four yes-or-no questions about how it reads at a glance; code sets one version of a chart against another, question by question. The pull request builds that as `npm run still-judge`, with two subcommands:

- `compare <sheet|rainfall|crop> <today.png> <other.png>...`: asks today's picture and each other version of the same chart the frozen questions for their kind, and prints, for each other version and each question, both numbers, the difference, and a reading: reads better, reads worse, or no difference, a difference under 0.12 being none. It never prints a single picture's number as a pass or a fail, and it ends with that rule in words. This is the command `vellum-plate-reader` would run at a step 6 sitting, the candidate against today's control, once a later pull request places it.
- `trial --out <dir>`: the score, kept as the regression a model move reruns (`handbook/specs/check-placement.md`). Three defects the house really found and fixed (Issue #108, Issue #158, Issue #9) and one invented for the title question are put back on today's chart by a style override, on 30 charts, each beside the same chart as it ships today; the score is how often today's twin reads higher on the defect's own question.

TypeSafe takes images (`jev-1.13.0` and `jev-1.14.0`) behind the request header `TypeSafe-Danger-Zone-Images: true` and calls them "Dreamer-ready": not ready for production, with format, limits and accuracy that may change between releases (https://docs.typesafe.ai/go/images.md, read 2026-11-11). The shared client sends text only today (recon's one blocking STALE row), so the pull request teaches it to carry an image.

## The design

**One request per picture, the image in the state once, every question of its kind beside it.** The state is `{ <slot>: <reference>, about: <one sentence saying what the picture is> }`, `<slot>` being `chart` for a whole sheet and `crop` for a piece; the sentence names no dress, which would hand Jev the answer.

**The kinds and their questions** (`scripts/still-judge/questions.ts`, word for word below, the live run's wording with `borders_distinct` removed): `sheet` asks `realm_names_read` and `title_reads_first`; `rainfall` asks `realm_names_read`, `rain_lines_lead` and `title_reads_first`; `crop` asks `names_read`. Every question is a Noul whose yes is the chart reading well. Questions in one request are answered each on its own (TypeSafe's primitives: a question cannot see another), so taking `borders_distinct` out of a request leaves the others' state and wording as they were scored.

**The comparison** (`scripts/still-judge/compare.ts`): for a question, the difference is the other version's probability less today's, rounded to hundredths; at 0.12 or more the other version reads better, at minus 0.12 or less it reads worse, and between them there is no difference. No line states one picture's number as a pass, a fail, a yes or a no; the output's last line is the rule, `COMPARISON_RULE`, which `score.md` ends with too.

**The trial's labelled set: four restages.** Each is CSS in a `<style>` element put straight after the sheet's opening `<svg>` tag (k = 1 at the 1500-pixel width):

| restage | issue | fixing commit | before, as restaged | today | kind | question |

| `rain-faint` | #108 | e691a640 | isohyets `#857257` (antique's `inkSoft`), 0.7 px, opacity 0.45 | `#78765f`, 1.0, 0.72 | `rainfall` | `rain_lines_lead` |

**Pairs, and the bar.** Today's twin and its restaged twin share the chart, so the chart's own look cancels out (the clustering that left Issue #1304's comment judge at chance). A pair is won when today's twin reads higher on the defect's own question, half won on a tie. A question is kept when all 30 pairs were answered, at least 0.8 of them were won, and it won at most 0.7 of the pairs of any other restage it was also asked of; the score prints this per row, with how many of today's twins read above 0.7 and how many restaged twins below 0.3, the off-target rows, and the largest re-ask difference.

**`scripts/still-judge/png.ts`** (about 30 lines):

```ts
export const MIN_SIDE = 280;
export const MAX_SIDE = 1568;
export const MAX_BYTES = 16 * 1024 * 1024;
export type PngSize = { readonly width: number; readonly height: number };
export const pngSize = (bytes: Uint8Array): PngSize | null
export const limitProblem = (bytes: Uint8Array): string | null
```

- One dated line directly above `MIN_SIDE`, exactly: `// 2026-11-11, Issue #1309: TypeSafe's image limits (https://docs.typesafe.ai/go/images.md, Limits): each side 280 to 1568 pixels, which also holds the total inside its 78,400 to 2,458,624, and 16 MiB a file; an image outside them is refused, never resized.`
- `pngSize` returns `null` when the input is under 24 bytes, its first eight bytes are not `89 50 4E 47 0D 0A 1A 0A`, or bytes 12 to 15 are not `IHDR` in Latin-1; otherwise `{ width, height }` read big-endian from bytes 16 and 20 through a `DataView` over `bytes.buffer` at `bytes.byteOffset`.
- `limitProblem` returns `"not a PNG"` when `pngSize` is null; `` `${width} by ${height} pixels: each side must be ${MIN_SIDE} to ${MAX_SIDE}` `` when either side is under `MIN_SIDE` or over `MAX_SIDE`; `` `${bytes.length} bytes: a still may hold at most ${MAX_BYTES}` `` when `bytes.length > MAX_BYTES`; `null` otherwise, the checks in that order.

## Calls made

1. **Noul questions only.** Rule: the labels are two-valued, the jaggedness page warns a Score is weak as a magnitude, and the client reads Nouls only.
2. **One request per picture, its image in the state once, every question of its kind beside it.** Rule: the skill's bundling rule and the docs'.
