## The design

The hook becomes three layers, and nothing a Claude session sees changes.

1. **The engine** (`scripts/agent-infra/hooks/engine.ts` and the check modules it calls) knows no harness. It takes a `HookRequest` (`scripts/agent-infra/hooks/request.ts`) and returns a `Verdict`: the first denial in operation order, or else ONE ordered list of notes, each a warning or a due gate. One list, not a list of warnings beside a list of gates, because today's output interleaves them (a shell call pastes its body warnings, then the escape note, then Gate 5, then the browser warning), and a byte-identical note needs that order. `deliver` then turns a verdict into a `Delivery`: it reads each due gate's text from `request.policyRoot`, drops a gate whose text is empty without marking it (as `gateNote` does today), marks each pasted gate shown, and joins the notes with a blank line. Marking happens only in `deliver` and only for an allowed verdict, so context withheld by a denial is never marked shown (plan section 8.2), which for a single operation is exactly today's behavior, since every refusal today returns before any gate is written.
2. **The Claude adapter** (`scripts/agent-infra/hooks/claude-adapter.ts`) is the one place that knows Claude Code: it maps `Edit`, `Write` and `MultiEdit` to a file change and `Bash` to a shell operation, reads `CLAUDE_PROJECT_DIR` (and nothing else in the hook does), chooses the policy root, and wraps a delivery in `hookSpecificOutput`. The caller is `main` when the payload has no `agent_id` and `subagent` when it has one; directory persistence is the payload's `cwd_persists` when present and `unknown` when absent; the engine refuses a bare `cd` unless the caller is a subagent or persistence is `false`, which is today's `agent_id === undefined && cwd_persists !== false` exactly.
3. **The launcher** stays at `.claude/skills/vellum-footguns/hooks/footgun-gate.ts`, the path `.claude/settings.json` registers, so that command never changes. It holds no policy: it calls `runClaudeHook` when it is the entry.

**The policy root (D7, ruled: Rulings, item 1): today's choice, from the adapter's own location.** Today `SKILL.md` and the PR template resolve from the hook file's own directory, which is the checkout whose hook ran, which is `$CLAUDE_PROJECT_DIR` when Claude Code runs the registered command. The adapter reproduces that exactly by taking the checkout it sits in (`resolve(import.meta.dirname, "..", "..", "..")`), since the launcher imports it by a relative path from the same checkout, and passes it to the engine as `request.policyRoot`. The engine reads policy only from there (`skillPath` and `templatePath` in `scripts/agent-infra/hooks/gate-state.ts`).

**State is unchanged:** `<tmpdir>/vellum-footguns-<session_id>.json` (`statePath`, moved verbatim), keyed by the session id alone.

**The selftest and its rows move to `test-support/footgun-gate/`**, where the rulebook keeps the checks' helpers, and are cut into seven files under 400 lines; every printed row name stays byte-identical, since `test/repo/footgun-gate.test.ts` and `test/repo/footgun-gate-cd.test.ts` pin `ok   <name>: want ...` lines. **`hooks/README.md` stays** beside the launcher: `PROSE_ROOTS` in `test/repo/prose-paths.test.ts` and `ROOTS` in `test/repo/memory-pointers.test.ts` walk `.claude/skills` and not `scripts/`, so a moved README would drop out of both scans, and its `DOC_FILES` entry in `scripts/docs-only.ts` would have to follow.

### Alternatives rejected, so the build does not rediscover one

- **The policy root from `CLAUDE_PROJECT_DIR`.** Not today's choice: CI has no `CLAUDE_PROJECT_DIR`, the selftest's cd rows set it to scratch and to home, and the rootless rows run the hook by hand with whatever the environment holds, so the no-template rows and several cd rows would change outcome.
- **The launcher passing its own path for the root.** Two code paths: the selftest calls `decide` in process, with no launcher, and would need the adapter's own default anyway.
- **Gates marked during evaluation.** A later operation's denial would leave an earlier one's gate spent unseen (plan section 8.2).
- **Separate lists of warnings and gates.** Loses today's interleaving; the order rows below would red.
- **Moving `footgun-gate.ts` in the move commit behind a temporary launcher.** Needs a non-mechanical export of its `main` and a second rewrite of paths; its content is split into the engine in commit 5 anyway, where the old path becomes the launcher in one step.
- **New names for `checkBash`, `checkEdit`, `ghRefusal`, `templateRawTexts`, `HEREDOC`, `CLICK_WARNING`, `UNIT_TEST`.** Open errata rows and comments that move with the code name them, and Codex's hook reports a shell call as `Bash` too (Issue #1394's matrix, row X-04), so `checkBash` is no Claude-ism.
- **Converting the selftest's rows into `node:test` files.** The issue keeps the selftest green unchanged in meaning; its rows are the corpus Sub 3 runs through the Codex adapter.
- **A committed golden of whole notes.** It would embed gate text and red on every edit to `SKILL.md`; byte parity is an evidence run instead (Evidence, item 4).
- **`delete` and `move` file changes in this sub.** Nothing here produces one, and their checks (a gate on a deleted test, which path a move is judged under) are Sub 4's to define with its patch decoder; this narrows plan section 8.2's list, as Alex ruled (Rulings, item 4).

import { gateText, rememberGate, shownGates } from "./gate-state.ts";
import type { Delivery, HookRequest, Note, Verdict } from "./request.ts";
import { checkBash } from "./shell-checks.ts";

export const evaluate = async (request: HookRequest): Promise<Verdict> => {
  const shown = new Set(shownGates(request.sessionKey ?? ""));
  const notes: Note[] = [];
  for (const operation of request.operations) {
    const result =
      operation.kind === "shell" ? await checkBash(operation, request, shown) : await checkEdit(operation, shown);

      notes.push(note);
    }
  }
  return { denial: null, notes };
};

export const deliver = (request: HookRequest, verdict: Verdict): Delivery => {
  if (verdict.denial !== null) return { kind: "deny", reason: verdict.denial };
  const texts = verdict.notes.flatMap((note): string[] => {
    if (note.kind === "warning") return [note.text];
    const body = gateText(request.policyRoot, note.gate.label);

    rememberGate(request.sessionKey ?? "", note.gate.key);
    return [`${note.gate.lead} Run this gate before you type; the full skill is \`vellum-footguns\`.\n\n${body}`];
  });
  return texts.length ? { kind: "context", text: texts.join("\n\n") } : null;
};

export const checkBash = async (
  operation: ShellOperation,
  request: HookRequest,
  shown: ReadonlySet<string>,
): Promise<Verdict> => {
  const { command } = operation;
  const cwd = request.operationDirectory.path ?? "";
  const template = templatePath(request.policyRoot);
  const notes: Note[] = [];
  const parts = commandSegments(command);

  for (const segment of parts) {
    const refusal = stashRefusal(segment) ?? perlRefusal(segment, command) ?? ghApiWriteRefusal(segment);
    if (refusal !== null) return { denial: refusal, notes: [] };
    const [ghDeny, warning] = ghRefusal(segment, command, cwd, template);
    if (ghDeny !== null) return { denial: ghDeny, notes: [] };
    if (warning !== null) notes.push({ kind: "warning", text: warning });
  }
  if (REDIRECT_INTO_SCRIPT.test(command)) {
    const bodies = heredocBodies(command);
    const { denial, note } = await escapeScan(bodies.length ? bodies.join("\n") : command, "a script written from the shell");
    if (denial !== null) return { denial, notes: [] };
    if (note !== null) notes.push({ kind: "warning", text: note });
  }
  const moved =
    request.caller !== "subagent" && request.directoryPersists !== false
      ? bareCdReason(command, cwd, request.sessionDirectory ?? undefined)
      : null;
  if (moved !== null) return { denial: moved, notes: [] };
  if (parts.some((s) => GH_PR_WRITE.test(s) || gitCall(s)?.sub === "push") && !shown.has("push")) {
    notes.push({ kind: "gate", gate: { key: "push", label: "Gate 5", lead: "You are about to push or write a PR body." } });
  }
  if (parts.some((s) => /^pkill\b.*(brave|chrom)/i.test(s))) notes.push({ kind: "warning", text: PKILL_WARNING });
  return { denial: null, notes };

import { existsSync, readFileSync } from "node:fs";
import { resolve } from "node:path";
import { deliver, evaluate } from "./engine.ts";
import type { HookRequest, Operation } from "./request.ts";

export type ToolInput = {
  file_path?: string;
  content?: string;
  new_string?: string;
  command?: string;
  edits?: ({ new_string?: string } | null)[];
};
export type Payload = { tool_name?: string; session_id?: string; cwd?: string; agent_id?: string; cwd_persists?: boolean; tool_input?: ToolInput };
type Output = { hookEventName: "PreToolUse"; permissionDecision?: "deny"; permissionDecisionReason?: string; additionalContext?: string };
export type Decision = { hookSpecificOutput: Output } | null;

const POLICY_ROOT = resolve(import.meta.dirname, "..", "..", "..");

const editFragment = (input: ToolInput): string =>
  [input.content ?? "", input.new_string ?? "", ...(input.edits ?? []).map((e) => e?.new_string ?? "")]
    .filter(Boolean)
    .join("\n");

const operationOf = (payload: Payload): Operation | null => {
  const input = payload.tool_input ?? {};
  if (payload.tool_name === "Bash") return { kind: "shell", command: input.command ?? "" };
  if (!["Edit", "Write", "MultiEdit"].includes(payload.tool_name ?? "")) return null;
  const path = input.file_path ?? "";
  return { kind: payload.tool_name === "Write" && !existsSync(path) ? "add" : "update", path, text: editFragment(input) };
};

export const toRequest = (payload: Payload, projectDir: string | undefined, policyRoot: string = POLICY_ROOT): HookRequest | null => {
  const operation = operationOf(payload);
  if (operation === null) return null;
  return {
    harness: "claude-code",
    sessionKey: payload.session_id ?? null,
    caller: payload.agent_id === undefined ? "main" : "subagent",
    directoryPersists: payload.cwd_persists ?? "unknown",
    sessionDirectory: projectDir ?? null,
    operationDirectory: { path: payload.cwd ?? null, provenance: "payload" },
    policyRoot,
    operations: [operation],
  };
};

export const decide = async (payload: Payload): Promise<Decision> => {
  const request = toRequest(payload, process.env.CLAUDE_PROJECT_DIR);
  if (request === null) return null;
  const delivery = deliver(request, await evaluate(request));
  if (delivery === null) return null;
  return delivery.kind === "deny"
    ? { hookSpecificOutput: { hookEventName: "PreToolUse", permissionDecision: "deny", permissionDecisionReason: delivery.reason } }
    : { hookSpecificOutput: { hookEventName: "PreToolUse", additionalContext: delivery.text } };
};

export const runClaudeHook = async (): Promise<void> => {
  try {
    const result = await decide(JSON.parse(readFileSync(0, "utf8")) as Payload);
    if (result) process.stdout.write(JSON.stringify(result));
  } catch {
    /* a malformed payload or a missing SKILL.md fails open */
  }
  process.exit(0);
};
