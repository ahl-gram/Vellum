## The design

Each recipe becomes two plain reads of the sandbox's commit, then one run call that keeps its `cd`:

```bash
cat /the/path/create/printed/.git
cat /the/directory/that/gitdir/line/named/HEAD
cd /the/path/create/printed && pwd && npm test
```

Every mention of git leaves the run call, so whatever an agent adds to it passes (T6), and the reads hold no command substitution and no `sed` (C1, C2). The `cd` stays with the run, so the run happens in the sandbox or not at all, and `pwd` prints the directory it ran in: that is the witness replacing the old "read inside the sandbox" claim. The fence list has one home, `CLAUDE.md` Worktrees, holding the 2026-09-13 list, the new fact, and that a dispatched agent stands in its dispatcher's fence; the skeptic, prover and implementer point there and keep only their own instructions.

Rejected:

- The issue's three calls with the `cd` alone: unsafe (T0); ruled out (Rulings).
- The one-call recipe kept with a warning against `$?` (D1 option B), and an `agent-sandbox.ts head <name>` command (option C): not ruled (Rulings).
- `npm --prefix <path> test` (NP passes): the prover runs `node --test`, which has no such flag, and the skeptic's Copies and Comment sweeps bullets already use `cd <literal> && ...`; one form for all.
- The Read tool for the two reads (RD passes): Calls made, 2.
