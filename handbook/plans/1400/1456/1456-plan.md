## The design

Alex's rule replaces a threshold. Today a red on CI gets a row in the flake record before its one re-run, and the step is skipped under an issue only at its third counted CI row (settle-doctrine item 12). From this change:

1. **What shows a flake (D1, ruled "Keep the one retry").** A red on GitHub's machines, in a run of the CI workflow or in an unmutated control of the proof runner, that the Mac and runner list does not explain (item 15) and that the Mac run does not reproduce, is re-run once, alone, as today. If that re-run passes, the check is shown to flake: at that first time, its step goes into `E2E_SKIPS` (`e2e/support/skips.ts`) and an issue is filed under the roadmap board's Flakes phase, with no offer first and no count of earlier reds. A re-run that reds again is a defect, as today.
2. **The trail moves from the row to the issue (D2, ruled "Close it").** The PR comment Gate 2 item 10 already asks for is posted before the re-run (it replaces the row as the thing written first), and the Flakes issue holds what a row held. The flake record is closed in place: it takes no new row, keeps every existing row at its path (so every citation of it stays valid), and an existing row still takes its disposition when its check is settled or deleted.
3. **Unit tests (D3, ruled "Issue only").** No skip list reaches them, so a unit test shown to flake gets its Flakes issue the same way and stays in the run until the issue is fixed; a further red adds its payload to that issue as a comment.
4. **The skip at a first flake rides the dispatcher's own small pull request.** The lane's pull request is green once its re-run passes, and a lane never edits `e2e/support/skips.ts` unless its plan names it (item 11), so the orchestrating session files the issue and opens a pull request adding the entry (with item 11's later-check waits), in place of today's pull request that only added a row.
5. Routes that are not "a flake" stay as they are: an explained red is rewritten (item 15), a red on a check already rewritten once is pulled out with no re-run (now under a Flakes issue), and a red the Mac reproduces is the lane's defect.
6. **The rule binds from the merge (D4, ruled "From now on").** No `E2E_SKIPS` entry is added and no issue is filed for a check already shown flaky (RB15, L10, EZ2, EZ1); each goes the new way at its next failure.
7. **Gate 2 item 10 changes as ruled and the Issue #591 freeze otherwise stands (D5, ruled "Change the line, keep the held clause").** `held-lines.md`'s "How a line leaves" paragraph and its "Held, not declined" section stay as they are.
