## The design (ruled: D1 option A, D2 option A)

**A page meant to come back rebuilt is evicted from the back/forward cache by a channel message.** Before the page is left it opens a `BroadcastChannel` with a listener; once the page it went to has loaded, that page posts one message on the same channel and closes its end; then the Back runs. The browser cannot deliver a message to a page it has frozen, so it discards that page, and the Back rebuilds the document with navigation type `back_forward`. Two exported functions in a new `e2e/support/cold-back.ts` hold the two halves, and PB18's `backHome` and CD38's `cd38BackRebuilt` call them where today they register the empty `unload` listener. Both checks already assert their premise (the marker gone, the navigation type `back_forward`), so a browser that ever restores the page anyway reds the check rather than measuring the cached road twice; nothing else in either check changes. Both `E2E_SKIPS` entries are deleted.

**Rejected, with the reason** (each measured; table above; D1 options B, C and D and D2 option B were on the menu and not chosen):
- **Leaving both checks skipped** (D1 option D): every claim PB18 and CD38 hold (T1 and T2) would stay unprotected.
- **The helpers as two more exports in `e2e/support/nav.ts`** (D2 option B): its one-line header, about a hop through the empty page, would have to cover two subjects.
- **Re-allowing the `unload` listener through a `Permissions-Policy` header** (D1 option B): it works today on both browsers, but it keeps the checks on the very listener whose retirement broke them, and it needs a new switch in `e2e/site-server.ts`.
- **Clearing the browser cache before the Back** (D1 option C): harness-only, but unbounded in time on Brave (up to 69.6 s on one road), and it clears the HTTP cache under every later suite in the lane.
- **Keyboard lock**: Brave, the browser `findBrowser` in `src/cli/raster.ts` picks first on a Mac, has no `navigator.keyboard`, so every local run would throw.
- **A critical memory-pressure signal**: it turns the cache off for the rest of the run, so CD37 and PB18's cached half would arrive cold.
- **`Cache-Control: no-store` plus a cookie**: cold on both, but needs a server switch and leaves a cookie behind for every later check; the channel needs neither.
- **The other features** in the table leave the page cached on Chrome 158 and Brave 158.
- **Splitting PB18 so only its cold arm waits**: no longer needed; the restore returns the whole step.
- **A unit test of the helper**: it could only restate the two payload strings. The browser checks are the helper's guard, and the prover's rows M1 to M4 delete each call.
