## The design

The design #1440's body proposed for the deleted script, carried to its successor: the `import.meta.main` block's logic moves into an exported function a unit test can call, and the block keeps one assignment. It narrows the unguarded part from the `catch`'s logic to that one assignment; it does not close it, and the test names that blind spot.

Rejected:
- **Re-creating `scripts/deploy-browser.ts` so the body's own test can be written.** It reverses Alex's Q6 ruling on Issue #1255, and the ruling on this issue says the deleted script is not re-created.
- **A test that spawns `main.ts`.** It is the only form that pins the block itself, but it costs 12.67 s a run on this Mac for one line (the probe above), and it can reach only the press-failure branch, never the no-browser one, because `findBrowser` falls back to whatever browser the machine has.
- **Pinning the `catch` by reading `main.ts`'s source text.** `handbook/specs/check-placement.md` (The unit suite) forbids a unit test that opens a source file and searches its text.

### Before and after (`scripts/build/primer-pictures/main.ts`, lines 88 to 100 at f92442a2)

Before:

```ts
if (import.meta.main) {
  try {
    await writePictures(resolve(process.argv[2] ?? GENERATED), {
      env: process.env,
      find: findBrowser,
      press: pressPictures,
      log: (line) => console.log(line),
    });
  } catch (err: unknown) {
    console.error(err instanceof Error ? err.message : err);
    process.exitCode = 1;
  }
}
```

After:

```ts
export interface RunDeps extends PictureDeps {
  readonly error: (reason: unknown) => void;
}

export async function runPictures(root: string, deps: RunDeps): Promise<0 | 1> {
  try {
    await writePictures(root, deps);
    return 0;
  } catch (err: unknown) {
    deps.error(err instanceof Error ? err.message : err);
    return 1;
  }
}

if (import.meta.main) {
  process.exitCode = await runPictures(resolve(process.argv[2] ?? GENERATED), {
    env: process.env,
    find: findBrowser,
    press: pressPictures,
    log: (line) => console.log(line),
    error: (reason) => console.error(reason),
  });
}
```

`RunDeps` and `runPictures` sit directly after `writePictures` (which ends at line 86), before the `import.meta.main` block; lines 1 to 86 are unchanged. The file goes from 100 lines to 110 (`wc -l` of the after-file). `error` takes `unknown` so a throw that is not an `Error` reaches `console.error` exactly as today.

Measured: the whole after-file, written to the scratchpad with lines 1 to 86 byte-identical to main's (`diff` of the two heads printed nothing), passes the repo's lint under the real file's name: `eslint --flag unstable_native_nodejs_ts_config --max-warnings 0 --stdin --stdin-filename scripts/build/primer-pictures/main.ts < 1440-after.ts`, exit 0.
