## The design

Retire the routine the way Issue #1087 retired the plan skeptic (`b8ad1bbc`): the files move byte for byte into `handbook/retired/`, out of every place a session reads as live; every live mention goes; one tombstone line in the rulebook's "Retired rules" says when, why, where the files went and how to restore them; and a unit test refuses a live mention coming back.

1. **The spec and its setup script move, unchanged, into the archive**: `git mv handbook/specs/cloud-routine.md handbook/retired/cloud-routine.md` and `git mv scripts/cloud-setup.sh handbook/retired/cloud-setup.sh`. Measured: both moves show as 100% renames, and the script keeps its mode 100755 (`git diff --cached --summary HEAD`, `git ls-files -s handbook/retired/` in the spike). The archived spec's own text still names `scripts/cloud-setup.sh`; it is an archive and is not edited, and `handbook/retired/` is outside every root `test/repo/prose-paths.test.ts` walks.
2. **Every live mention goes**, by the exact edits under Files, in `CLAUDE.md`, three specs, the planner's role body (then `npm run agents:generate`), one test-support comment and one test fixture string.
3. **The tombstone** is one new physical line in `handbook/specs/rulebook.md` directly after the plan skeptic's tombstone line.
4. **The guard**: `test/repo/retired-agents.test.ts` becomes `test/repo/retired.test.ts`, the register of everything retired, driven by one table with a row per retirement (the plan skeptic, the cloud routine). It is strengthened on the way: it now reads `.claude/skills` (bar each skill's `references/` folder) and `README.md` as well, it exempts only each retirement's own tombstone line rather than the whole rulebook, it catches a mention wrapped across two lines, and it proves its patterns against one listed spelling per arm.

Rejected:
- **A sibling test file for the cloud routine beside `test/repo/retired-agents.test.ts`.** Its scan would be the plan skeptic's written a second time, which `npm run copy-hunt -- diff` reports at the cold review (workflow step 14). One register of retirements matches the rulebook's one "Retired rules" section.
- **A shared helper in `test-support/` used by two test files.** Two files and a helper where one table does the same job.
- **No guard at all.** Issue #1087's retirement added one, and a mention coming back is exactly the silent drift `CLAUDE.md` warns of: nothing in the repo sweeps a claim in markdown.
- **Keeping the rulebook-wide exemption.** It would leave the rulebook's sibling paragraph and companion footer, two of this plan's own edits, unguarded (mutation MC below reds only under the line-scoped exemption).
- **A pattern of plain `cloud`.** It would red on any future mention of the sky (the prospect plates draw clouds) and on the near misses (mutation CR8 below).
- **Leaving the setup script in `scripts/`.** The rulebook's "What `src/` holds" names it as the one non-`node` command, pasted into a cloud environment that will no longer exist; kept there, it is a live command for nothing.

One module-level helper, its body the implementer's:
```ts
function mentionsIn(file: string, r: Retirement): string[]
```
It reads `file` (repo-relative) as text; when `file` is `TOMBSTONE_FILE`, it first replaces every line that starts with `r.tombstone` by an empty string, keeping the line count; it returns one `"<file>:<line>: <r.what>"` per match of `[...text.matchAll(r.names)]`, `<line>` being the count of newlines before the match plus one. Match with `matchAll` only, never `.test()`: the patterns are global and `.test()` carries `lastIndex` from one call to the next.
