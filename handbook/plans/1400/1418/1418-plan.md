## The design (Q1: B, Q2: B, Q3: A)

The build works in **its own clone** of the repository, with its own `.git` folder and today's full access, and **the session never runs git inside that clone**: after each run the wrapper fetches the build's branch from it by path into the main repository and moves a **review tree** (a linked tree of the main repository, at today's path `.claude/worktrees/codex-<issue>`) to it. Everything after the run (the push, the guard prover, the pull request, the retire) works on the review tree. A build's ordinary git commands (a config line, a hook an installer writes) land in its own clone, where nothing of the session reads them except the fetch, which measured inert (measured 1). A build that sets out to can still write anywhere in Alex's home folder, the main repository's `.git` included (accepted by the ruling).

- **The clone** is `.claude/worktrees/codex-build`, one fixed path, so the hook's trust is given once (measured 9). One Codex build at a time: `build` refuses while another issue's live record holds the clone.
- **Making it** (`build`, before Codex starts): `git -C <root> fetch origin`; read `origin/main`'s sha; remove the old clone with `rmSync` (measured 8); `git clone -q --no-hardlinks --no-checkout <root> <clone>` (its own object files, none shared with the main repository); in the clone, `git remote set-url origin https://github.com/ahl-gram/Vellum.git`, `git update-ref refs/remotes/origin/main <sha>`, `git checkout -q --detach <sha>`; then link `node_modules` as today (`../../../node_modules`, which resolves from `.claude/worktrees/codex-build`).
- **The run** is today's: `buildArgv` and `resumeArgv` unchanged, D2's flags, the clone as `-C` and as a resume's working folder, `buildEnv` unchanged. The build still writes its record files into the record folder `out/<issue>-handoff/`, as today.
- **Collecting a run** (`collect`, after every `build` and `resume`): `lstat` the clone's `.git` (a directory, not a link or a gitfile) and its `HEAD` (a regular file of at most 4096 bytes); take `refs/heads/<branch>` from its text only when `isIssueBranch(branch, issue)`; `git -C <root> fetch -q --no-tags <clone> +refs/heads/<branch>:refs/handoff/<issue>`; if the review tree is absent, make it with `createPlan(tree, "refs/handoff/<issue>", true)` (detached, `node_modules` linked) and then `git -C <tree> switch -q -c <branch>`; if present, `git -C <tree> merge -q --ff-only refs/handoff/<issue>`. A failed step adds its first error line to the problems the wrapper prints, and leaves the review tree as it was.
- **The prompt** names the clone as the build's own clone and the hook check's new ending: a hook check that is not refused ends the run with `OUTCOME: hook`, since the hook's trust is keyed by path and the clone's first build meets an untrusted hook.
- **`next`** reads the branch, heads and pull request from the review tree as today; gains the `trust` step (the run ended `OUTCOME: hook`: Alex opens Codex once in the clone and trusts the hook, then the session resumes); prints the push as `git -C <tree> push -u origin <branch>` (Q3); and retires the review tree and `refs/handoff/<issue>`, leaving the clone for the next build to replace.

### Rejected

- **Options A, C and D**: not taken (comment 7089981355).
- **The clone's git folder kept beside it** (`--separate-git-dir`): only option A's sandbox needed a writable root not named `.git`. Under full access a `.git` inside the clone is the plain shape, and `readSlotBranch` refuses a gitfile there, so the session reads a git folder the wrapper made.
- **`node_modules` copied into the clone**: only option A's sandbox needed it (the site build failed through the link under the sandbox). Under full access the link works, as for today's tree.
- **The build's record files moved into the clone, copied out by the wrapper**: only option A needed the record folder kept out of the build's reach. Under full access the build can write that folder whatever the prompt says, and today's prompt already writes there.
- **The browser checks moved to the session**: under full access the build opens local ports and runs them itself, as today.
- **Sandbox flags, `-a never`, `--ignore-rules`, the extra writable root and the three-turn sandbox probe**: option A's alone (Calls made, below).
- **Taking the work back by a bundle the build writes**: it adds a step the build must remember; the fetch by path measured inert.
- **A clone per issue**: every build would wait on Alex trusting the hook by hand at a new path.
- **A shared (hardlinked) clone**: faster, but it shares object files with the main repository; the ruling asks for the build's own git folder, and `--no-hardlinks` costs 1.64 s.
