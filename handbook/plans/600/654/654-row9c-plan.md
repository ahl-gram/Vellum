## How each function splits

Row 9a's K5, unchanged: consecutive phases become module-level helpers **in the same file**, above the function they serve, each taking what it reads and returning what the next phase reads; **the named function keeps its name, signature and file**, so every citation holds (`atlasDocument` in `plans/654-row7-9-plan.md` and `errata/prose.md`; `src/atlas/document.ts` by path in `specs/rulebook.md`, `specs/site-architecture.md` twice and `specs/ui-design.md`, each about a constant or a markup property that stays in that file; `src/cli/main.ts` by path in `specs/engine-invariants.md` and as the lint wiring's witness file; `stripFor` in `src/itinerary/dress/layout.ts` in `specs/engine-invariants.md`, untouched). **No new file**: the largest file, `foreground.ts`, measures 364 lines in a scratch sketch of the split below (`654-9c-sketch/`, taken after this plan's first draft; every sketched file is under 400), so no sibling is needed and none is planned (plan skeptic 8: the first draft's `foreground-land.ts` fallback would have had to import `scatter`, `cxOf` and `width` back from `foreground.ts`, a cycle).

**The five rules every split keeps** (9b's, with 9c's weight on the first two):
- **Order is behaviour.** Draws, emitted order and the order a caller's callback is called in stay in base order; a helper is called where its code ran. `atlasDocument` calls the caller's `plateSrc` for the draughtings, themes, regions and prospects, then the hero; the sweep records that order, so a helper that frames the hero first reads different.
- **No random draw is added, removed or reordered, on any stream.** This row draws on handed streams throughout: `composeProspect` hands `rGeo` to `composeTownscape` and `rDecor` to the land dressing, the sea or river front, the collapse field and the birds, in that order, with `rDelight`'s one serpent draw between the collapse field and the birds; `composeTownscape` draws in `packRow` twice, then per spire (a slot, a form only after the first, a width, a height, and a broken draw ONLY when ruined, since `ruined && rng.next() < 0.8` short-circuits), then the keep's broken draw only when ruined; `composeLandDressing` and `composeSeaFront` draw inside object literals and `scatter` callbacks whose FIELD order is draw order. A helper that draws is handed the stream the base drew from at that point and keeps every short-circuit and every field order. **Two sites no instrument can check** (plan skeptic 3): a draw added at the END of a stream nothing reads afterwards moves no output, and there are two such ends, the keep's broken draw (the last draw on `rGeo`, whose only reader is `composeTownscape`) and the serpent's one draw on `rDelight`; at those two the rule rests on reading the diff, and the PR says so.
- **A helper returns a new value and writes into nothing it was handed.** The base's `out` arrays filled by `push` become arrays each helper returns and the caller concatenates in the base order; `composeTownscape`'s `let masses` and its `map` become one expression. The scratch syntax-tree scan (`654-9c-mutscan.ts`, 9b's re-keyed scan) is run at base and head and must report no NEW hit.
- **Every helper meets the size rules itself** (50 lines, depth 4).
- **Arithmetic moves verbatim**: the same operands in the same grouping. `654-9c-arith.ts` (9b's tool, copied) lists every arithmetic expression of the nine files with no identical partner at the other root, and each is read; in `layoutRibbon` the `overlap` and `latMax` values feed only a comparison and a clamp, where a regrouping can hide from the byte sweep.
