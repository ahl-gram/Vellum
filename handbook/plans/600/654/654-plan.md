## Row 1 in detail: the any-typed reads, the unused names and the stray markers

### Design

Every fix is erasable (a type annotation, an `as` from `any` or `unknown` to the shape the code already relies on, a type argument, `import type`), except the runtime edits enumerated here, each of which runs the same:

1. `void` before the three fire-and-forget calls the Correctness comment names (`runTurn(...).then(...)` in `src/site/explorer/app.ts`, `plateFor(world, s)` in `src/site/reading-room/prospect-stage.ts`, `document.fonts?.ready.then(layout)` in `src/site/shared/room.ts`, whose trailing marker keeps `no-unnecessary-condition` alone). An expression statement discards its value; `void` evaluates the operand and discards it. Same behaviour.
2. `scripts/e2e/harness.ts`, `startServer`: the async request handler is wrapped in place, `createServer((req, res) => { void (async () => {` on the line that opens it today and `})(); });` on the line that closes it, so the handler's body and its note stay where they are and the file gains no line. A rejection stays unhandled exactly as it is today.
3. `scripts/e2e/harness.ts`, the socket's message handler: the statement `m.error ? w.reject(...) : w.resolve(...)` becomes `if (m.error) ... else ...` on the same three lines (the `if` on the first, the `else` opening the third), so its two notes stay above the lines they cover and each still covers one objection.
4. `scripts/e2e/suite-zoom-gestures.ts` (ZG4): `cx = ..., cy = ...` becomes two statements.
