## The design

**Three tracked trees and one generated one, after this pull request.**

- `src/styles/` holds every sheet at the path it is served from: `index.css` and `home-noscript.css` (home's), the eight sheets every page links, and one folder per page with a sheet (`explorer/` with `index.css`, `broadside.css`, `chart-drawer.css` and `portfolio/index.css`; `faq/`, `glossary/`, `print-room/`, `prospect/`, `reading-room/`, `ribbon/`, `seed-of-the-day/`, `specimen/`, each `index.css`).
- `src/static/` holds `charts/` (the seven committed SVGs), `favicon.svg`, `apple-touch-icon.png` and `og.png`, at the paths they are served from.
- `generated/` is Astro's public folder (`publicDir`): what `npm run astro:generate` writes (the bundle twins and chunks, `fonts/`, `atlas/`, `gallery/`, `sitemap.xml`, `robots.txt`, `llms.txt`), ignored by one line, deleted whole and rebuilt at the start of every generate, and never tracked.
- `public/` no longer exists. `dist/` is the built site, as today.

**The two source trees reach the built site through one Astro integration and the dev server reads them in place.** `servedSources` in a new `scripts/served-sources.ts`, registered in `astro.config.ts`, over `SERVED_SOURCES`, a list of `{ dir, types }` where `types` maps the extensions a source keeps to their content types: `src/styles/` keeps `.css`, `src/static/` keeps `.svg` and `.png`.

- `astro:build:done` copies every file of a kind its source keeps to the same path under the built directory (`dist/`, or a test's `outDir`), and nothing else: a `.DS_Store` (34 sit in the main checkout's tree outside `node_modules/` and the worktrees), a swap file or a note stays behind. It refuses to overwrite a path the build already holds (`COPYFILE_EXCL`), so a source file and a generated file claiming one address fail the build.
- `astro:server:setup` adds a dev middleware: a request with no `..` whose extension a source keeps and whose file exists under that source is answered with the file's current bytes and that source's content type; anything else passes on to the generated folder and the routes.
- The committed files never travel through `generated/`, so a build that skipped `astro:generate` loses only generated files, as today, and Astro's silent skip of a missing public folder (recon ledger 2) can never drop a chart or an icon.

**The build-output folder.** `GENERATED = "generated"` is exported from `scripts/clean-generated.ts` (today's `scripts/clean-public-generated.ts`, renamed): `cleanGenerated(root)` deletes `root` whole and refuses any `root` whose last segment is not `generated`, so no argument can make it delete another folder. The four generators and the clean take `GENERATED` as their default root; `astro.config.ts` sets `publicDir` to it and points the Issue #204 dev middleware's `PUBLIC_DIR` at it. `GENERATED_SUBTREES`, its tombstone and the per-file ignore lines retire, and with them every check that guarded the list (ruling 3 of comment 4).

### Alternatives rejected

- **A copy step in `astro:generate` writing the sources into `generated/`** (the `scripts/kit-fonts.ts` precedent): the committed files would then depend on generate having run, the dev server would serve a stale copy until the next generate, and the three pins of the generate string would move twice.
- **Folder moves** (`git mv public/explorer src/styles/`): on a built tree they carry the ignored bundles along (measured on the first trial). Sheets move per file; only `public/charts/`, which holds nothing generated, moves as a folder.
- **Keeping `GENERATED_SUBTREES` for the clean** (the second menu's option b): ruled against.
- **Resolving a prose served address through `generated/` when no source holds it**: every such address would pass, since the folder is ignored whole.
- **A refusal of non-sheet files in the copy**: Finder's `.DS_Store` would break every local build.
- **Splitting the over-cap files** (`test/site/astro-scaffold.test.ts` at 1167 lines, `test/repo/lint-wiring.test.ts` at 671): edited in place and grown by at most a line, as PRs #904, #893 and #892 did.

### New file `scripts/served-sources.ts` (about 75 lines; its shape ran on the second and third trials)

```ts
import type { AstroIntegration } from "astro";
export type ServedSource = { readonly dir: string; readonly types: Readonly<Record<string, string>> };
export const STYLES = "src/styles";
export const STATIC = "src/static";
export const SERVED_SOURCES: readonly ServedSource[];
export const REPO: string; // fileURLToPath(new URL("..", import.meta.url))
export const sourceFor = (repo: string, sources: readonly ServedSource[], pathname: string): { readonly file: string; readonly type: string } | null;
export const copySources = async (repo: string, sources: readonly ServedSource[], to: string): Promise<readonly string[]>;
export const servedSources = (repo: string = REPO, sources: readonly ServedSource[] = SERVED_SOURCES): AstroIntegration;
```

- `SERVED_SOURCES` is `[{ dir: STYLES, types: { ".css": "text/css; charset=utf-8" } }]` from commit 2 to commit 4, and gains `{ dir: STATIC, types: { ".svg": "image/svg+xml", ".png": "image/png" } }` in commit 5.
- `sourceFor`: `null` if `pathname` contains `..`; otherwise the first source whose `types` holds `extname(pathname)` and under which `join(repo, source.dir, pathname)` is an existing regular file, as `{ file, type }`; `null` when none. `pathname` arrives without its query and still percent-encoded, so `..` is the only way out of a source.
- `copySources`: for each source in order, reads `join(repo, source.dir)` recursively, takes the regular files whose extension its `types` holds, and for each in sorted order creates its folder under `to` and copies it with `copyFile(..., constants.COPYFILE_EXCL)`; resolves to the sorted, `/`-separated relative paths of everything it copied.
- `servedSources`: `{ name: "vellum-served-sources", hooks: { "astro:server:setup": ({ server }) => { server.middlewares.use(<middleware>); }, "astro:build:done": async ({ dir }) => { await copySources(repo, sources, fileURLToPath(dir)); } } }`. The middleware takes `sourceFor(repo, sources, (req.url ?? "").split("?")[0] ?? "")`; on `null` it calls `next()` as a statement and returns (the returned form fails `@typescript-eslint/no-confusing-void-expression`); otherwise it reads the file and ends the response with it and the found `Content-Type`, calling `next(error)` on a read failure.
- Under `scripts/` because `astro.config.ts` is in neither the lint nor the type check; `scripts/lint/sheet-tokens.ts` importing `STYLES` from it passed check, lint and the lint-wiring and package-imports tests (probe).
