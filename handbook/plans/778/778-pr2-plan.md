## The design

**One class on the root decides the frame, set once as the room binds.** `bindRoom` in `src/site/shared/room.ts` is the one call every staged chart room makes, and only they make it. Its first statement toggles the class `desk-frame` on `document.documentElement` when `deskFrameDue(window.visualViewport?.scale ?? 1)` holds, that is when the page boots set small to fit the screen. Nothing reads the scale again: a pinch moves the scale past 1 (measured), and a reread would drop the frame mid-visit.

**The page box reads the frame.** `pageBox()` in `src/site/shared/page-box.ts` returns the frame's height while the root carries the class, read from the token `--desk-frame-h` the way `slipWidth` reads `--slip-w`, and the root's client height otherwise. Every caller (the fit in `fitRoom`, the seats in `room-seats.ts`, the Explorer's drawer band) therefore lays the room out at 768 with no change of its own.

**Every vertical seat read is in page coordinates.** Issue #762's pull request C put every horizontal read on the page (`pageLeft`, `pageRight`) because a narrow window scrolls the 1024 page sideways; the frame scrolls the page down, so `pageTop` and `pageBottom` join them, and the four vertical reads that place a piece take them: `tops` and `bottoms` in `room.ts` (the fit's reserves), and `placeSlip` and `placeLegendRow` in `room-seats.ts`. Unscrolled the two forms are the same number, so nothing on a desktop moves.

**The sheet frames it.** In `public/atelier.css`, inside a screen media block, `html.desk-frame:has(body.chart-room)` lets the root grow to its content, scroll, and paint the desk in `--chart-ink`, and `html.desk-frame body.chart-room` takes the token's height. The body's `contain: layout` (cascade-traps) already makes the body the containing block of every fixed piece, so the stage, the corners, the Glass, the fog and the vignettes all stand in the 1024x768 box with no rule of their own; and because that containment also keeps the body's own ground off the canvas, the desk is painted on the root.

**The notice keeps its seat above the screen's foot.** The notice is fixed inside the contained body, so in a frame taller than the window it would stand at the frame's foot, below the screen. The frame's root rule sets `--desk-lift: max(0px, var(--desk-frame-h) - 100svh)`, and the notice's own `bottom` adds `var(--desk-lift, 0px)`: sideways that lifts it 294 to the window's foot, upright it is 0 and the notice stands at the frame's foot. `100svh` is the window with the browser's bars shown, so the note never sits under them.

### Rejected, with the reason (do not rediscover these mid-build)

- **A desktop window taller than 4:3 framed, as the PR 1 spike drew one:** ruled out by ruling 3 (rulings 9 and 10 name a phone, and that spike framed a 1024x1100 desktop window only because its arm keyed on the window's shape on any device).
- **The frame wherever touch is the main pointer, in CSS alone (`@media (hover: none) and (pointer: coarse)`):** ruled out by ruling 1, which took B over it (an 1180x820 tablet then scrolls 56 and its Glass starts below the screen, and six more browser suites that emulate touch on a desktop-sized window, broadside at 1024x700, chart-drawer at 1024x844, reading-room at 1024x800, cards at 1280x800 and its kit sizes, and the cluster's trail at its narrow width, would lay out the frame and owe a re-read each).
- **The Notice to Travellers' own test (`noticeDue`, a page set small AND a screen under 1024 tall):** ruled out by ruling 1, which took B over it (an upright tablet keeps the tall layout ruling 9 replaced).
- **Re-reading the scale on each layout:** measured, a pinch past full size then drops the frame and floors the sheet.
- **A 768 literal in TypeScript beside one in CSS:** two homes for one number; the token is the one home, `pageBox` reads it (`ui-design.md`: derive from the token, never from a literal), and `vellum/css-var-declared` needs the token declared in a sheet anyway.
- **The deep's gradient painted on the root below the frame:** measured, a visible step at the frame's foot (1.229) where flat chart ink is seamless (1.001); the stills ruling 9 was taken from showed flat ink.
- **Restructuring the default root rule as `html:has(body.chart-room):not(.desk-frame)`:** it would raise that rule over the print stand-down (`@media print` adds no specificity) and break print; the frame's rule is an override scoped on its own state, inside `@media screen`, which `cascade-traps.md` names as the form that fights nothing.
- **Overriding the notice's `bottom` in a frame rule:** a second copy of the notice's seat; the lift custom property leaves the seat written once.
- **A pre-paint inline script to set the class before first paint:** `site-architecture.md` keeps such a script a re-ratified exception, not a licence to add more; see Calls made 12.
- **The page-coordinate fix for the Chart Table's mouse drag (`table-drag.ts`):** see Calls made 11.
- **Exempting the Print Room from the frame:** ruled out by ruling 2.
