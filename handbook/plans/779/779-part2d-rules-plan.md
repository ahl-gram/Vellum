## The file key

Every rule maps `context.filename` to a key: a sheet's repo path with `public/` dropped (`motion.css`, `explorer/broadside.css`, the form the lists use today), and a built source's virtual path `<source>.css` to `<source>` (`src/cli/gallery.ts`). An exception list entry is `<key> :: <selector>`.

## The rules

Each is a `CSSRuleDefinition` over the CSSTree AST like `vellum/css-no-narrow-width`. Every value node of type `Raw` is re-parsed as a value before it is read (measured at `c1b8a7cd`, 21 sheets: 233 `Raw` nodes, 80 of them custom-property values and the rest inside declarations, chiefly `var()` fallbacks; the only two outside a declaration are the `(root)` arguments of `::view-transition-old` and `::view-transition-new` in `public/motion.css`, which no rule keys on, so no selector a rule reads is unparsed), so a colour in a custom property's value or in a fallback is read. A `Raw` value css-tree cannot re-parse (it throws, `onParseError` or not; the tolerant plant in `test/repo/css-comment-form.test.ts`, `if(style(--x: 1): 2px; else: 3px)`, is one) is caught and skipped, a miss declared at each rule's test, since the family parses tolerant (Issue #648) and a rule that threw would crash the lint; every `Raw` node in the sheets and the built CSS re-parses today (the plan skeptic's probe: 294, none failing). A hash is compared case-insensitively, a three- or four-digit hash expanded first, an eight-digit one by its first six. A selector's text, where a key or an exact arm is compared, is the prelude's source text with comments dropped and whitespace collapsed, the form the lists are written in today.
