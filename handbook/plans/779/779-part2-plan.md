**Design.**

- **The suite map leaves the runner, typed by the roster.** `SUITES` moves from `e2e/run.ts` into its own module, written `satisfies Record<E2eSuiteName, ...>`, so a missing or an extra name is a type error (`handbook/specs/check-placement.md`: make the wrong state unrepresentable first); the runner's run-time `missing` FAIL then guards nothing and goes. Its key ORDER is not the run order (`runSelected` walks the selection, which `canonicalise` filters from `E2E_SUITE_ORDER`, `e2e/support/suites.ts`), so a swap of two keys changes no behaviour and no test pins it; the true half of the comment above `SUITES` (render needs the pristine boot first, health's N1/N2 read the state everything before it left, a selection is filtered to this order) moves to `E2E_SUITE_ORDER` as one line. Measured: importing all 32 suite modules in a plain Node process takes about 60 ms, leaves no live handle and exits 0 (`779-import-probe.ts`, and the skeptic's own run).
- **The runner becomes a function with its effects handed in, and it never exits.** Everything `e2e/run.ts` does at module level (resolve the site, the ports, the out directory and the selection, apply the browserless policy, start the harness, run the selection with its three hooks, print the report) moves into one exported `runE2e(io)` that RETURNS the exit code on every path (a bad port or selection 1, the browserless FAIL 1, the SKIP 0, the outcome 0 or 1, the harness error 2), built from functions each under 50 lines. `io` carries `env`, `isTTY`, `findBrowser`, `start`, `cleanup`, the suite map, the two output sinks, and the four accumulators (`results`, `consoleErrors`, `http4xx`, `skippedGroups`), which stay declared in `e2e/run.ts` so `vellum/e2e-console-read-through-drop`'s owner list (`OWNERS` in `scripts/lint/source-shape.ts`, which names `e2e/run.ts`) stays true and neither listed file moves (measured by the skeptic: the runner's text linted at an `e2e/support/` path reports the `consoleErrors` hand-off). The binding to the process (`env: process.env`, `isTTY: Boolean(process.stdout.isTTY)`, the real `findBrowser`, `start` and `cleanup`) is itself an exported function in the module, `runE2eFromProcess(deps)`, whose `deps` a test replaces with fakes while `process.env` and `isTTY` stay the real ones; so a mutant that drops the `env` binding is caught in-process with a fake browser, and can never launch a real one. `e2e/run.ts` keeps the accumulators, one call and its `process.exit`. Paths resolve from the repo root, not from the module's own directory, since the module sits one level deeper.
- **The lane driver the same way.** `e2e/lanes.ts`'s sequence (resolve the lane from argv, refuse an ambient selection, the browserless gate, spawn `process.execPath` on the runner per lane, stream and read the lines, aggregate) becomes `runLanes(io)`, returning its code, with `spawn`, `findBrowser`, `env`, `isTTY` and the sinks handed in; `e2e/lanes.ts` keeps one call and its exit.
- **A check that changes the browser undoes it itself.** CD50's check (`cd50ScriptsOffHome` in `e2e/suites/chart-drawer/portfolio.ts`) turns page scripts off through a helper that runs its body and turns them back on in its own `finally`, swallowing a failed restore so the body's error survives, the shape `onFixedDay` in `e2e/support/fixed-day.ts` already has; the `.finally(scriptsBackOn)` at the step goes. DN7's refusal becomes one call that arms, runs and disarms (`dnRefused` calls it; `arm` and `disarm` stop being separate exports), and DN4's `dnContinue` forgets the dismissal in its own `finally`. The cleanup can then not be forgotten at a call site, because there is none. The injected-script class (DN7's) is held by convention, declared: its two other sites (`e2e/support/fixed-day.ts`, `e2e/suites/corners/top-row.ts`) already clean up in a `finally`.
- **Menu item 3 option A, the class:** no e2e file names `Emulation.setScriptExecutionDisabled` but the helper's, held by a new house rule in its own file under `scripts/lint/` that exempts its home by `context.filename` (the `OWNERS` pattern), joining the block that already reaches `e2e/**/*.ts` with the `vellum` plugin (Issue #812's ruling).
