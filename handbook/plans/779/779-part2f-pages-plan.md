## The rule this round applies

The unit of proof is the claim (2e call 1): one assertion with its message; its mutation is the smallest change to the code under test that makes the claim false. A unit test leaves only when every claim it makes is held:

- **A HELD claim** is held by its named existing browser check: the claim's mutation, applied alone, reds the unit test AND prints that check's `FAIL` (or stops the suite on an exception that check's own read throws, 6090198881). The build, the type checker and the lint do not hold a claim (2e call 2).
- **A claim with no holder today** gets a new browser check first, and the same proof is run against the new check.
- **A claim no browser here can see** keeps a smaller unit test, renamed where its name over-claims, and is named for part 2i with the reason (call 6): Chromium's aliased prefixes, CSS a served page never wears, and rule absences in a sheet. A claim that runs code (an import's value, a function's output) is not a source read and stays in its unit test.
- **The census's mutation is re-aimed** where the move changed its target (recon's twelve), and a claim whose census mutation the code no longer has gets the nearest mutation that makes it false, named in the ledger.

## Procedure

1. The archived plan is committed and pushed alone; the checks are written and committed with every unit test still in place; then the proofs run, on committed code (Commit before you mutate); then the deletions and shrinks are the next commit.
2.
