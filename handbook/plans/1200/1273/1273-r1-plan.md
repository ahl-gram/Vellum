## The design

**The clean-up bullet tells an open errata row from a closed record.** The one sentence that called
every errata row a dated record is replaced by two:

1. An open row in `handbook/errata/` is live work, so a row there that the bullet's greps hit (the
   deleted check's id, or a file the pull request deletes or empties) is edited to say what still
   stands once the check or the file is gone, or deleted where nothing does; any gap the row
   recorded that the edit takes out is listed with the check's lost coverage, where the bullet
   above lists it, naming the row's file and the pull request that left it (a row has no id, and
   line numbers shift).
2. A closed or archived record stays as written: an archived plan under `handbook/plans/`, a row in
   an errata file's Ruled and left section, and a row in
   `.claude/skills/vellum-footguns/references/scars.md`; the check's rows in
   `.claude/skills/vellum-footguns/references/flake-record.md` still take the disposition
   *deleted*.

The rest of the bullet (the `E2E_SKIPS` entry, the closing reference, an emptied suite's rosters) is
unchanged in its words and rewrapped only so its lines keep the bullet's width.

**The README points at it.** `handbook/errata/README.md`'s "How a row leaves" gains a fourth bullet,
"Its check deleted.", that says the deleting pull request edits or deletes the row and points at
the settle-doctrine section for the terms. Without it the README's list of how a row leaves stays at
three, which is the same mismatch the review found, read from the README's side. It is a pointer and
not a second copy of the rule (`handbook/specs/conventions.md`, Where a rule lives).

**The rows themselves are not edited here.** No check is deleted in this pull request, and the
amended sentence gives each row to the pull request that deletes the check it names: NS1's and
EZ4's rows to pull request 2 (the camera group), CO3's to pull request 5 (chrome and documents).

**Alternatives rejected:**

- **Edit the three rows in this pull request.** Rejected: the checks still exist and still run, so
  each row is true today; editing it now would record a deletion Alex has not yet ruled check by
  check (Q1, "You rule each").
- **Keep every errata row as written and list its gap as lost coverage only.** Rejected: Alex ruled
  the open row edited ("Fix the rule now"), and a row naming a check that no longer exists is a
  stale finding in live work.
- **Also edit rows under Ruled and left.** Rejected: the README makes a ruled row closed ("not open
  work ... it reopens only by a later dated ruling"), so a deletion that rewrote one would reopen a
  ruling of Alex's without a new one; it was option 3 of the menu, and Alex chose option 1.
- **Restate the rule in the README.** Rejected: two normative copies (`handbook/specs/conventions.md`,
  Where a rule lives); the README carries a pointer.
- **Amend the README's line 34 ("is an archive").** Rejected: it says the directory sits outside the
  path scan, which stays true; the new fourth bullet removes the ambiguity where a reader of "How a
  row leaves" meets it.
