## What this is

Three modules bind the chart's touch press by calling `bindChartTouch` from
`src/site/shared/chart-touch.ts` themselves (`git grep -n "bindChartTouch(" -- src/site` prints exactly
these three call sites besides the definition):

- `src/site/shared/glass-keys.ts`, the kit's Glass keys, line 2 imports it from `./chart-touch.ts`,
  line 16 calls it. The Hunt and the six zoom rooms reach it through `bindGlassKeys`, which the lint
  already requires of `zoom-room.ts` and the Seed of the Day.
- `src/site/home/app.ts`, line 18 imports it from `../shared/chart-touch.ts` beside `pageTouchEnv`,
  lines 121 to 128 call it.
- `src/site/explorer/glass.ts`, line 2 imports it from `../shared/chart-touch.ts` beside
  `pageTouchEnv`, line 151 calls it (inside `glassPresses`).

No `SHARED_BINDINGS` entry in `scripts/lint/shared-bindings.ts` names any of the three, so nothing
refuses one that stops taking the shared binder, or keeps a copy of it, which is the defect the
rule's own message names ("so the room binds the shared code rather than a copy of it").

**The issue's premise is half true, and the plan says so.** It says Home's press "is held by
nothing" since ZG9 left the run (PR #1277). Measured on this tree's build (below): a browser check
still reads each of the three presses, as `vellum-footguns` Gate 1 item 6 asks of a room whose own
code carries the part. L9i (`e2e/suites/landfall/touch.ts`) reads Home's, ZG5
(`e2e/suites/zoom-gestures/touch.ts`) the Explorer's, and ZG10 (`e2e/suites/zoom-gestures.ts`) the
Writing Room's, the kit's path; each fails when its page stops binding the press. What no check
holds is that the page takes the SHARED binder: a copy that behaves the same passes every browser
read by construction. That is a rule about what the code says, so it belongs to the lint
(`handbook/specs/check-placement.md`, The lint, the first bullet), and the lint is also the first
and cheapest red (its Order section). This plan adds that hold for all three, keeps every browser
check as it stands, and changes no product code.

## The design

1. **`SHARED_BINDINGS` gains three entries**, each holding the one binding `bindChartTouch` with the
   specifier the module imports it by today: `src/site/shared/glass-keys.ts` from `./chart-touch.ts`,
   `src/site/home/app.ts` and `src/site/explorer/glass.ts` from `../shared/chart-touch.ts` (a new
   file constant `TOUCH` names the second form, used twice). The rule's code, its message and its
   wiring in `eslint.config.ts` are untouched: the block that reaches every site script already
   gives it `SHARED_BINDINGS` (the existing test "the rule resolves at error ..." reads that for every
   roster key, so the three new keys join it by existing).
2. **A new unit test, G1**, lints six plants through the house's real config (`plantMessages` and the
   file's `reported` helper), two at each module's own path: one taking and using `bindChartTouch`
   (must report nothing) and one with its import and use deleted (must report exactly
   `["bindChartTouch", <that module's specifier>]`). Before step 1 the three deletion plants report
   nothing, so G1 reds on its `deepEqual` at plant (t2), the assertion that matters, not on a missing
   module. The deletion plants are the witness that the rule has something to refuse at each path;
   the opening `assert.ok` requires the list to hold a plant the rule must pass and one it must
   refuse, as the file's other outcome tests do.
3. **The roster pin, G2** ("the roster is exactly the import pins ..."), moves with the roster:
   `ROSTER` gains the same three entries in the same positions, and its title and message name
   Issue #1288.
4. **The lint itself, G3**, holds the three real files: `npm run lint` reds on
   `vellum/shared-binding-imported`, and on nothing else, for whichever of them stops taking the shared
   binder (mutations L1 to L3, measured precise).
5. **Commit 3 corrects the errata note that carries the same false premise** (ruled, Q2): the open row
   `PR #893 (2026-10-13, medium)` in `handbook/errata/guards.md` ends with Issue #1273's narrowing note
   "ZG9 was deleted, so no check reads any room's touch press but the Explorer's", which L9i and ZG10
   falsify (measured below). A dated parenthetical is appended to that one physical line; PR #1277's
   note and the row's finding are left as they are, since this plan does not touch what the row
   finds (a future chart page that never reaches the press takes a finger).

### Rejected

- **Home alone, as filed.** The rule binds three modules, not one: Gate 1 item 6 lists every instance
  the rule binds, and each of the three is a place it can break on its own. Home alone leaves the
  Explorer's Glass and the kit's Glass keys free to keep a copy. Ruled out by Alex (Q1 of the
  rulings comment: "All three places").
- **The issue's mutation** (its fix step 4: delete Home's import and its call). Measured: under
  TODAY's roster it already reds `prefer-const` (`'takesTouch' is never reassigned`, line 118 of the
  mutant), since the call's callback holds `takesTouch`'s only write; dropping only `bindChartTouch`
  from the import adds `@typescript-eslint/no-unused-vars` on `pageTouchEnv`. The proof runner keys a
  lint red by rule id and file (`lintOutcome` in `scripts/proof-runner/outcome.ts`), so that row would
  print IMPRECISE. L1 below replaces it, as the issue's step 4 itself asks.
- **A local copy of `bindChartTouch` as the mutation** (the import keeps `pageTouchEnv` and the two
  types, a same-named function appended). Measured precise at Home and at the kit's Glass keys, but
  at the Explorer's Glass it also reds `vellum/split-arguments-by-name` under today's roster, because
  `src/site/explorer/glass.ts` is on `SPLIT_FILES` and the rule reads a call to a function declared in
  the file. One form for all three is the call-site stand-in, L1 to L3, measured precise everywhere.
- **Holding `pageTouchEnv` too.** The issue names one binding; the press's behaviour is
  `bindChartTouch`'s, and `pageTouchEnv` is a two-line reader of `TOUCH_PRIMARY` that
  `src/site/explorer/loupe-page.ts` also takes on its own. A plant keeps it in every case so the
  deletion plants differ from the passing ones by `bindChartTouch` alone.
- **A witness test that reads the source** (`check-placement.md` allows one "where the rule cannot say
  so itself"). This rule's requirement is positive: on a real file it passes only by taking and using
  the binding. The paths by which it could read nothing are held already: a roster file renamed or a
  specifier gone (the roster test's `existsSync` loop), the rule not reaching the file (test "the rule
  resolves at error ..."), an inline `eslint-disable` (`test/repo/ts-comment-form.test.ts`).
- **A browser check for the copy.** No browser read can tell a copy that behaves the same from the
  shared binder, and the behaviour is already read by L9i, ZG5 and ZG10. `check-placement.md`: a move
  never adds a browser check, and a rule about what the code says is a lint rule.
- **Home taking the kit's `bindGlassKeys` instead.** Refused by `vellum/explorer-no-glass-keys`
  (`scripts/lint/import-bounds.ts`: "the Explorer and home bind their own zoom presses by id"), and a
  product change nobody asked for.
