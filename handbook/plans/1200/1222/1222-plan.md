## The design

In `forestLabelNodes`, the candidate list becomes the five heights at the centroid, each at the centroid's own x, followed by `interiorProbes(blob, w, proj, c)`; the label takes the first candidate `p` whose `textBox(p.x, p.y, forest, fs, "middle")` the arena claims at pad 4, and is drawn at `p.x`, `p.y`. Everything else in the function is unchanged: the size (`12.5 * k`), the pad, the ink, the halo, the claim order inside `featureLabelsLayer` (the forest still claims last of the feature labels).

Why a chart lettered today keeps its bytes, by construction: the first five candidates are today's five, in today's order, at today's x; `find` stops at the first claim; and a failed `tryClaim` in `createLabelArena` (`src/render/context.ts`) pushes nothing and returns false, so trying a candidate that fails changes no state; `interiorProbes` is pure and draws no rng. The planner's sweep confirms it: zero charts lettered today whose bytes differ, over 529 woods in eleven configs and 122 woods in five more (What it moves, below).

**Rejected, so the builder does not rediscover them:**

- **The interior probes before the five heights.** Moves every chart lettered today, the committed seed-42 charts among them: under that arm the hero drift guard reds on all four committed charts (`chart-42-antique.svg: 2/138759 numbers drifted beyond 0.05px (max Δ 2.03e+1)`, the forest label's x and y), which would owe a regen and break Q3's "changes only charts that lose the name today".
- **A shared helper with the range label** (`placeRangeLabel` builds the same two stages inside its size loop). Touches the range label for no behaviour; the range label stays as it is and keeps its bytes by not being edited.
- **A ladder of smaller sizes, as the range label has** (14.5, 13, 11.5, 10). A smaller face is an appearance nobody has ruled, and the interior probes alone leave one wood of the sweep's 529 unlettered at 1500 (seed 400). The Ribbon already captions such a wood by size (Q3).
- **Claiming the forest label earlier** (before the rivers and lakes). Reorders label priority, so river and lake names on charts lettered today would yield, moving them and the committed charts.
- **Forcing the label into place** as a realm name may be forced. Overprints other lettering.
- **Clearing tree glyphs from under the label** (adding its box to `nameBoxes`). A world sheet clears no glyph from any name (`handbook/specs/chart-dress.md`, "A world sheet does none of this"); the label keeps its halo over the glyphs as every forest label does today.

```ts
// Issue #1222 evidence probe, no hook: of the seeds given, on how many charts that carry a wood the gate names (namedForestBlob in src/render/named-forest.ts) is the wood's name lettered, in antique with the key and in ink with the key at 1500, and which charts drop it. Run on main and on the branch. node out/1222-dry-run/1222-letters.ts <from> <to>
import { generateWorld, defaultRecipe } from "../../src/world/generate.ts";
import { renderMap } from "../../src/render/map-renderer.ts";
import { namedForestBlob } from "../../src/render/named-forest.ts";
import { escapeXml } from "../../src/render/svg.ts";

const from = Number(process.argv[2] ?? 1);
const to = Number(process.argv[3] ?? 500);
let woods = 0;
const dropped: string[] = [];
for (let seed = from; seed <= to; seed++) {
  const world = generateWorld(defaultRecipe(seed));
  const name = world.names.forest;
  if (!name || namedForestBlob(world) === null) continue;
  woods++;
  for (const style of ["antique", "ink"] as const) {
    if (!renderMap(world, { style, legend: true }).includes(`>${escapeXml(name)}<`)) dropped.push(`${seed} ${style}`);
  }
}
console.log(`seeds ${from} to ${to}: ${woods} charts carry a wood the gate names; unlettered: ${dropped.length ? dropped.join(", ") : "none"}`);
```
