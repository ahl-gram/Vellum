## What this is

The Seed of the Day (`src/site/seed-of-the-day/app.ts`) does not take `bindZoomRoom`: it composes the
shared room kit itself. It imports `bindRoom` from `../shared/room.ts` (line 11) and `bindGlassKeys`
from `../shared/glass-keys.ts` (line 12) and calls both (`const room = bindRoom({` at line 61,
`bindGlassKeys($("map-viewport"), zoomController);` at line 66). Its entry in `SHARED_BINDINGS`
(`scripts/lint/shared-bindings.ts`, lines 24 to 27) requires only `createZoomController` and
`framingCamera`, so nothing holds it to the other two. `vellum-footguns` Gate 1 item 6 counts rooms held
to one shared module by `SHARED_BINDINGS` as one instance, read in one room, and PR #1277 narrowed EA5
and ZG9 on that footing. This plan adds the two bindings to the entry, adds an outcome test that
lints a Seed of the Day module missing each binding and must see it refused, and moves the roster pin
the issue names.

**No product code changes.** The page already binds both through the shared modules; the probe below
lints the real page under the new roster and reads no message at all.

## The design

   block "the house's rules on every site script" already reaches the page with `SHARED_BINDINGS` as

   file).
2. A new unit test, **G1**, lints five plants at the Seed of the Day's own path through the house's
   real config (`plantMessages` and the file's `reported` helper): one taking and using all four
   bindings, which must report nothing, and one per binding with that binding's import and use

   `bindGlassKeys` report nothing, so G1 reds on its `deepEqual` at plant (s2), the assertion that
   matters, not on a missing module. The refused plants (s2) to (s5) are the witness that the rule
   has something to refuse at this path; the opening `assert.ok` requires the list to hold a plant
   the rule must pass and one it must refuse, as the file's first test does.

### Rejected

- **The issue's roster pin alone (G2) as the failing test.** It reds because one hand-kept list differs
  from another, a declaration pin; it never shows the rule refusing a Seed of the Day that skips the
  shared binder (Gate 1 item 3, assert the outcome). It stays, moved, beside G1.
- **G1 passing its own roster to the rule as an argument** (a `Linter` with `{ required: {...} }`).
  The rule already takes its roster as an argument, its `required` option, and the existing plants at
  `zoom-room.ts` already drive its logic. What is missing is the house's roster entry, so a test that
  supplies its own roster would be green before the fix. G1 reads the roster through the house config
  on purpose.
- **G1 covering only the two new bindings.** The entry names four, and each is a place the page can
  stop binding the shared kit on its own (Gate 1 items 5 and 6). Plants (s3) and (s5) are green from
  the start and are proven by mutations U2 and U4.
- **A witness test that reads the page's source** (`check-placement.md` allows one "where the rule
  cannot say so itself"). This rule's requirement is positive: on the real page it passes only by
  taking and using each binding, which is what a witness would read. The paths by which it could read
  nothing are held already: a roster file renamed or a specifier gone (test "the roster is exactly
  ...", its `existsSync` loop), the rule not reaching the page (test "the rule resolves at error
  ..."), and an inline `eslint-disable` at the page (`test/repo/ts-comment-form.test.ts`, the rulebook's
  accepted skips). A source read would add a `SOURCE_READS` entry for nothing those do not hold.
- **The issue's `bindRoom` mutation** (its fix step 3: delete the import and the call). Measured: it
  deletes `framingCamera`'s only use, so it reds `vellum/shared-binding-imported` under TODAY's roster
  already (a `framingCamera` report), and it adds `@typescript-eslint/no-unused-vars`,
  `@typescript-eslint/no-unsafe-call`, `@typescript-eslint/no-unsafe-member-access` and a type error
  (`TS2304 Cannot find name 'room'`). The proof runner keys a lint red by rule id and file
  (`lintOutcome` in `scripts/proof-runner/outcome.ts`), so that row would print BITES for a pin that
  holds nothing. L1 below replaces it. The issue's `bindGlassKeys` mutation is kept as L2, measured
  precise.
- **Changing the page to take `bindZoomRoom`.** A change of product behaviour nobody asked for: the
  Hunt builds its own controller on purpose (`vellum/hunt-fixed-world`, and the header comment of
  `src/site/shared/zoom-room.ts`).
