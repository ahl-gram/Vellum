## The design

### What is built

The chart of lessons stands across the head of the Primer's sheet, first inside `.primer`, above `.opening` (Q1). It is the chart of the atelier's coast, places, roads and tracks (`PLACES`, `ROADS`, `TRACKS`, `COAST`, `PIP_R`, `roadPath` in `src/layouts/atelier-chart.ts`) drawn again on the chart's paper over the whole frame, with:

- every place drawn, the fourteen of today's `PLACES`; those the Primer teaches in full ink, the others pale, each named by `ROUTE_NAMES` in `src/layouts/nav.ts` and, where it has no entry (the Atlas), by its place's own name (Q6);
- round each room the Primer teaches a ring with one mark per step, starting at the top and running clockwise, a lesson parted from the next by one empty slot (Q2);
- a sealed step's mark red, a mark for a step this device cannot take (and that is not sealed) dotted, every other mark faded ink (Q2, Q4);
- the road from home to every room holding at least one seal inked red, along the site's own roads; The Seed of the Day and the Gallery, which no road reaches, ink only their own marks (Q3);
- the room open on the page lit gold, and the house's manicule at the open room's first step that is not sealed and that this device can take (Q4, Q5); a room with no such step left takes the hand off the chart. The hand keeps the seat its step gives it, across the Explorer's name on a first visit (F1), and takes no press, so a press anywhere on that name reaches the Explorer's link (F2, revision 1);
- each taught room's place (its pip, its name and its ring) a link to that room's head on the page; a press opens that room below (Q1, Q2). No place the Primer does not teach is a link, and home is not one (the round's own drawing).
- under the chart its key line, the ring-of-steps line the ruled q2-b still shows (Q7, call C4).

### How it is split

1. **The model, DOM-free** (`src/layouts/chart-of-lessons.ts`): from a list of rooms in the page's order, every number the drawing takes: each place's ring, marks, light, hand seat and label seat, each road's rooms, the frame. It imports `src/layouts/atelier-chart.ts` and `src/layouts/nav.ts` only. It takes the rooms by a structural type of its own and never imports the ladders: a `src/layouts/` module that imports `LADDERS` reds `npm run check`'s engine pass, which type-checks `src/layouts/` with `lib: ["ES2023"]` and no DOM, because `src/site/shared/primer/ladders.ts` pulls in `src/site/explorer/chart-drawer.ts`, `src/site/explorer/worker-client.ts` and `src/site/seed-of-the-day/app-dispatch.ts` (measured: `tsc --noEmit -p out/1257-dry-run/1257-tsconfig.engine-probe.json` exit 2, `Cannot find name 'HTMLButtonElement'` and twenty more; the same config over the planned imports alone, `out/1257-dry-run/1257-tsconfig.engine-probe-ok.json`, exit 0).
2. **The markup, DOM-free** (`src/layouts/chart-of-lessons-svg.ts`): the model written as one SVG string through `el` and `renderSvg` in `src/render/svg.ts` (the engine's own builder, which the Print Room's markup modules already use), so a unit test renders the real markup and runs the page's script over it in `linkedom`.
3. **The component** (`src/layouts/ChartOfLessons.astro`): the nav landmark, the frame and the key line, the SVG set into the frame with `set:html` (the Gallery's and the Print Room's pages set built markup the same way). The Primer page seats it and passes `page.rooms`.
4. **The ink, client side** (`src/site/primer/chart-ink.ts`): the build cannot know this browser's seals, its device or the open room, so the markup ships neutral (no mark sealed, none dotted, no road inked, no light, the hand hidden) and the page's own script inks it. `bindPrimer` in `src/site/primer/bind.ts` calls it where it already draws the seals and opens a room, and its click handler reads a link's `href` attribute in place of `hash`, which an SVG link does not have (Q1).
5. **The dress** (`src/styles/shared/chart-of-lessons.css`): the round's own paper dress, linked by the Primer through `extraCss`.

The frame is computed at build because it does not depend on the open room: the round's own `drawChart` at the ruled answers gives `viewBox` `7 59 559 351` with each of the nine taught rooms open, with none open, and on a first visit (`node out/1257-dry-run/1257-mock-frames.ts`, output `out/1257-dry-run/1257-mock-frames.json` at 817f90f4 and `out/1257-dry-run/1257-mock-frames-9667a7fe.json` at 9667a7fe, identical).

### Alternatives rejected

- **Drawing the SVG in the `.astro` component's markup** (as `src/layouts/AtelierChart.astro` does): no unit test could then run the page's script over the real markup without a build, and the ink's selectors would be held to the markup only by a built-page read. Rejected for the string builder (call C13).
- **Importing `LADDERS` into the model**: reds the engine type check (measured above).
- **Inking at build time** (marks sealed in the markup): the seals live in this browser's `localStorage` under `vellum.primer.v1`, which no build sees.
- **One hand group per step, shown by class**: 81 groups for one visible hand, about 20 KB of markup, against one group moved by the script.
- **Computing the hand's geometry in the browser**: it put the client over the inline limit's comfort (sized below) and duplicated the model's trigonometry in a second home. Each mark carries its hand's transform instead.
- **Lessons as numbered waypoints**: ruled against (Q2 B).
- **Flattening the three washes to plain colours** so they can join `SITE_PALETTE` as flat hexes: changes the ruled picture where two washes lie over each other. The land wash (0.6 of `--parchment-deep`) over the sea's rim (0.4 of `--line-tan`) reads about rgb(226, 213, 180) inside the coast against rgb(235, 223, 193) for the land alone; an opaque land would hide the inner half of the sea's 9-unit rim. Rejected by the fidelity rule; where the washes are named Alex ruled (M1, "Shared sheet only").

export interface ChartLesson { readonly steps: readonly ChartStep[] }

The arithmetic. Every number below is one of the round's stand-ins (`/Users/ahl/CodeProjects/Vellum/out/1256/notes.md`, "For whoever builds it"), which this sub settles as drawn; the round's code, which these rules port exactly, is `/Users/ahl/CodeProjects/Vellum/out/1256/mock/layout.ts`, `labels.ts` and `chart.ts`:

- `round1(v) = Math.round(v * 10) / 10`; `at(x, y, r, deg)` is the point `(round1(x + r * cos(deg * PI / 180)), round1(y + r * sin(deg * PI / 180)))`, angles in degrees, y down. Every `cos` below is of an angle in degrees, converted the same way.
- **`ringOf(lessons)`**: `slots` is the sum over lessons of (its step count + 1); `r = round1(max(RING_FLOOR, slots * SLOT_ARC / (2 * PI)))`; `per = 360 / slots`; a slot counter starts at 0; for each lesson the counter steps once (the gap), then for each step `from = -90 + slot * per - per / 2 + per * 0.14`, the counter steps once, `to = from + per * 0.72`, and the arc records the step's id and its lesson's index. On today's ladders: the Explorer's ring is 23.6, every other room's 9.
- **A mark** (one per arc, in arc order): `d` is `M{p.x} {p.y} A {r} {r} 0 0 1 {q.x} {q.y}` with `p = at(x, y, r, from)` and `q = at(x, y, r, to)` round the place's own `x, y`; `only` copies the step's; the hand: `mid = (from + to) / 2`, `t = at(x, y, r, mid)`, `east = cos(mid) > 0`, `rot = Math.round(east ? mid : mid + 180)`, `hand = "translate({t.x} {t.y}) rotate({rot})"`, `side = east ? "east" : "west"`.
- **A taught place** (a place whose route is a room's): `room` the room's `id`, `ring` its ring's `r`, `marks` its marks, `halo = max(16, ring + 2 + 5)`, its extent `ring + 2`, its obstacle box the circle box of radius `ring + 2`. **Any other place**: `room`, `ring` and `halo` null, no marks, extent `PIP_R[rank]`, obstacle box the circle box of radius `PIP_R[rank]`. Every place: `pip = PIP_R[rank]`. A circle box of radius `c` round `(x, y)` is `{ x: x - c, y: y - c, w: 2c, h: 2c }`.
- **A room whose route is not a key of `PLACES` throws** `no place on the chart of the atelier for {route}` (the wording `roadPath` already throws).
- **Places** are listed in `PLACES` key order, every key, taught or not.
- **Labels**: one item per place, `text = ROUTE_NAMES[route] ?? place.name`, `size` 12 for a taught place and for home (`"/"`), 10.3 for every other, `ext` the place's extent. Items are placed in order of `(taught ? 0 : 10) + RANK[rank]`, `RANK = { capital: 0, landing: 1, town: 2, isle: 3, village: 4 }`, a stable sort over `PLACES` order. For an item: `w = text.length * 0.58 * size`, `up = 0.82 * size`, `h = 1.07 * size`, `gap = 3`; `aboveY = y - ext - gap - 0.25 * size`, `sideY = y + 0.33 * size`, `belowY = y + ext + gap + up`. The candidates, in this order: above (`anchor` middle, `x` = place x, `y = round1(aboveY)`, box `{ x - w/2, aboveY - up, w, h }`); right (`start`, `round1(x + ext + gap)`, `round1(sideY)`, box `{ x + ext + gap, sideY - up, w, h }`); left (`end`, `round1(x - ext - gap)`, `round1(sideY)`, box `{ x - ext - gap - w, sideY - up, w, h }`); below (`middle`, place x, `round1(belowY)`, box `{ x - w/2, belowY - up, w, h }`). Two boxes meet when `a.x < b.x + b.w + 1.5 && b.x < a.x + a.w + 1.5 && a.y < b.y + b.h + 1.5 && b.y < a.y + a.h + 1.5`. The first candidate meeting no obstacle box (every place's) and no label already placed is taken with `forced` false; where none is free, the above candidate with `forced` true. The label's `x`, `y` are the candidate's text position. The word-width estimate (0.58 of the size a letter) is the round's, measured once against the Fell small capitals; the plate reader is the real check.
- **Roads**: one per `ROADS` pair, in `ROADS` order: `pair`, `d = roadPath(pair)`, `rooms` the ids of the rooms, in the rooms' order, whose `pathFromHome(route)` holds that very pair. **Tracks**: `roadPath` of each `TRACKS` pair, in order.
- **`pathFromHome(route)`**: a breadth-first walk from `"/"` over `ROADS`, taken as undirected, neighbours in `ROADS` order; the legs from `route` back to home, or `null` where the walk never reaches it (today The Seed of the Day and the Gallery).

type UnderHand = { on: boolean; area: number; x: number; y: number; hit: boolean } | null;

const HAND_AIM = (id: string): Payload<UnderHand> => `(() => {
  const link = document.querySelector(${JSON.stringify(`.col-chart a[href="#${id}"]`)});
  const name = link && link.querySelector("text.name");
  const hand = document.querySelector(".col-chart .col-next");
  if (!link || !name || !hand) return null;
  name.scrollIntoView({ block: "center" });
  const glyph = [...hand.querySelectorAll("text")].find((t) => t.getBoundingClientRect().width > 0);
  if (!glyph) return { on: hand.classList.contains("on"), area: 0, x: 0, y: 0, hit: false };
  const n = name.getBoundingClientRect(), g = glyph.getBoundingClientRect();
  const left = Math.max(n.left, g.left), top = Math.max(n.top, g.top);
  const w = Math.min(n.right, g.right) - left, h = Math.min(n.bottom, g.bottom) - top;
  const x = left + w / 2, y = top + h / 2;
  const area = w > 0 && h > 0 ? w * h : 0;
  return { on: hand.classList.contains("on"), area, x, y, hit: area > 0 && link.contains(document.elementFromPoint(x, y)) };
})()`;

const lands = (d: Pressed): boolean => d.head !== null && d.head >= 0 && d.head < d.inner;
