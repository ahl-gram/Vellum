## The design

1. **The room lays out at the press.** `bindSlip` (`src/site/shared/slip.ts`) toggles the classes and then calls the room's fold handler at once, in the press's own task. It no longer schedules a layout 340 ms later.
2. **The sheet slides from where it stood.** The room's fold handler does four things in order:
   - it reads the sheet's box as it stands (a slide already in flight included);
   - it lays the room out (the fit, the camera's refit and the seats, as today);
   - it hands the old box to the sheet's slide, which reads the new box and, on the next animation frame, plays one Web Animations animation of the sheet's own `translate` and `scale`, from the old box to none;
   - when the slide ends, it lays the room out once more, at rest.
3. **Why this keeps the camera true.** The sheet keeps its aspect, so the old and the new box differ by one uniform scale and a translate. The chart, its camera's transform and every overlay inside it scale together. The framing the refit restored is therefore the framing on screen at every frame. The slide runs on the compositor, so the chart is never laid out or re-rasterized mid-slide. That is the "Counter-scale" section's rule that the mount's only per-frame mutation is the composited transform.
4. **The slide's coordinates and pace.** The slide's offset is in the sheet's own pixels: the screen delta divided by the depth of the sheet's ancestors (the sheet's screen width over its layout width). That depth is 2 on a zoomed Seed of the Day, whose sheet rides inside the camera's mount, and 1 elsewhere. The duration and the curve come from two new tokens in `src/styles/shared/motion.css`, `--fold` (320ms) and `--ease-fold` (`cubic-bezier(0.2, 0.7, 0.3, 1)`). The slip, the Glass and the legend row read the same tokens, so the slide shares their pace by construction.
5. **Why the slide starts on the next frame.** The observers that measure the sheet (the slide-away's, on its style) run in the press task's microtasks, before the slide exists, and so read the rest box. No paint falls between the press and that frame, so nothing flashes.
6. **Reduced motion: no slide.** `prefersReduce` is read at each press, since a Web Animations animation is outside the blanket's reach, as the sheet turn's is. The room lays out at the press and the sheet stands at its new fit.
7. **The fit holds transitions off while it writes.** `fitRoom` holds the frame's and the sheet's transitions off while it writes the reserves and the size, and reads a rect before it lets them go, as `placeLegendRow` does. Under reduced motion the camera's refit then reads the sheet's new size, not the old one.
8. **The Glass is read where it is going.** When the slip folds, `glassLeft` reads the Glass where its running `right` transition will leave it, so a layout at the press fits the folded room against the Glass's folded seat. That seat is set by the page: `var(--chrome-x)` in `atelier.css`, beside the Drawer tab in the Explorer's `chart-drawer.css`.
9. **Every other layout stands the sheet at its fit at once.** A resize, a draw landing or the fonts loading cancel a slide in flight.

**Rejected**, so a builder does not rediscover them mid-build:

- **Transitioning the stage's padding and the sheet's width and height.** It drifts the zoomed framing 0.0837 mid-slide at 1024x768. Holding it true would need the camera's transform transitioned too, which would smear every camera apply in the window. It lays the chart out and re-rasterizes it every frame (frames to 52 ms), and it writes on an ancestor of the chart svg every frame.
- **Tweening the camera.** A camera tween moves the chart inside the sheet, not the sheet, so the sheet would still jump.
- **A frame-by-frame script tween of the reserves and the size.** It has the same per-frame layout and the same per-frame write on the mount's ancestor.
- **Keeping the 340 ms timer and only animating.** The fit would still land after the furniture has stopped.
- **Starting the slide synchronously at the press.** The slide-away's observer would then measure the sheet mid-slide, scaled where the slide changes size.
- **`transition-property: none` on `#sheet` and the frame in CSS.** On the Seed of the Day the frame is `#map`, the camera's target, so it would change every camera write there under reduced motion.
- **Computing the Glass's folded seat from tokens, as the open seat is.** The folded seat is overridden per page, so a second formula would drift.

**`src/site/shared/sheet-slide.ts`** (about 75 lines; the name as ruled):

- `export interface SheetBox { readonly left: number; readonly top: number; readonly width: number; readonly height: number }`
- `export interface SlideStart { readonly dx: number; readonly dy: number; readonly s: number }`
- `export function slideStart(from: SheetBox, to: SheetBox, depth: number): SlideStart | null`
  - Pure.
  - `dx = ((from.left + from.width / 2) - (to.left + to.width / 2)) / depth`, `dy` the same on `top` and `height`, `s = from.width / to.width`.
  - Returns `null` when `|dx| < 0.5 && |dy| < 0.5 && |s - 1| < 0.001`, and `null` when `to.width <= 0` or `depth <= 0`.
- `export function foldTiming(): { readonly ms: number; readonly ease: string } | null`
  - Reads `--fold` (parsed with `parseFloat`, in ms) and `--ease-fold` (trimmed) from `getComputedStyle(document.documentElement)`.
  - Returns `null` when the first does not parse to a finite number above 0, or the second is empty.
  - No literal fallback (C7).
- `export interface SheetSlide { readonly stop: () => void; readonly slide: (from: SheetBox, reduce: boolean) => Promise<boolean> }`
- `export function createSheetSlide(sheet: HTMLElement): SheetSlide`. A closure holding the pending frame id, the running `Animation` and the pending promise's resolver.
  - `stop()`:
    - It cancels a pending frame (`cancelAnimationFrame`) and resolves its promise `false`.
    - It cancels the running animation it holds (its `finished` rejection resolves that promise `false`).
    - With nothing in flight it touches no DOM. It never calls `getAnimations()`, so the unit tests' element shim, which has none, can bind a room.
  - `slide(from, reduce)`:
    - It first calls `stop()`.
    - It then reads `to = sheet.getBoundingClientRect()` and `depth = to.width / (parseFloat(getComputedStyle(sheet).width) || to.width)`, then `start = slideStart(from, to, depth)` and `timing = foldTiming()`.
    - When `start` or `timing` is `null`, or `reduce` is true, it returns `Promise.resolve(true)`.
    - Otherwise it returns a promise. On the next `requestAnimationFrame` the promise calls `sheet.animate([{ translate: `${dx}px ${dy}px`, scale: String(s) }, { translate: "0px 0px", scale: "1" }], { duration: timing.ms, easing: timing.ease })` and keeps the animation.
    - The promise resolves `true` when that animation's `finished` resolves, and `false` when it is cancelled.
- One head comment line; no other comment.
