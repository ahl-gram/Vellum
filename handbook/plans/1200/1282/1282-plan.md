## The design (Q1 A, as ruled)

Four `check & test` jobs, and the files dealt among them by measured seconds instead of by position.

1. **`scripts/unit-shards.ts`** holds `UNIT_SECONDS`, every unit file whose CI seconds over the nine runs
   (each run's reading scaled to the median runner, then the median taken) are at or over 5 s (115
   files) at its whole seconds, and `UNLISTED_SECONDS = 0.5` for every
   other file. `shardOf(files, index, total)` sorts the files heaviest first (ties by path), deals each
   onto the shard with the least weight so far (ties to the lower shard), and returns the `index`th
   shard's files sorted. It is a pure function of the file list and the table, never of the machine, so
   every job computes the same partition.
2. **`scripts/unit-suite.ts`** keeps `--test-shard=<k>/<n>` as its interface, so `ci.yml`'s Test step,
   the regex `test/repo/e2e-tiers.test.ts` pins on it, branch protection's step names and the shard
   command in `.claude/agents/vellum-implementer.md` all stay true. When the flag comes with no path, the
   launcher no longer forwards it: it lists `SUITE` itself with `globSync`, passes node the `k`th part's
   paths, and, when no reporter was forwarded, adds the spec reporter and the per-file clock, both to
   stdout. With a path forwarded, the flag reaches node exactly as today.
3. **`scripts/unit-file-clock.ts`** is a node test reporter: it prints, after the run, every file's whole
   seconds (load and hooks included) under `per-file wall clock (<n> files, <s> total):`, in the form the
   lanes' `per-suite wall clock` block takes, so `UNIT_SECONDS` is refreshed from CI's own logs as
   `MEASURED_SECONDS` is. Node reports each file as a nesting-0 `test:complete` event whose `name` is the
   path as given and whose `file` is that path resolved (probed in `<scratch>/1282-summary-probe/`, a red
   file included).
4. **`.github/workflows/ci.yml`** runs `shard: [1, 2, 3, 4]`, and the proof runner's `max-parallel` drops
   from 12 to 11 so 11 + 4 unit jobs + 4 lanes + the deploy build stays at the 20
   `test/repo/proof-runner-workflow.test.ts` holds.
5. **Alex renames the required checks by hand at the merge**: `check & test 1 of 3`, `2 of 3`, `3 of 3`
   out; `check & test 1 of 4`, `2 of 4`, `3 of 4`, `4 of 4` in. No one else edits branch protection.
   "The merge sequence" below orders it.

**Rejected, with the reason:**

- **Declined by Alex** (the ruling above): three jobs by measured seconds, four jobs by file count, and
  speeding up the slowest files. Their modelled numbers stay in the table above as the record of the
  choice.
- **A split that models node's start order** (deal each file onto the shard whose modelled Test step it
  lengthens least): four jobs read 324 s against 339 s for the plain deal, three jobs 397 s against
  403 s (`evaluate-5.out`), inside a ten-to-ninety band about 50 s wide, while the run waits on the lanes
  at 398 s either way; and it ties the partition to node's worker count and sort order.
- **A table of every file, or a cut at 2 s or at 10 s**: 167 files at 2 s read 337 s (four jobs) and
  407 s (three), 65 files at 10 s read 337 s and 406 s, against 339 s and 403 s for 115 files at 5 s
  (`<scratch>/1282-logs/table-2.out`, `table-10.out`, `table-5.out`): no cut buys more than 4 s. The cut
  is set on what it leaves unweighed: the files under 5 s carry about 14% of the seconds (336 s), those
  under 10 s 29% (723 s), so at 5 s a light file's real seconds can move the balance least.
- **A new flag or a step change in `ci.yml`**: it would change the Test step `test/repo/e2e-tiers.test.ts`
  pins and the shard command the implementer definition gives, for nothing the launcher cannot do.
- **Reading the seconds from the test lines CI already prints**: they carry no file name, mapping them
  needs a full local run, four names are ambiguous, and a file's load and hooks are not in them.
- **`--test-concurrency=4`** (the runner's fourth core): unmeasured, so not offered.
- **Moving the typecheck, lint and format checks into one job**: ruled at Issue #743 ruling 3 and
  recorded at Issue #1001 as not proposed.

  - `export const shardOf = (files: readonly string[], index: number, total: number, seconds: Readonly<Record<string, number>> = UNIT_SECONDS): string[]`:
    throws `RangeError` when `total` or `index` is not an integer, `total < 1`, `index < 1` or
    `index > total`, with the message ``--test-shard=${index}/${total} names no shard: the index runs from 1 to the total``;
    weighs each file `seconds[file] ?? UNLISTED_SECONDS`; sorts a copy heaviest first, ties by path in
    code-unit order (`a < b`); keeps `load`, one number per shard from 0; for each file takes
    `k = load.indexOf(Math.min(...load))` (the lowest shard on a tie), adds the weight, and keeps the
    file when `k === index - 1`; throws `RangeError` with
    ``shard ${index} of ${total} holds no file of the ${files.length} it was given`` when the kept list is
    empty; returns the kept list sorted.
- `scripts/unit-file-clock.ts` (about 35 lines):
  - `export type FileTiming = { readonly file: string; readonly ms: number };`
  - `export const fileClockLines = (timings: readonly FileTiming[]): readonly string[]`: `[]` for no
    timing; else the head ``per-file wall clock (${timings.length} files, ${seconds(total)} total):``
    and one row per file, slowest first, ties by `file` in code-unit order:
    ``  ${file.padEnd(width)}  ${seconds(ms).padStart(6)}  ${share.toFixed(1).padStart(5)}%``, where
    `seconds = (ms: number) => \`${(ms / 1000).toFixed(1)}s\``, `width` is the longest `file`, and `share`
    is `ms / total * 100` (0 when `total` is 0). This is `formatSuiteTimings` in `e2e/support/suites.ts`
    with files for suites; it is written here and not imported, so `scripts/` takes nothing from `e2e/`.
  - `export default async function* unitFileClock(source: AsyncIterable<{ type: string; data: { name?: string; file?: string; nesting?: number; details?: { duration_ms?: number } } }>): AsyncGenerator<string>`:
    keeps each event with `type === "test:complete"`, `nesting === 0`, `file` and `name` both defined and
    `resolve(name) === file` (from `node:path`), as
    `{ file: relative(process.cwd(), file), ms: details?.duration_ms ?? 0 }`; after the source ends,
    yields each line of `fileClockLines` followed by `"\n"`.

    const whole = (Date.parse(job.steps.at(-1)!.completed_at) - Date.parse(job.steps[0]!.started_at)) / 1000;
    draws.push({ factor: test / span(today[k - 1]!), before: whole - test });

  const rs = runs.slice().sort((a, b) => a - b);

}
