## The design

A step in the publish job's `build` job, after `npm ci` and before `Build site into dist/`, runs `node scripts/deploy-browser.ts` with `VELLUM_BROWSER: /usr/bin/google-chrome`, as CI's lanes set it. The script prints two lines: `deploy browser: <the path findBrowser returns> (<its --version>)`, or `deploy browser: none found`; and `VELLUM_BROWSER: <its value> (present)` or `(missing)`, or `VELLUM_BROWSER: unset`. It exits 1 when no browser is found, so the step shows the miss, and the step's `continue-on-error: true` keeps the publish going; `timeout-minutes: 2` bounds a hang. A version that cannot be read prints `version unreadable: <message>` after the path rather than losing the path. Nothing else in the publish changes: the build step, the upload and the publish are as they were.

**Rejected, with the reason:**
- **Setting `VELLUM_REQUIRE_BROWSER` or failing the step:** the ruling is that this line "cannot fail the publish".
- **A job of its own in `deploy.yml`:** the ruling places the line in the publish job; a step in the `build` job runs on the very runner that will press the pictures, where a separate job takes a runner of its own.
- **Printing `findBrowser()` alone:** were Chrome absent, `findBrowser` would fall through to `/usr/bin/chromium`, and the path alone would not say whether `VELLUM_BROWSER` pointed at nothing; the second line says so.
- **Touching `ci.yml`:** the lanes' build needs no browser until pull request 2 makes pictures; their variables are pull request 2's.

## Files

   ```ts
   // Issue #1255, pull request 1: prints in the publish job's log the browser findBrowser finds there, so the Primer's pictures are built on a reading of it (Issue #1255 comment 7115489261, Q1).
   import { execFileSync } from "node:child_process";
   import { existsSync } from "node:fs";
   import { findBrowser } from "../src/cli/raster.ts";

   // 2026-11-23, Issue #1255: a browser's --version answered in 0.03 s on this Mac; 30 s is far above it, so a stalled read prints the path with "version unreadable" instead of holding the step.
   const VERSION_MS = 30_000;

   export function browserReport(
     found: string | null,
     wanted: string | undefined,
     exists: (path: string) => boolean,
     version: (path: string) => string,
   ): readonly string[]
   ```
   `browserReport`: the second line is `VELLUM_BROWSER: unset` when `wanted` is undefined or `""`, else `` `VELLUM_BROWSER: ${wanted} (${exists(wanted) ? "present" : "missing"})` ``; with `found === null` it returns `["deploy browser: none found", <second line>]`; else it calls `version(found)` inside a `try`, a throw giving `` `version unreadable: ${err instanceof Error ? err.message : String(err)}` ``, and returns `` [`deploy browser: ${found} (${read})`, <second line>] ``. On `import.meta.main`: `found = findBrowser()`; print each line of `browserReport(found, process.env["VELLUM_BROWSER"], existsSync, (path) => execFileSync(path, ["--version"], { encoding: "utf8", timeout: VERSION_MS }).trim())` with `console.log`; `if (found === null) process.exitCode = 1;`.

## Calls made

- **D1.** The step sits in the `build` job after `npm ci` and before `Build site into dist/`: the runner that will press the pictures, before anything that could stop the job. Rule: the ruling places it "in the publish job".
- **D2.** It cannot fail the publish by `continue-on-error: true`, and cannot hold it by `timeout-minutes: 2` and the version read's 30 s cap; it still exits 1 on no browser, so the step itself shows the miss. Rule: the ruling, "cannot fail the publish".
- **D3.** It prints a second line saying whether `VELLUM_BROWSER` points at anything, since a lone path cannot tell Chrome missing from Chrome found. Rule: the reading must decide pull request 2's design.
- **D4.** Only `VELLUM_BROWSER` is set, as CI's lanes set it; `VELLUM_REQUIRE_BROWSER` is pull request 2's. Rule: the ruling's words.
