## The design

**RR26 and RR28 (Q1, and Q2R for RR28): one read each, once the draw has settled, of the stage and of the plate it was asked for.** The stage returns the key it already keeps (`shown`), the room's hook `__vellumReadingRoomState` carries it as `plate`, and the kit's `plateBare` replaces `plateStaysHidden`: it reads `bareRead` once and returns `null` (bare) only when the stage is present, hidden, and asked for nothing; a missing stage stays a failure (`{ missing: true }`), as the issue requires. RR26 reads it after the boot settles, as today; RR28 reads it straight after RR17's poll has seen the counter draw settle, on today's fixture. No window: the read sees an ask before its plate paints (`out/1285-dry-run/round1/1285-hook-n2-1.log`, `RR17 BEFORE`, read just after a settle under P5: `{"stage":{"hidden":true,...},"plate":"13:512"}`), so a single read of the DOM alone would not be enough and the hook is what makes the instant read sound. It gives up what Alex's Q1 ruling names: a plate asked for later than the one read with nobody pressing anything.

**RR28's sentence says what its fixture holds.** It becomes "RR28 the counter draw stages no plate unasked (#442)": the read holds that (P1, P5 and CTR each red it), and "clears the old world's plate" goes, since the fixture never had one to clear. That gap and the carry-over are Files 9's errata row, as Alex ruled.

**Keeping the hook honest.** A hook that always answered `null` would pass RR26 and RR28 (the `hooknull` run passed both). So the kit's `plateShown` reads `bareRead` too and returns the stage it found up together with the key the hook gave in that same read (`asked`), and RR28b and RR29 each assert `asked !== null` on the snapshot in which Play's plate is up. That holds on any runner: the stage sets `hidden = false` only in `paintPlate`, reached only while `shown()` equals the plate's key, and the only way back to a null key is `hide`, which sets `hidden = true` in the same call, so in any one read a stage that is up has a key. The `hooknull` run red exactly RR29 and RR28b.

**RR20 (Q3): no window, and a second witness.** The 2 s sleep and the read after it go; the held read is taken at once after the poll. Beside `sawForeign` (a 50 ms poll that caught the stale world's name on 7 polls over about 310 ms on the Mac), the check counts the chart's draws with a `MutationObserver` on `.rf-chart`, as the environment bullet on `textContent` prescribes for "written exactly once", and asserts one. Gate 1 item 21: the count is added beside `sawForeign`, not in its place.

**Alternatives rejected.**

- *A shorter watch, 0.5 s*: ruled out by Q1.
- *Deleting RR28*: ruled out by Q2R; with RR28 gone nothing reds CTR (`out/1285-dry-run/plan-rr28-deleted/1285-plan-hook-ctr-1.log` and `1285-q2r-none-hook-ctr-2.log`, 46 of 46 each).
- *Giving RR28 a plate to clear (Play on the day's world before the Read)*: Q2R's second option, not taken; it would also hold X2.
- *A single DOM read with no hook*: misses an ask whose plate has not painted (the `hook-n2` reading above).
- *Waiting on the worker's queue emptying*: the page reports no queue, the prefetch keeps the worker busy after the settle, and the key already says what a queue would only imply.
- *Moving the arrival rule to a unit test*: the gate lives inline in `src/site/reading-room/app.ts`, so a unit test needs it extracted first.
- *Asserting the hook's key equals the key of the plate's href, read after `plateShown`*: Play's sweep keeps telling, and `show` moves the key at once while the new plate's fetch is still on its way, so a second read, or one read mid-sweep, can see the next key beside the last plate's href on a correct build; a staged late ask (`out/1285-dry-run/plan-equality/1285-plan-hook-late1500-1.log`) red RR29 with `asked "0:451"` beside an href of `0:1059`. Rejected for the one-snapshot non-null form.
- *Keeping `sawForeign` alone for RR20*: it catches M1 by sampling; the count catches it on every run regardless of how the polls fall. Kept both.
- *Re-timing `MEASURED_SECONDS`*: ruled out by `handbook/specs/site-architecture.md`.
