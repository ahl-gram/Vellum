## The design: where the Explorer wires the growth (replaces revision 1's C14)

**The room's call stays in `app.ts`.**

- `app.ts` keeps `import { bindRoom } from "../shared/room.ts";` and calls `bindRoom(roomFor(glass))`.
- `roomFor(glass: Glass): RoomParts<Camera>`, in `app-wiring.ts`, returns exactly the object `app.ts` passed on main, `{ frame: stageEl, sheet: sheetEl, camera: { hold, restore } }`, plus `onLayout: growBill`.
- The roster entry for `src/site/explorer/app.ts` in `SHARED_BINDINGS`, and its copy in `ROSTER` in `test/repo/shared-bindings.test.ts`, are untouched. The lint still reads that `app.ts` takes `bindRoom` from the shared room and calls it.
- `app.ts` no longer names `stageEl`, so it leaves `app.ts`'s import from `./elements.ts`. `sheetEl` stays: `app.ts` reads it elsewhere.

**The zoom hook lives in `followView`.**

- `function followView(loupe: LoupeBinding, slide: RoomSlide): (k: number) => void` is a module-level function in `app-wiring.ts`, placed directly after `insetDogEar`.
- It returns `(k) => { loupe.follow(); slide.follow(k); zoomBill(k); }`: the two followers `onView` held, in the same order, then the bill.
- `pageGlass` passes `onView: followView(loupe, slide)`.
- `split-arguments-by-name` reads that call: its arguments `loupe, slide` are the parameter names `loupe, slide` in order, so it passes.

**`RoomParts` is exported** from `src/site/shared/room.ts`, with no other change to that file. Then `roomFor`'s return is checked as the parts `bindRoom` takes: a misspelt part is a type error, not an extra property passed silently, and `restore`'s `cam` takes `Camera` from the annotation.

Nothing changes at run time. `bindRoom` is called once, with the same five parts as revision 1's `pageRoom`, at the same point in `app.ts`. `onView` calls the same three functions in the same order. The built candidate's readings match revision 1's staged ones to the hundredth (Tests).

**Rejected, so the builder does not rediscover them:**

- **Revision 1's `pageRoom`** (the call moved into `app-wiring.ts`). It reds `vellum/shared-binding-imported` on `app.ts` and leaves `stageEl` unused there (measured, the hand-back).
