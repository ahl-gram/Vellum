## 2. Construction rules

The issue's plan, section 3.1 and 3.2, and Alex's rulings 1 and 5 govern. What this slice adds, each a rule the split proof holds the build to or a case the plan did not meet:

1. **`run` is the table of contents.** It keeps the factory lines in their base order (`makeSettle`, `makeStep`, `scopedHealth`, `makeStage(...)` destructures), the health bases, the kit call, one line per step (`await step("T2", () => t2NewWorldSettles(ctx));`), one call per unstepped group, the `let` a stepped group assigns, and the closing restore. A group function sits below `run` in call order, the kit first.
2. **A step whose body passes 50 lines calls its functions in order in its one line**, split at statement boundaries: ribbon RB1 to RB5e (three), prospect PB2 to PB5 and broadside BR1 to BR1c (two each), e.g. `await step("PB2 to PB5", async () => { await pb2CapitalPlate(k, href); first = await pb3eRoomAndPlate(k); });`. None of the three bodies holds a top-level `return`, so cutting it cannot skip a later part.
3. **Render's four control blocks stay in `run`** (`const landPresent = ...; if (!landPresent) { check(...) } else { await step("R11a", () => r11aFloods(ctx)); ... }`), each step cut to one line and R13d's unstepped parity read a call inside its `else`. This is the literal reading of ruling 1 (every numbered check listed in `run`), passes no `step` into a helper, and measures at about 45 of 50 lines. The alternative the proof was gated on in PR 1 (`673-gate-render-split.ts`: one helper per control taking `step`) hides the steps one level down; not taken.
4. **A statement between groups that sets up several of them stays in `run` as its own line**: a viewport or metrics change (zoom-gestures' `setMobileViewport(390, 780)`, ribbon's `setMobileViewport(390, 844)`, room-drawer's two, cluster's `setDeviceMetricsOverride` and `setMobileViewport(390, 844)`, document-rooms' two), glass-ceremony's `__vellumSetRedraftEnabled(true)`, room-drawer's script switch and `scriptsBackOn`, and every closing `clearMobile`, metrics reset, `gate.check`, navigate and `waitReady`. So `clearMobile` stays a trailing statement in cluster and room-drawer, which keeps `scripts/e2e-explorer.ts`'s comment at the runner's phone-metrics compensation true. A statement that brackets ONE check's stretch moves with it (glass-ceremony's reduced-motion pairs around G3 and G6, document-rooms' script switch around IX6, broadside's `setMobileViewport`/`clearMobile` inside BR6's stretch).
5. **Helpers that close over the context go in one kit per suite**, declared exactly as today, `return { ...ctx, <helpers> };`, called as `const k = <suite>Kit(ctx)` (or `(<{ ...ctx, settle }>)` where a factory product made in `run` must reach them: room-drawer, document-rooms). The kit call sits at the base position of the kit's first sequenced statement: broadside's `EXP` and region-detail's `LINK` are templates with a substitution, so their kits are called right after `const step = makeStep(ctx)` and before any health base. Kits: verso, zoom-gestures, region-detail, ribbon, prospect, room-drawer, broadside, glass-ceremony, document-rooms. Turn and render have no such helper; cluster's are all factory products made in `run`, so its groups take them by name (`cl4Opens(ctx, settle, clickAt, pressKey, burger)`) and it has no kit.
6. **Data flows by name** (the proof's call 22): each argument is the same name as its parameter, or a bag of spreads and shorthand names; no default parameters; a group that hands a value back computes it into the caller's bound name on its own line and ends `return <name>;` (or `return { a, b };` for a destructuring caller). A group with no `await` is not `async`, and every async group is awaited at its call.
6a. **A stepped group that hands a value back to a `let` in `run` writes it where the base did, or with nothing after it that can throw.** The base writes the outer binding at its own line, so a later throw inside the same step leaves the value written for the next step to read; a handback writes it only when the group returns. So the write is the group's last statement, or is followed only by statements that cannot throw (`check` cannot: it pushes a result, `scripts/e2e/harness.ts`). Verso's `vTitle` is the step's last statement; prospect's `first` is followed only by PB5's `check`. Ribbon's `svg1` is followed by about forty lines that can throw (two `evaluate` gestures and their polls), so RB1 to RB5e is cut in three: `const first = await rb1SetsOut(k); svg1 = await rb5PressedPlate(k); await rb5bTheSlip(k, first);`, where `rb5PressedPlate` presses the plate and checks RB5 only. The plan skeptic ran the two-part cut under a mid-step throw with the real `makeStep`: RB7 passed at the base and failed at the head, and the proof read both the same. This rule is recorded as a call so PR 7's `laid` (chart-drawer CD2, read by CD4) inherits it.
7. **Parameters are destructured in the signature**, typed as the value's type at its old site (`SuiteContext`, `ReturnType<typeof <suite>Kit>`, a named module type, or `Awaited<ReturnType<typeof group>>[...]`), except `consoleErrors`, which is destructured in the body (the console-support sweep reads a signature naming it as an unfiltered read). No PR 2 suite reads `serverState`. A group that needs a literal `ctx.send(` (region-detail RD3 and RD5) takes `ctx` beside the kit.
8. **Types declared inside `run` move to module level** (region-detail's `Inset`, broadside's `Box` and `Room`, glass-ceremony's `Btn`); position-free primitive constants may too (region-detail's `SEED` and `LAST_INSET`, which the guarded CSS citation in `public/explorer/chart-drawer.css` still finds in `scripts/e2e/suite-region-detail.ts`). Types are stripped before the proof reads anything.
9. **A `let` in `run` that a later group only writes before it reads is declared at that first write inside the group**: zoom-gestures' `r` (line 53 `r = await vpRect();` becomes `let r = await vpRect();` in the ZG2 group) and region-detail's `redrafts` (line 113 in the RD3 group). Measured by reading: each group's first touch of the name is that write, and no later group reads the value it held. No outer binding survives in `run` in either suite, so a read of the old one would not compile.
9a. **The lines not moved byte for byte, all named in the PR body**: those two; the three handback writes that become a group's `const` (verso's `vTitle = await evaluate(...)`, prospect's `first = await svgOf()`, ribbon's `svg1 = await svgOf()`), each with rule 6a argued; the `return <name>;` lines the handback groups gain; and blank lines. Everything else moves verbatim but for its leading indentation, template continuation lines keeping their bytes.
10. **New function names** are checked against the base family before use (a name the base already declares is compared as a helper, and reads as changed).
11. Comments travel with their lines; a comment directly above a `step(` call sits directly above its group function; no comment is added.

## 3. The proof's unnamed blind spot this slice leans on

The proof drops `const`, `let` and `var`, which its allowances need (a base assignment to `run`'s `let` becomes a group's `const` it returns: verso's `vTitle`, prospect's `first`, ribbon's `svg1`). So `let x = v` and `x = v` print alike, and a split that declares a new local where the base wrote an outer binding that a LATER statement still reads is a behavior change the proof reads as the same. The checker catches it only when no outer binding survives. Beside it, two more the plan skeptic measured: a handback moves the outer write to where the group returns, which differs from the base only when the step throws after the base's write (rule 6a; the proof reads it the same, and so does a check list taken from green runs); and `stepOf` unwraps the `await` on a `step(...)` line, so a bare `step(...)` reads the same (lint's `no-floating-promises` refuses it). `compareFamilies`' blind-spot comment names none of the three. PR 2 names all three there, each a miss with its direction argued and what catches it, in the same one-line comment and without spelling either marker the Issue #654 greps count (call 16), since the house rule is that an unnamed blind spot is the defect and naming it is the fix; no errata row, since rule 6a keeps PR 2 clear of the second.
