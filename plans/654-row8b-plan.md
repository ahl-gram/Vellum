## The allowed differences

**Provenance, stated.** The rules below were declared while the sketch was being measured, as row 8a's were (its "Provenance, stated"): the tool was extended against the sketch's forms, and each extension is written here before the build. Three of them were widened after a sketch run refused a form: names destructured from a part now count as handed-in names (rule 18), a helper's prelude may bind what its caller dropped (rule 19), and the rewrites reach the builder's own statements (rule 15); each has a planted pair on the refusing side next to what it now admits (below). Row 8a's rules 1 to 12 stand unchanged; the extended tool (`654-row8b-moved.ts`) reads row 8a's head as 35 SAME, 0 problems and row 8a's 32 planted pairs 32 of 32, as the 8a tool did. Row 8a's first-sketch pairs (the only ones exercising its getter and field-setter rules) read 30 of 31: every pair as expected but the verbatim control, which rule 18's tightening now refuses because that sketch's parts took `d` and `k`. **Every new rule gets planted pairs at this row's head** (below).

13. **Const-arrow inner functions.** A builder's `const f = <arrow or function expression>` is an inner function as a declaration is: it moves whole into a part as the same `const f = ...`, or to module level as a declared module move, and is compared by its parameters and body. Whether a function is `async` or a generator is now compared as well; the 8a tool compared parameters and body only and could not see `async` dropped.
14. **Members moved into a part.** A member of the builder's returned object that the spec names, a method `m(p) { body }` or a property `m: (p) => body`, may become a part's `function m(p) { body }` or `const m = (p) => body`. The builder's return then carries `m` as a shorthand, bound without renaming from the part that holds it. Compared as an inner function, so rules 1 to 3 apply; a method reading `this`, `super` or `arguments` is refused, since a function declaration binds them differently. The return object's keys compare in order with each moved member standing for itself.
15. **The rewrites reach the builder's own statements.** Rules 1 and 3 (getter read, rebind setter) and rule 16 apply to the builder's kept statements and to its return's properties for a `let` or `Map` a part now owns; a getter or setter the builder names must be bound from the part that owns it. (The road listener reads `items()`; the zoom listener writes `setSettleTimer(...)`; `refit` and `glideHome`, in return-object helpers, read `glideTargetK()` and write `setGlideTargetK(null)`.)
16. **A shared `Map` has one owner.** A builder-level `const M = new Map(...)` is declared by exactly one part, as the base declared it. Outside that part a write used as a statement, `M.set(k, v)`, `M.delete(k)` or `M.clear()`, is written as the owner's declared accessor (`putArt(k, v)`, whose body is exactly `art.set(key, value)`); reads (`get`, `has`, `values`, iteration) go through the `Map` itself, which the owner hands out typed `ReadonlyMap`. Direction: a write by a function the `Map` is handed to is not seen; no such call exists in the split, and the type makes one a compile error.
17. **A module of its own.** In the sibling module, a name the base file declared at module level resolves as an import of that name from the base file. An importer re-pointed at the sibling for the moved builder (`app.ts`, declared as a re-import) compares its imports as a set of bindings with that one re-pointed, and its imported modules in the base's order, the new one aside, since module evaluation follows import order.
18. **A destructured builder parameter, and what a part is handed.** The names `createZoomController` binds by destructuring its options are its own names for rule 12 and for what a part may be handed; a part may also be handed a function the builder destructured, without renaming, from a part it created earlier, and a destructure from a part may name only what that part returns. **Tightened, not only widened:** every name handed to a part lands in the part's parameter of the same name, so two handles of one type (`targetEl` and `viewportEl` into `zoomPaint`, both `HTMLElement`) cannot trade places with the type check and rule 12 both passing. Row 8a's head meets it (its round 1 named the chronicle's parameters `deps` and `paint`); its first sketch, which named them `d` and `k`, does not.
19. **A file with no builder** (`app.ts`, `worker.ts`, `hash-sync.ts`, `controls.ts`, `sheet-turn.ts`) is compared whole: every top-level statement in order, the declared statement helpers inlined by rules 5 to 7 wherever they are called and their declarations set aside, imports as in rule 17. **A helper's prelude may bind a name the caller's own destructure of the same record then drops** (`landSlider` and `coastSlider` from `readHash`'s `controls`, `coastSlider` from `wireControls`'s `deps`, which would otherwise red `no-unused-vars`), provided the base's function of that name bound it from that record and the head declares no module-level name of the same spelling, so a dropped name cannot resolve anywhere else and the type check refuses any other read of it. The drop is keyed by function and record, so `writeHash`'s own destructure of `controls` is compared whole.
